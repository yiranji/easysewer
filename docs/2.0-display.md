# Map labels and profile plots

These 2.0 interfaces implement `[LABELS]` and `[PROFILES]` as GUI
metadata. They do not change hydraulic inputs or cache physical conditions.
`easysewer.Model` and `easysewer.model.Model` are the same public model.

## Labels

```python
from easysewer.model import Point, Ref
from easysewer.model.project import MapLabel

model.update_labels(entries=(
    MapLabel(position=Point(x=100, y=200), text="North district",
             anchor=Ref(collection="swmm:nodes", key="J"), bold=True),
    MapLabel(position=Point(x=100, y=200), text="North district"),
))
```

`model.labels` is a `MapLabels` value with an ordered `entries` tuple. Labels
have no IDs in INP; duplicate text and coordinates are valid. Positions in this
tuple are not persistent object identities. Replace, insert, remove or reorder
entries with `update_labels`. An empty tuple removes all label rows on export.
The collection has the stable owner `Ref(collection="swmm:labels", key="layer")`,
which Scenario operations can address.

Font defaults follow the fixed SWMM-GUI 5.2.4 implementation: Arial, size 10,
not bold, not italic. Omitted fields remain omitted in an unchanged source
document; normalized or newly created rows write all fields explicitly. Font
size is a signed 32-bit integer, including zero/negative values accepted by that
parser; no visual font-rendering guarantee is implied. Map coordinates and
font sizes remain unchanged when converting any of the six flow units.

GUI anchors refer only to nodes. A node rename updates anchored labels. A
missing node is a validation error, even if a subcatchment has the same name:
the model does not silently bind that different object. With same-named node
and subcatchment, the node is the anchor. This differs from the 5.2 manual's
description of subcatchment anchors. The fixed GUI also expects integer font
flags: only `1` is true. Manual `YES`/`NO` flags are decoded with a compatibility
warning; use `to_document(normalize=True)` to replace them with `0`/`1` before
opening that input in the GUI. Unchanged source still contains the original
flags. Other integer flags retain GUI semantics and normalize to `0` or `1`.

Deleting an anchored node is protected. The label layer is one graph owner:
explicit `cascade=True` removes the entire layer, including unanchored labels.
To keep other labels, first remove the affected entries or clear their anchors,
then delete the node within `model.transaction()`.

Text and font names support spaces, empty strings and Unicode. Quotes,
semicolons, physical newlines and NUL are rejected because they cannot roundtrip
through the supported token syntax. Extra columns are retained in unchanged
source, diagnosed, and removed during normalization.

## Profiles

```python
from easysewer.model.project import ProfilePlot

model.profiles.add(ProfilePlot(name="North route", links=(
    Ref(collection="swmm:links", key="P1"),
    Ref(collection="swmm:links", key="P2"),
)))
model.profiles.rename("North route", "Main route")
```

Profiles are named records. Their names may contain spaces and Unicode,
including a leading `[`; the token writer quotes header-like names. Names
require non-whitespace text and cannot contain quotes, semicolons, newlines or
NUL. Identity uses the model's deterministic ASCII case-insensitive comparison;
non-ASCII characters retain their spelling rather than depending on a GUI
locale. Whitespace inside quoted names remains significant.

A leading `[` is representable for GUI/model roundtrips but cannot be sent to
the fixed solver: its input parser treats even a quoted first token as a section
header. Run validation reports `inp.native_header_token` with its source line;
rename the profile before running. The runner does not silently discard metadata
to work around that engine restriction.

Repeated same-name input rows, including rows in repeated sections, append
links in order. Link order and duplicates are retained. The writer uses at most
five links per row, independent of the source's original grouping. A profile
requires at least one link. One-token source rows ignored by the GUI remain
source-owned with a diagnostic; normalization does not invent a profile for them.

Link renames update every occurrence. Link deletion is protected; an explicit
cascade removes profiles that reference it. Missing links are errors. An
ordered sequence that cannot form a continuous path in either direction gets
a plotting warning, without changing its order or treating it as a hydraulic
error. Profile names and record order survive INP/JSON rebuild, rename and
`model.profiles.move(...)`.

Both domains participate in Model JSON 1.0 and Scenario serialization. Existing
source-only data can be re-read with a schema that registers these codecs;
claiming it must produce exactly one set of output records. Parsing does not
open a GUI, select fonts, render plots or fetch external resources.

The compatibility basis is the official
[SWMM-GUI v5.2.4 source](https://github.com/USEPA/SWMM-GUI/tree/9e026d6bf70efa8ddda541714aa202484d6e54c3/Epaswmm5):
`Uimport.pas` ReadLabelData/ReadProfileData, `Uproject.pas` TMapLabel.Create,
`Uutils.pas` Tokenize, and `Uexport.pas` ExportProfiles/map-label export.
Native tests verify complete OUT and normalized RPT invariance plus moved
checkpoint recovery. They do not claim an interactive GUI or browser test.
