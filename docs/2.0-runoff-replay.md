# Candidate RUNOFF replay semantics

Known standard revision 5 and custom ABI 201 builds expose
`swmm_getEasySewerRunoffPhysics() == 1`. Both backends advertise
`easysewer:runoff-physics:1` and record `swmm:runoff-replay` with that policy in
their output semantics. This capability requires reviewed binary hashes, not
only a SWMM version or exported function. Custom ponding policy 2 and native
I/O revision 3 retain their separate identities.

The same known builds expose `swmm_getEasySewerRunoffRainClock() == 1`,
advertise `easysewer:runoff-rain-clock:1`, and record that policy under
`swmm:runoff-rain-clock`. This independently qualified capability maintains
the consumer's rain gages and accumulated-rain controls during replay.

## Fields and time

RUNOFF contains project-unit samples at the end of each stored time step.
Replay advances the relative runoff clock and reconstructs these values:

| Cached field | Replay and reporting |
| --- | --- |
| Rainfall | Informational; current rain gages still supply rain reports and instantaneous rain controls |
| Snow depth | Converts depth units and interpolates old/new aggregate snow depth |
| Evaporation | Converts evaporation units (in/day or mm/day), without interpolation |
| Infiltration | Converts rainfall-rate units (in/hour or mm/hour), without interpolation |
| Runoff | Converts volumetric flow and interpolates old/new flow |
| Groundwater flow | Divides by flow-unit factor **and native catchment area**, then interpolates old/new depth-rate for routing and reporting |
| Groundwater elevation | Converts length units and subtracts the actual local groundwater bottom to recover saturated depth |
| Soil moisture | Restores the current fraction, without interpolation |
| Pollutant concentrations | Restores each project-unit concentration; native reporting/routing interpolation remains in effect |

Previously evaporation recovered at 24 times its saved value, groundwater flow
was multiplied by catchment area again, and elevation used a reversed difference
from the aquifer default. The previous groundwater flow also failed to advance
between frames. Policy 1 corrects all four defects. A first frame retains the
groundwater flow initialized by USE HOTSTART as its left boundary; subsequent
frames use the preceding cached value. Without HOTSTART the initial flow is zero.

A zero-area catchment can represent only zero groundwater volumetric flow.
Nonzero cached groundwater flow for such a catchment returns native error 325;
zero flow restores safely without division. Overflow of the reconstructed
depth-rate also fails before applying any frame. Validation includes unused
trailing frames and runtime reads. Signed groundwater exchange is retained.
Restoration requires a groundwater binding on the consumer catchment; without
one, native replay does not use its groundwater columns. The cache header does
not identify aquifers, nodes or these bindings, so positional layout alone
cannot verify that they match the producer.

Normal native small-runoff reporting thresholds still apply. A tiny runoff can
appear as zero in OUT, with zero reported washoff, even when its stored value
is nonzero. Hydrology ignore options do not filter flows supplied by USE RUNOFF;
they control recomputation, which replay skips.

Typed results now carry [applicability](2.0-result-applicability.md). Unrecomputed
hydrologic summary numbers become explicit missing values while original RPT
tokens and artifacts remain intact. Cached samples, routing results, incomplete
system evaporation and partial HOTSTART carry separate scopes.

## Consumer rain clock

SAVE obtains the rainfall column from the gage's most recent report value;
that is not necessarily rainfall at the cache frame time. It cannot reliably
replace the current gage's rainfall history. Replay therefore does not overwrite
shared gages with individual catchment rows. Instantaneous rain controls use
the consumer's gage state and require compatible rainfall resources.

Rain-clock policy 1 advances source rainfall at actual routing and reporting
times, independently of cache frame lengths. It integrates intensity between
source changes and month boundaries, keeping 48 completed hourly bins plus
the current partial hour. Bins start at the simulation origin, including a
non-hour start time; a bin closes at its exact hour boundary. `1-HR_DEPTH`
through `48-HR_DEPTH` exclude the current partial hour. A cache frame spanning
many hours never makes a control see future rainfall. Controls still evaluate
at the native routing/control schedule, including `RULE_STEP`.

Inline series, external series and rain files retain their INTENSITY, VOLUME
or CUMULATIVE interpretation and rain-unit conversion. Co-gages share their
source. Monthly rainfall adjustments apply at the consumed time, including
a zero factor followed by a nonzero month. Nonnegative API rain overrides
apply from the next step and bypass the source's monthly adjustment; the
native public setter has no operation for clearing that override.
`IGNORE_RAINFALL` yields zero current rain and accumulation. Cached rain
columns do not override any of these sources.

The normal non-cache gage path retains its existing one-second tolerance
and hydrologic-step accumulation. Replay uses exact source boundaries and
the actual consumer clock. Consequently SAVE and USE control traces can
differ when a normal hydrologic step anticipates rainfall or closes an hour
at a different evaluation time. Rain-clock policy 1 promises the documented
consumer-time behavior, not identical control traces for every original run.

## State that the format cannot recover

RUNOFF has no full infiltration memory, subarea ponding, snow-surface state,
LID layer/drain/clogging state, land-use buildup or groundwater evaporation and
deep-loss history. It cannot reproduce full hydrologic water balances or their
summary statistics. Native hydrology summary tables and continuity values from
replay must not be interpreted as recomputed hydrology. The system evaporation
series also lacks groundwater evaporation that was not stored. Routing still
computes its own flow/quality state and balances from supplied inflows.

SAVE HOTSTART after replay contains the restored runoff, runoff quality and
groundwater flow/elevation/moisture, together with other states left at their
initial values or inherited from USE HOTSTART. This is **not a complete
hydrologic continuation state**. Model run validation reports
`files.runoff_replay_scope`, and additionally `files.runoff_hotstart_partial`
when SAVE HOTSTART is requested. Existing [LID drain restrictions](2.0-lid.md)
remain applicable. These limits require additional state/provenance support,
not invented values for absent fields.
Rain-history bins are not stored in HOTSTART either; replay begins their
accumulation at the new simulation origin.

## Compatibility and verification

The on-disk RUNOFF format and pure codec are unchanged. Uncached runs and SAVE
outputs retain their previous results; USE results affected by the corrections
intentionally change. Runner records the new binary identity. Its existing
producer/engine-hash checks reject mismatched old provenance; callers must
review and explicitly establish evidence for reuse, not relabel old manifests.
Positional layout evidence alone does not certify compatible area, groundwater,
dates, rainfall, quality, LID settings or hydraulic feedback.

Independent literal caches cover all six flow units, all 16 combinations of
local groundwater overrides, evaporation, snow, losses, signed groundwater,
quality, different frame lengths, intermediate reports, zero area and HOTSTART
boundaries. An equivalent surface-inflow oracle checks downstream water and
pollutant results. Non-cache and SAVE comparisons cover quality, groundwater,
LID, snow and streets on both native families. Rain-clock checks observe all
49 control operands through public link settings against an independent
piecewise rainfall integral. They include fractional routing steps, RULE_STEP,
all source forms, both rain-unit systems, co-gages, month changes, API overrides,
cache exhaustion and a routing step longer than 48 hours. Broader physical reuse validation,
report availability metadata and complete hydrologic continuation remain release
work; these checks do not certify every SWMM combination.
