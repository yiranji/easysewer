# Candidate record provenance

`Model.provenance(Ref(...))` queries the original INP declarations associated
with a current record. It does not render current values and call them original
source. The query is pure and does not open files or load native libraries.

```python
from easysewer.model import Model, Ref

model = Model.from_inp("network.inp", strict=True)
model.nodes.rename("J1", "Upstream")
info = model.provenance(Ref(collection="swmm:nodes", key="Upstream"))
print(info.kind, info.original, info.changed)
for row in info.records:
    print(row.section, row.span.line, row.text)
```

`RecordProvenance` is an immutable query result. `owner` uses the current spelling
of the identity; `original` is a canonical source identity. `source` is the
original document path (possibly None), and `source_sha256` identifies its exact
bytes, including encoding/newlines. `original_value` is the immutable decoded
record. `records` contains every bound original declaration, in physical line
order, including repeated assignments. Each `SourceRecord` has feature, section,
codec key, source span, original text and token values. A missing current owner
raises `KeyError`; the argument must be a `Ref`.

The kinds are:

| Kind | Meaning |
| --- | --- |
| `inp` | An explicit lifecycle association to a structured original INP record. `changed` compares its decoded value with the current record. |
| `created` | A record added after the model's source baseline, including a recreated old ID. It has no borrowed source rows. |
| `untracked` | No original INP lineage is known, for example legacy JSON without an association ledger or portable JSON without source. |
| `unavailable` | JSON retains an original association but the current codecs cannot structure that original record. No source rows/value are invented. |

Replacement preserves the record's lifecycle, including a change of variant.
Renaming follows all rewritten composite relation keys (such as object tags),
not just the explicitly named object. Collection moves preserve association;
deletion removes it. Adding an equal value with a previously deleted ID is a new
record. Nested transaction failures roll back both data and associations. Copies
share immutable declarations but have independent lifecycle maps. Scenario edits
and flow-unit conversion obey these same rules.

Saving INP does not reset the in-memory source baseline. Loading that INP creates
a new baseline; INP has no record-history extension. Source-bearing Model JSON
preserves associations in optional `source.origins`, with independent format
`easysewer:record-origins`, schema version `1.0` and a digest binding it to the
original source bytes. This is an additive declaration in the candidate Model
JSON 1.0 envelope, not a change to the graph's authority or a frozen release API.
Older readers preserve the unknown member and apply their incomplete-data guards.

The association ledger validates duplicate/current/original identities, collection
consistency, source digest and non-reuse of an original record. It follows graph
deletions and survives temporarily unavailable codecs. An unknown ledger version
stays opaque, makes history untracked and guards unsafe mutations/INP export.
Legacy JSON without the ledger does not prove a current same-ID object is the
original object: that history is explicitly untracked. An unchanged legacy JSON
can retain its original formatting without manufacturing an association table.

These are reproducible source declarations, not an authenticity signature or a
complete audit log. JSON can be intentionally edited by its author. The query
currently describes **records**, not exact field-token lineage: multiple fields
may share a row, and defaults may not have a token. Field-level source/default/unit
discovery remains a separate unfinished R04/R05/R11 requirement. The candidate
[field inspection API](2.0-field-inspection.md) now provides explicit declarations
and semantics for analysis options; other domains remain unaccepted.
