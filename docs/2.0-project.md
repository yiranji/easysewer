# Candidate reports and project metadata

`Model` has separate report, title, annotation and map/background domains, available through INP, Model JSON and ScenarioPatch.

## Reporting choices

```python
from easysewer.model import Model, Ref
from easysewer.model.report import ReportSelection

model = Model.from_inp("network.inp", strict=True)
model.update_report(
    input=True,
    continuity=True,
    averages=False,
    nodes=ReportSelection(mode="SELECTED", members=(
        Ref(collection="swmm:nodes", key="J1"),
        Ref(collection="swmm:nodes", key="J2"),
    )),
    links=ReportSelection(mode="ALL"),
)
print(model.effective_report.nodes)  # Selected references in native object order.
model.to_inp("edited.inp")
```

`ReportOptions` exposes `disabled`, `input`, `continuity`, `flow_stats`, `controls`,
`averages`, `subcatchments`, `nodes` and `links`. An omitted field is `None` and
stays omitted on export. Profile defaults apply only in `effective_report`:
continuity and flow statistics are enabled, other switches disabled and object
selectors NONE. Selectors have mode ALL/NONE/SELECTED and an immutable tuple of
typed `Ref` values. Renames propagate; deleting a referenced object is guarded.
Invalid namespaces, duplicate IDs and empty SELECTED lists fail validation.

SWMM 5.2.4 keeps two separate selection states: the final selector mode and the
cumulative set of explicitly marked objects. Multiple list lines accumulate.
`NODES J1` followed by `NODES NONE` still records J1 in OUT, while suppressing its
RPT detail table. `NODES ALL` followed by `NODES J1` records only J1. The model
retains both states; NONE with members produces a warning, and `effective_report`
resolves the actual OUT object set. Replacing a field with
`ReportSelection(mode="NONE")` deliberately clears its accumulated members.
Output positions follow native object construction order, not selection-list
order. The later result reader must use the actual output identity map.

Writers split long lists at 39 IDs and a conservative byte budget. Imported
lines exceeding 40 total tokens model only the prefix read by the native engine;
the ignored tail is diagnosed and remains in an untouched source document.
ALL/NONE cannot be the first explicit ID on a list line. Chunking repeats an
already selected ordinary ID when needed to keep a later ALL/NONE ID literal.
The importer also diagnoses native keyword-prefix aliases and ignored tails.

`AVERAGES YES` changes node/link OUT values to reporting-interval averages.
`FLOWSTATS NO` suppresses routing accuracy/time-step statistics, while node/link
summary tables remain. `DISABLED YES` suppresses normal analysis/summary output,
but an explicit native `swmm_report()` call still emits selected detail tables.
It does not stop recording selected objects to OUT. A future Runner must define
when it calls that native function; this domain codec does not run simulations.
These behaviors are checked against fixed-engine files and the official
[report parser](https://raw.githubusercontent.com/USEPA/Stormwater-Management-Model/v5.2.4/src/solver/report.c),
[statistics dispatch](https://raw.githubusercontent.com/USEPA/Stormwater-Management-Model/v5.2.4/src/solver/stats.c)
and [solver lifecycle](https://raw.githubusercontent.com/USEPA/Stormwater-Management-Model/v5.2.4/src/solver/swmm5.c).

The manual's `REPORT LID` directive is not accepted by this engine profile.
It remains source-owned with a warning and blocks run validation; a later LID
usage codec must explicitly migrate the output request. `NODESTATS` is not a
new boolean field: the native keyword lookup matches NODE first, so `NODESTATS
YES` selects an object named YES or fails when absent.

## Title prose and informational annotations

```python
model.update_title(lines=("Drainage study", "; Retained project note"))
model.set_annotation("user:labels", {"event": "Storm A", "return_period": 10})
labels = model.metadata["user:labels"].value
```

`ProjectTitle.lines` contains physical lines, preserving quotes, semicolons,
blank lines, comments and Unicode. Ordinary JSON-looking title text stays prose.
Untouched source bytes, encoding and repeated TITLE sections remain unchanged.
An edited title is rewritten as one owned block without duplicate comments.
Newlines, NUL and section headers inside an entry are rejected. Run validation
warns that native SWMM uses only the first three non-comment title lines and
rejects physical lines exceeding its input buffer.

`JsonAnnotation` is a namespaced, immutable JSON text value in
`easysewer:metadata`. Its `.value` property returns a detached JSON tree. It is
strictly informational: embedded IDs are strings, numbers have no hydraulic
unit semantics, and nothing is imported or executed from it. Store real object
references or quantities in a registered feature with declared reference/unit
rules. Renaming a node does not rewrite a label string and unit conversion does
not rescale annotation numbers.

INP annotations use versioned TITLE comments:
`;@easysewer.annotation/1 <base64url-key> <part>/<count> <base64-json-chunk>`.
UTF-8 payloads are split into bounded lines, validated as complete ordered chunks
and decoded only under the known marker version. Unknown versions remain prose
with a warning. Malformed/duplicate known chunks stay inspectable in the source
and block semantic export. Known markers cannot be injected as ordinary title
prose. The JSON domain registry has explicit type tags for annotations; no Python
module names or reflection define the wire contract. Root JSON `extensions`
remain a separate preservation mechanism and are not silently moved here.

## Map and backdrop

`model.map` is `MapSettings(extent, units, units_precedence)`; units are FEET,
METERS, DEGREES or NONE. `MapExtent` uses lower-left and upper-right `Point`
values. MAP requires increasing bounds; BACKDROP also accepts reversed or
degenerate finite bounds, matching the fixed GUI importer. `model.backdrop` is
`Backdrop(file, extent, clear_file, units, legacy_offset, legacy_scaling)`.
Its `FileReference` is an
input resource resolved against the source INP directory and rebased on export.
Loading never opens or verifies the image. `update_map` and `update_backdrop`
change these singleton records, with normal JSON/scenario support.

Legacy BACKDROP UNITS shares the GUI map unit state with MAP UNITS. Both explicit
declarations are retained, and `units_precedence` selects which is written last
when both exist (MAP by default). Import follows physical line order across
repeated sections. `model.effective_map` returns explicit bounds and the resulting
`units`/`units_source`; absent units remain None, distinct from explicit NONE.
It does not infer GUI preferences, automatic bounds or display precision. Changing
precedence alone changes section order on export. BACKDROP precedence requires
both unit declarations; remove it in the same transaction when removing either.

`clear_file=True` with `file=None` writes `FILE ""`, an explicit cleared image;
`clear_file=False` with `file=None` omits the directive. A file and clear flag cannot
coexist. Deprecated OFFSET and SCALING pairs are preserved as `legacy_offset`
and `legacy_scaling`; the fixed GUI parses them into unused private variables, so
these fields are not interpreted as current image geometry. Four-character keyword
prefixes, first-letter unit aliases, repeated assignments and ignored trailing
columns produce diagnostics. Untouched source stays intact; normalization writes
canonical keywords and the last assignment. Missing FILE/UNITS values stay
source-owned with warnings. Invalid MAP bounds are reported rather than silently
discarded as the GUI does. Old JSON lacking the new fields recovers their values
from a same-type original INP record when available, otherwise uses their defaults.
Explicit JSON values always win, including null, empty arrays and false.

These contracts follow the pinned SWMM-GUI 5.2.4
[importer](https://github.com/USEPA/SWMM-GUI/blob/9e026d6bf70efa8ddda541714aa202484d6e54c3/Epaswmm5/Uimport.pas).
No live GUI application test is claimed.

Map coordinates and units are independent of flow-unit changes: changing CFS
to CMS does not rescale MAP/BACKDROP bounds. Unknown map settings remain
source-owned and retain conservative mutation guards. [GUI LABELS and
PROFILES](2.0-display.md) have separate typed records; project JSON annotations
do not substitute for them. [EVENTS](2.0-events.md) has a separate typed schedule because
it changes hydraulic routing, unlike informational map metadata.

## Map geometry ownership

Node and rain-gage `position` values own COORDINATES and SYMBOLS. Link `vertices`
own ordered VERTICES. Both `Subcatchment.polygon` and `Storage.polygon` own
ordered POLYGONS. These are tuples of finite `Point` values in map coordinates;
they do not define conduit length, catchment area or storage volume. Repeated
points, open outlines and short sequences remain valid display data. An empty
tuple removes that owner's polygon/vertices, and `position=None` removes its
coordinate assignment. Old Model JSON without a storage polygon recovers it from
the same storage record in its retained INP source, or defaults to () without one.

The fixed GUI looks up POLYGONS IDs in subcatchments first, then storage nodes.
Same-ID objects of different kinds remain independent, but a storage polygon
cannot be exported when a same-ID subcatchment exists. Validation reports
`geometry.shadowed_storage_polygon`; rename one owner before export. Import
never redirects a malformed declared subcatchment's polygon to a storage node.
Other node kinds do not own polygons. Unknown owners remain source-owned and
retain mutation guards instead of silently disappearing.

Repeated COORDINATES/SYMBOLS assignments use the last pair; VERTICES/POLYGONS
append in physical source order across repeated sections. Declaration order
still determines object order, including when geometry precedes declarations.
Ignored trailing columns are diagnosed and preserved in untouched source;
normalization writes only ID/X/Y. Object renaming updates every associated row,
and removal removes all owned geometry. Copy, transaction rollback, Scenario
and JSON follow the same ownership rules. Hydraulic flow-unit conversion leaves
all these points unchanged; they are excluded from physical cache conditions.

Verification compares complete native OUT and normalized RPT for creation,
portable JSON rebuild and edits on both packaged solver families, and checks
full results after removing the original workspace and relocating checkpoints.
The fixture includes active rainfall, a subcatchment and storage; these checks
do not claim an actual GUI application test.

Source-field upgrades emit `json.source_field_promoted` and materialize recovered
fields on the next JSON write, so removing the source block afterwards remains
lossless. Only explicitly registered optional fields participate (`JsonType`'s
`source_defaults`); source records of different types are never merged. Existing
explicit JSON fields are not replaced. If an old JSON file path conflicts with
a newly recognized `FILE ""` source directive, validation reports the conflict;
choose `file=None` to clear the image or `clear_file=False` to keep the JSON file.
This field upgrade is separate from tracking an object's lineage through edits.

## Object tags

`model.tags` contains `ObjectTag(target=Ref(...), text=...)` values from
`easysewer.model.project`. Its composite key is `(target.collection, target.key)`:
`('swmm:nodes', 'J')` and `('swmm:links', 'J')` are independent tags. Supported
targets are `swmm:raingages`, `swmm:subcatchments`, `swmm:nodes` and `swmm:links`.
An object rename updates both the reference and tag key. Deletion is protected;
an explicit cascade also removes its tag. To retarget a tag, remove/add it within
`model.transaction()`; replacing a row cannot change its identity.

```python
from easysewer.model import Ref
from easysewer.model.project import ObjectTag

model.tags.add(ObjectTag(target=Ref(collection="swmm:nodes", key="J"), text="North area"))
model.tags.update(("swmm:nodes", "J"), text="North district")
```

The effective tag follows SWMM-GUI 5.2.4: repeated assignments use the last value,
class keywords match their first four letters, and trailing columns are ignored
with a diagnostic. Original duplicate rows/comments remain intact until editing
or normalization. The effective collection order survives rename and explicit
`move` operations through INP and JSON. Empty text is an explicit empty tag; remove the record to omit
the assignment. Text can contain spaces and Unicode, but no quotes, semicolons,
newlines or NUL. These cannot roundtrip through the GUI token syntax.

Unlike the GUI's silent omission of unresolved targets, model validation reports
missing references so metadata cannot disappear unnoticed. Unknown object classes
remain source-owned with conservative rename/delete guards. Tags support Model
JSON and Scenario edits, are unchanged by flow-unit conversion and are excluded
from cache physical conditions. Tests compare complete native OUT and normalized
RPT results before/after creation, JSON rebuild, editing and deletion for both
packaged solver families. No live GUI application test is claimed.

Raw-line codecs must declare `FeatureDescriptor.raw_sections` as a subset of
their sections. They may own blank/comment lines and emit `EncodedRow.raw_text`
with no tokens. The framework rejects injected headers/newlines/NUL and retains
the same ownership, record coverage and conflict checks as token codecs.

Verification covers source/JSON/scenario roundtrips, graph references, large
annotation chunks, malformed markers, independent map units, backdrop relocation,
native selection histories, actual OUT values and RPT
table presence. Editing project/report settings on the repository's cubic INP
preserves all 22 unstructured water-quality/land-use rows and its hydraulic
histories. Current delivery boundaries and follow-up work are listed in
[delivery scope](2.0-delivery.md) and [known issues](2.0-known-issues.md).
