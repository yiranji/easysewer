# Testing and builds

Run commands from the repository root. The project uses a `src` layout; ordinary tests can run in an environment with the current package installed. Tests requiring native backends, optional dependencies or platform-specific behavior need the corresponding environment.

## Documentation, schemas and inventory

```console
python tools/audit_docs.py
python tools/build_result_schemas.py --check
python -m unittest discover -s tests -p test_support_matrix_audit.py -v
```

See the [support inventory](2.0-support-matrix.md) for inventory auditing and optional historical-evidence arguments. The `1.x` in Schema files denotes data-format versions used by current readers, writers and tests; these files must not be removed as obsolete software versions.

## Rebuildable delivery

```console
python tools/build_release.py --output dist/rebuild
python tools/audit_docs.py --sdist dist/rebuild/native/easysewer-2.0.0.tar.gz
python tools/qualify_release.py --package dist/rebuild/installed-native --output build/release-native-check
python tools/qualify_release.py --package dist/rebuild/installed-pure --pure --output build/release-pure-check
```

Build and qualification output directories must not already exist. The builder copies documents from the explicit publication list, creates a source distribution, rebuilds native and pure packages from it, verifies tests/fixtures and package members, then installs the packages and checks every file. Native build recipes are documented under [standard](../native/standard/README.md), [custom](../native/flexible_ponding/README.md) and [checkpoint](../native/checkpoint/README.md).

Installed-package qualification covers APIs, editing, scenarios, project metadata, results and the first-run example. It does not replace verification of every platform or physical parameter combination. Run `qualify_release.py --help` for targeted-test and archive-reading options. Quick Start has a separate verifier at `tools/qualify_quick_start.py`.

## Interpreting evidence

Current verification after removal of all 1.x compatibility code is recorded in `build/remove-v1-compat-20260930/verification.json`. Earlier API-removal records are historical snapshots. Documentation cleanup records are under `build/docs-cleanup-20260930/`, and English-language checks are under `build/docs-english-20260930/`. These are local build records and are not bundled in releases.

Each record applies only to its bound source, package and environment. Repeated executions must not be summed as independent tests, and successful retries do not erase initial failures. See the [development archive](development-archive.md) for historical material and [known issues](2.0-known-issues.md) for unfinished work.
