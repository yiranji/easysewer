# Candidate Model JSON 1.0

`Model` persists its graph as `easysewer:model`. Schema version `1.0` is independent of package version `2.0.1` and engine profile `epa-swmm:5.2.4`.

```python
from easysewer.model import Model
from easysewer.io.json import JsonDocument

model = Model.from_inp("network.inp", strict=True)
model.to_json("network.json")
restored = Model.from_json("network.json", strict=True)
restored.links.update("Pipe1", length=125.5)
restored.to_inp("network-edited.inp")

document = model.to_json_document()          # Immutable snapshot; no file IO.
copy = Model.from_json_document(document)
data = document.data                       # Independent ordinary JSON tree.
schema = model.json_schema()                # Includes explicitly enabled types.
```

The built-in [JSON Schema](model-json-1.0.schema.json) uses Draft 2020-12. It checks
the envelope, known field types, tagged variants and collection membership.
Loading also checks case-insensitive duplicate identities, derived record keys,
local value constraints, dates and durations. Graph validation handles references
and feature combinations; JSON Schema alone cannot prove a model runnable.

## Wire representation

The root contains `kind`, `schema_version`, `profile` and an ordered `collections`
array. A collection block has `collection` and `records`; each record has `key`
and `value`. Keys are strings or nonempty arrays of strings for composite
identities. The key must agree with the value's identity. Resource sharing stays
explicit through `core:ref`, with `collection` and `key`; it is not expanded into
duplicate nested resources or converted to engine indexes.

Values have stable namespaced `type` tags. The 181 built-in type declarations
explicitly name wire fields, Python attributes, accepted shapes and defaults.
Neither `__dict__`, class/module names from the payload, nor dataclass inspection
defines the serialized layout. Class renames need not change a wire tag. A new
field or variant needs a deliberate contract declaration. Built-in field coverage
tests detect fields added to domain classes without updating their JSON contract.

- Numeric values retain the model's declared units. `None`, zero and false stay
  distinct. Unspecified options are not replaced with effective profile defaults.
- `core:duration` stores normalized integer `days`, `seconds` and `microseconds`;
  it does not reinterpret durations as INP decimal hours or round through float
  seconds. Days can be negative for general values; consuming fields apply their
  own constraints. Dates, times and timestamps use tagged ISO local values.
  Time/timestamp `fold` is preserved explicitly; timezone-aware values are rejected.
- FLOW and the node-invert offset marker are tagged singleton values, distinct
  from arbitrary strings, nulls and pollutant references.
- File references retain path, base directory, path flavor and input/output
  direction. Saving a JSON file does not rewrite external data or rebind an
  existing base directory to the JSON's new directory. A `native` path flavor or
  missing base remains an explicit unresolved context choice; use `windows` or
  `posix` and a base directory when that interpretation must be portable.
- Arrays retain order, including control programs, geometry points, optional DWF
  pattern slots and time-series records. The loader never sorts them by identity.

The parser rejects duplicate object members, non-finite numbers, integers beyond
the interoperable exact JSON range, malformed temporal values and excessive
nesting (currently 128 levels). This limit and very long expression/performance
cases still require release-gate review. UTF-8 JSON, including BOM and original
spacing, remains byte exact when an imported document has not changed.

`strict=False` allows unresolved graph references to remain as a draft; malformed
typed values still fail. `strict=True` additionally runs current model validation.
Neither mode loads a native library or opens referenced data files.

## Original INP and graph authority

An optional `source` holds the original INP bytes as base64, encoding, source path
and `known_records` ownership ledger. It preserves comments, unknown records,
repeated sections, original spelling and formatting independently of semantic
edits. The structured JSON records are authoritative for known values: loading
does not replace them with older values from that source snapshot.

The ledger distinguishes an intentionally deleted structured object from a
previously unknown source record newly recognized by a codec. It also survives
temporarily reading with fewer codecs. Enabling a feature later can therefore
promote new source data without resurrecting deleted objects or writing duplicate
records. `model.document` and `model.json_document` expose immutable original
snapshots; `to_document()` and `to_json_document()` return current projections.

The optional, independently versioned `source.origins` association ledger preserves
record lineage through rename, relation-key changes, delete/recreate and copying.
Use [`model.provenance(ref)`](2.0-provenance.md) for original record declarations.
Legacy JSON without this ledger reports untracked history rather than inferring
lineage from matching IDs. Explicitly registered newly supported fields can still
be recovered from original INP using `JsonType.source_defaults`; explicit JSON
fields take precedence, and recovered fields materialize on the next save.

JSON and INP saves share atomic byte replacement. Encoding and semantic failures
occur before replacement; failed writes leave the old destination intact and
clean up the temporary file. Copies share immutable snapshots and have independent
editable collections. The ordinary data tree returned by `JsonDocument.data`
cannot mutate the model or document.

## Unknown content and explicit extensions

A newer minor version is retained with a warning; an unsupported major version
is rejected unless an explicitly supplied migration reaches the supported major.
Unknown collections, tagged variants, same-kind enum additions, fields and root
extension payloads are retained. A known object with extra fields remains usable
for an unrelated numeric edit. An unknown variant remains opaque as a whole.
Unknown members in arrays cannot be silently attached to different points after
reordering; affected changes fail and roll back inside a transaction.

Incomplete JSON can be saved as JSON. INP export and execution reject unsupported
JSON content instead of dropping it. Identity changes, reordering and unit
conversion remain conservatively blocked where unknown content may contain
unresolved identities, references or dimensions. Narrowing these footprints is
still part of the remaining extension work. Top-level `extensions` payloads are
currently preserved without interpretation. Explicit informational project data
instead belongs in the typed `easysewer:metadata` collection; its JSON annotations
have an INP comment representation described in [2.0-project.md](2.0-project.md).

Feature authors explicitly register `JsonType` declarations on a `ModelSchema`
using `schema.register_json(...)`. `JsonField` supplies a wire name, a Python
attribute and an explicit shape; the two names can differ. Defaults also belong
to the declaration. Model schemas are snapshots: modifying the original schema
does not change an existing model. Reload with the expanded schema to promote
previously opaque JSON. No payload-directed imports or plugin discovery occur.

The [G-domain candidate verification](2.0-architecture.md) exercises two
explicit test feature generations together: unknown fields and nested variants,
mixed record order, safe edits, source authority, deletion across disabled
codecs, and explicit upgrade in a fresh process. It binds the results to the
installed native and pure packages without claiming solver support for the
synthetic extension section.

## Migrations and remaining integration

`MigrationRegistry.register(source_version, target_version, transform)` declares
one increasing transition. A transform returns `MigrationOutput` with a new
`JsonDocument` and explicit unmapped paths. `upgrade(document, target="1.0")`
runs the declared chain and returns a `MigrationResult` containing computed
add/remove/replace changes, unmapped paths and applied steps. Failed/missing
transitions do not mutate the original document. `Model.from_json(...,
migrations=registry)` exposes the result through `model.json_migration`.

Model JSON schema versions are independent of EasySewer package versions.
The migration registry is a generic extension mechanism tested with explicitly
labeled test versions; it provides no EasySewer 1.x data importer.
[ScenarioPatch/RunConfig](2.0-scenarios.md) use separate document kinds and codecs.

Verification includes fixtures for all 181 declared domain types, 123 model
graphs, unknown-content promotion, composite identities, temporal precision,
source encodings, file relocation, failure injection and independent schema
validation. Native comparisons remove the source INP from JSON before rebuilding:
26 cross-sections, 17 link configurations, four modulated action forms, RULE_STEP
action timing, and five infiltration methods across six flow units preserve full
relevant hydraulic/control/OUT histories. Wheel and pure Python manifest probes
cover JSON graph reconstruction without importing ctypes or legacy/native APIs.

## Cooperative capture

`Model.to_json_document(checkpoint=...)` accepts an optional no-argument work
callback. Built-in collection/record traversal, typed tuple encoding and shape
checks, source/origin merging, preserved plain JSON-tree copying and comparison,
and diagnostic JSON location indexing check between batches. Nested built-in
work inherits an active scope. A callback failure preserves the original
exception object and chain, leaves the source model intact, and does not publish
a partially built location index; the same model/document can be used again.

Ordinary calls preserve existing JSON bytes and unknown/future content behavior.
The cooperative tree operations preserve ordinary Python copy/equality semantics
for JSON values, including aliases and numeric equality. Unknown field edits,
future origin ledgers, and disabled/re-enabled codecs retain their existing
preservation and mutation guards. They do not confer permission to rewrite
unknown structures or promote unsupported content.

Callbacks must not mutate the model. These checks do not make it thread-safe or
provide hard deadlines. One scalar/C/OS operation, base64 conversion, arbitrary
custom copying/equality, and some complete structured-value comparisons can run
until they return. JSON decoding checks at object boundaries, so a scalar-only
array or long string is not internally preemptible. Full INP rendering and
resource work have separate interruption coverage.

`Model.to_json(path)` retains its existing signature and atomic-write contract;
this callback API is on the in-memory document capture. Obtaining a document
with a checkpoint does not imply that a later `document.write(path)` is
cancellable after file publication.
