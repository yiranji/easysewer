# 2.0 model and semantic INP editing

Use `from easysewer import Model` for the 2.0 model. The old public model API has been removed.

## Fast parameter loading and checked loading

`Model.from_inp(path)` assumes valid input and reads parameters without local
field, reference, range or whole-model validation. It creates the same business
objects and preserves meaningful record order, but does not build an original
document, field provenance or a text-editing baseline. Its `to_inp(path)` writes
parameter-equivalent INP directly, without implicit model validation. Numeric
precision, quoting and representability remain serialization requirements;
conversion failures are not silently repaired or truncated.

```python
from easysewer import Model

model = Model.from_inp("network.inp")
model.to_inp("parameters.inp")
report = model.validate()  # Explicit checks of the current objects.
model.to_inp("checked.inp", strict=True)
```

Use `Model.from_inp(path, strict=True)` for checked loading with parser reports,
original source and the existing provenance/editing APIs. Errors raise
`ValidationError`; warnings remain in the retained reports. This runs the
implemented model checks, not native simulation or external-file preflight.
`Model.from_document(document, strict=False)` remains the explicit source-aware
entry point for inspecting malformed drafts without rejecting all report errors.
Schemas containing custom codec classes retain this document-based import
protocol even when `from_inp` is called without `strict=True`.

For fast imports, `model.document` and `model.support` are `None`; source
provenance is untracked. `model.source_path` retains the input path independently
for resource resolution and runtime protection. `to_document()` explicitly
builds a generated document when one is needed; it is not the original snapshot.
Copies and JSON persistence retain the lightweight input context. Existing
public constructors, edit/transaction checks and Runner preflight still apply.

Unstructured parameter rows are retained as lightweight ordered text, rather
than discarded. They conservatively guard identity changes that could invalidate
unknown references. Cross-directory export cannot automatically rebase unknown
file references; use the original directory or explicitly choose
`path_policy="preserve"` when preserving their lexical paths is appropriate.

## Source-aware editing

```python
from dataclasses import replace
from easysewer.model import Model

model = Model.from_inp("network.inp", strict=True)
pipe = model.links["Pipe1"]
model.links.update("Pipe1", length=125.5)
model.nodes.rename("Node1", "Upstream")
model.to_inp("network-edited.inp")
```

`nodes` and `links` are ordered mappings keyed by ID. Iteration yields keys;
`.values()` yields immutable objects. Named IDs match using ASCII case folding,
with original spelling retained. Node and link names occupy separate namespaces.
`Ref(collection="swmm:nodes", key="Node1")` represents a relationship, without
depending on list position, Python object identity, or native object indexes.

`update()` replaces a value. `rename()` updates all known nested references and
recomputes derived relation keys atomically; collisions leave the graph unchanged.
Deleting an object in use fails by default. `deletion_plan(ref)` previews its
transitive dependents, and `remove(key, cascade=True)` explicitly removes them.
`with model.transaction():` validates at commit and rolls back on errors.
`move(key, before=other_key)` changes collection order; omit `before` to move to the end.
`model.copy()` shares immutable values and source snapshots, with independent
editable collections.

## Scope

The model covers the domains in the [documentation index](README.md). The [support inventory](2.0-support-matrix.md) records per-section boundaries; exhaustive combination review remains open. Missing writers fail explicitly. `None`, zero and `Offset.NODE_INVERT` are distinct; LINK_OFFSETS mode is validated with analysis options.

Explicit validation currently checks local fields, references and missing conduit
sections and static analysis-option rules. It does not yet implement every SWMM cross-field rule,
curve-purpose check, or backend run preflight. `ValidationReport.is_valid` means
no implemented checks found an error; review warnings and support information.
The separate [file preflight](2.0-files.md) reads declared input resources;
Model validation itself does not establish their availability or full format validity.

Unparsed input remains source-owned. Identity mutations and additions are blocked
when unknown content could contain a conflicting identity or affected reference.
Current facade constraints are conservative; feature-specific scope narrowing is
pending. Changing an existing supported numeric field remains possible. Invalid
records remain inspectable after document-based import in `model.document`;
source-aware semantic export rejects errors.

For source-aware imports, `model.document` is the immutable imported snapshot.
`model.to_document()` returns
the current projection; exporting twice does not mutate the snapshot or duplicate
records. Deleted row comments remain as standalone comments. New rows receive
explicit section headers. A model with opaque records cannot be saved to another
source directory until its external-file references can be proven safe to rebase.

Numeric hydrology edits replace their bound source rows, preserving unrelated
section headers and records. Changing collection identities/order still rebuilds
the hydrology feature in its declared order. A source with native ordering or
legacy syntax errors also requests a full rewrite when edited, preserving the
existing repair behavior. Normalization remains an explicit full projection;
it is not a promise that every section header appears only once.

## Feature and shape extensions

`ModelSchema` adds structured writers to `SchemaRegistry`. Each codec declares
collection specifications and implements `decode`, `encode`, and `validate`.
`FeatureData` contains immutable `RecordEntry` values and one `SourceBinding` per
claimed line. Each `EncodedRow` has a stable key, tokens, section and owning model
references. Conflicting claims, missing bindings, duplicate writer keys and model
records without an active writer fail explicitly.

A codec may implement `requires_atomic_write(document, profile) -> bool` to
request a full feature rewrite when its source layout requires one. This hook
is consulted for changed features and must return a boolean. It cannot disable
the descriptor's unconditional atomic-write policy, identity-order protection,
stateful section termination or declared writer dependencies.

Schemas are snapshotted when a model is constructed. Promoting an opaque feature
is explicit: register its codec and import the source into a new model with that
schema. `tests/test_model_extensions.py` demonstrates a sensor extension with a
node reference, transactional rename, field editing and a single output record.
This validates a small complete extension path; it does not substitute for the
complete LID and result-extension trials.
[RDII](2.0-rdii.md), [quality/land use](2.0-quality.md) and
[groundwater/GWF](2.0-groundwater.md), plus [treatment](2.0-treatment.md) and [LID](2.0-lid.md), now have structured records and native
integration evidence, with their remaining gates documented separately.

`CrossSectionCodec` separately accepts explicit `GeometrySyntax` registrations
for new numeric parameter layouts. Domain geometry classes do not contain INP
positional parameters. Shapes with resource references have specialized codecs.

Codec emission order is preserved across section transitions. Features can declare
`ordered_sections` to retain identity order when renaming or changing record kinds.
`rewrite_after` names required features whose block rewrites force this feature
to follow their relocated declarations. Features are processed in dependency order.
This matters for native indexing as well as ordered programs; the
[storage/divider guide](2.0-nodes.md) explains the verified engine-ordering case.

## Validation and limits

The native tests target SWMM 5.2.4 and compare full depth, per-step node depth and
link flow, and mass balance between source and emitted input. All 26 shapes plus
three standard-size variants pass. For the 23 numeric/dummy shapes the test
rebuilds a fresh candidate Model to exercise the writer. CUSTOM, IRREGULAR and
STREET use the cross-section codec with hand-authored shared resources, so this
does not declare their full resource Model migration complete.

The later [shared-resource increment](2.0-resources.md) implements CURVES,
TIMESERIES and PATTERNS and adds a fully typed CUSTOM-section native test. IRREGULAR
and STREET resources and inlet placements were subsequently implemented with
their own native tests; see [surface resources](2.0-surface.md).

The native tests exposed a tagged-engine ordering requirement: a following section
triggers finalization of the last transect. The transect writer now handles this
explicitly, and normalized output is available for preserved source needing repair.
See the [5.2.4 input reader](https://github.com/USEPA/Stormwater-Management-Model/blob/v5.2.4/src/solver/input.c).

See [analysis options and transformations](2.0-options.md) for RULE_STEP, profile
resolution and explicit unit/offset operations. [Pumps and regulators](2.0-regulators.md)
complete the five link-family codecs and extend coefficient, curve and offset rules.
[Climate configuration](2.0-climate.md) adds temperature, wind, evaporation and adjustments.
[Rainfall, catchments and snow](2.0-hydrology.md) add the base hydrology chain.
[External flow and DWF](2.0-inflows.md) add node/constituent relations and flow-series consumers.
[Control programs](2.0-controls.md) add ordered rules, named variables/expressions and actions.
[Model JSON](2.0-json.md) adds graph and source persistence with explicit contracts.
Further increments cover [groundwater](2.0-groundwater.md), [water quality](2.0-quality.md),
[LID](2.0-lid.md), [run sessions](2.0-backend.md), [OUT results](2.0-output.md)
and [RPT/LID reports](2.0-report.md). These remain APIs: metadata domains,
complete legacy migration, crash recovery, performance and the full release gates
are still being completed. Platform verification must use the actual interpreter,
packaging profile and native build; a copied pure Python directory or a syntax
check alone is not evidence of WebAssembly or minimum-Python compatibility.

`Model.copy(checkpoint=...)` and `Model.validate(checkpoint=...)` accept an
optional no-argument cooperative work callback. A callback failure preserves
its original exception object and chain. Nested built-in work inherits an
active scope; no callback preserves the existing result and copy semantics.
Copies retain independent record/origin mappings and shared immutable values.
Collection iteration still snapshots key order before yielding any key.

Checks cover record-map copying, collection traversal, recursive reference
scanning, complete reference-index construction, built-in validation traversal
and inline-series calendar checks. An interrupted index is not partially
published. Existing transaction rollback also handles interruption exceptions.
These callbacks do not make a Model thread-safe; do not mutate it concurrently
with capture or validation, or from the callback.

This is cooperative interruption, not a hard deadline. Individual allocations,
scalar operations and arbitrary extension code may run until they return.
Individual validator and extension internals still have boundary limits; a
callback on `validate` does not guarantee a fixed interruption delay.

`Model.to_json_document(checkpoint=...)` accepts the same cooperative callback.
Built-in JSON capture, source merging and preserved JSON trees participate;
see [Model JSON](2.0-json.md) for the covered operations and boundaries.

`Model.to_document(checkpoint=...)` accepts the same optional callback for
in-memory INP capture. Built-in eager encoders, row/source comparison, ordering
and source-document parsing participate in the inherited work scope. Interrupted
capture leaves the caller's model and original document usable. A no-op callback
preserves the ordinary complete INP bytes, including unchanged source formatting.
This does not add a callback to `to_inp(path)` or alter its file-publication
contract. Individual allocation, formatting, sorting, joining, C/OS calls and
arbitrary extension code remain boundary-only; these APIs are not hard deadlines.
