# Candidate rainfall, catchment and snow model

The candidate `easysewer.model.Model` now owns `raingages`, `subcatchments` and
`snowpacks` collections. It also integrates the existing
`subcatchment_adjustments` relation collection. These are immutable records in the
same reference/transaction graph as nodes, links, time series and patterns.

```python
from datetime import timedelta
from easysewer.model import Model, Ref
from easysewer.model.hydrology import (
    RainGage, SeriesRainfall, Subcatchment, Subareas, Infiltration, Horton,
)
from easysewer.model.network import Junction
from easysewer.model.resources import InlineTimeSeries, SeriesPoint

model = Model()
model.nodes.add(Junction(id="J", elevation=0))
model.timeseries.add(InlineTimeSeries(id="Rain", points=(
    SeriesPoint(time=timedelta(), value=.5),
    SeriesPoint(time=timedelta(hours=1), value=0),
)))
model.raingages.add(RainGage(
    id="R", form="INTENSITY", interval=timedelta(hours=1), snow_factor=1,
    source=SeriesRainfall(series=Ref(collection="swmm:timeseries", key="Rain")),
))
model.subcatchments.add(Subcatchment(
    id="S", rain_gage=Ref(collection="swmm:raingages", key="R"),
    outlet=Ref(collection="swmm:nodes", key="J"),
    area=2, impervious_percent=30, width=100, slope=1, curb_length=0,
    subareas=Subareas(
        impervious_roughness=.01, pervious_roughness=.2,
        impervious_storage=.05, pervious_storage=.1, zero_storage_percent=25,
    ),
    infiltration=Infiltration(method="HORTON", parameters=Horton(
        maximum_rate=3, minimum_rate=.2, decay=4, drying_time=2,
    )),
))
model.subcatchments.rename("S", "Catchment")
document = model.to_document()
```

This demonstrates creation/export in default US units. A complete routing run
also needs its analysis period and connected drainage network.

## Data shapes and inherited methods

| Input | Representation |
| --- | --- |
| RAINGAGES | INTENSITY, VOLUME or CUMULATIVE; whole-second interval; snow factor; series or external rainfall file source |
| SYMBOLS | Optional rain gage `position: Point` |
| SUBCATCHMENTS | Area, impervious percentage, width, slope, user-defined curb length, rain gage, typed outlet and optional snowpack references |
| SUBAREAS | Two roughnesses, two depression-storage depths, zero-storage percentage, routing target and optional routed percentage |
| INFILTRATION | One `Infiltration(parameters, method)` configuration, supporting all five methods |
| POLYGONS | Ordered catchment `polygon: tuple[Point, ...]`; storage polygons belong to `Storage.polygon`, with subcatchment IDs taking precedence (see [ownership rules](2.0-project.md#map-geometry-ownership)) |
| SNOWPACKS | Plowable, impervious and pervious parameter groups plus optional removal routing |
| Local ADJUSTMENTS | INFIL, DSTORE and N-PERV MONTHLY pattern references keyed by subcatchment |

An outlet references either `swmm:nodes` or `swmm:subcatchments`. Although the
Python reference records its namespace, native input cannot distinguish identical
outlet names in both collections. Validation rejects this ambiguity; ambiguous
imported catchments remain source-owned. Outfall `route_to` references now also
resolve to this catchment collection.

`Infiltration.parameters` is exactly one `Horton`, `GreenAmpt` or `CurveNumber`
parameter object. `method` selects HORTON, MODIFIED_HORTON, GREEN_AMPT,
MODIFIED_GREEN_AMPT or CURVE_NUMBER. A missing method explicitly inherits the
project option. It is not inferred from the parameter class or silently made
explicit on write. Changing the project method to an incompatible family causes
validation failure; a transaction rolls the change back. Within a compatible
family, inheriting objects follow the new method as native input does.

Horton maximum volume remains optional. Green-Ampt conductivity must be positive
and its initial deficit lies in [0, 1]. Curve Number keeps the supplied number and
diagnoses the engine's [10, 99] clamp; its obsolete second input parameter is
preserved in untouched source and normalized to zero. All five parameter variants
have native source/reconstructed-model comparisons.

The bundled standard revision 16 and custom native revision 14 include the
[Modified Horton MIN state-bound correction](2.0-known-issues.md).
Further finite-capacity issues remain open: the constant-rate/zero-decay shortcut
bypasses state processing, and ordinary Horton can increase its cumulative state
above the cap when drying follows capped wet steps. The
[native reproductions and isolated candidate](2.0-known-issues.md)
record these limits. Modified Horton's `Fe` represents excess infiltration;
ordinary Horton's finite-volume state has a different meaning. The existing input
comparisons establish migration fidelity; full physical qualification continues.

## Snow parameter sets and transfers

`Snowpack` is a named shared parameter set; the engine still creates independent
snow state for each catchment that references it. `PlowableSnow` has a plowable
fraction, while `DepletableSnow` has a full-cover water-equivalent depth. Both carry
minimum/maximum melt coefficients, base temperature, free-water holding fraction,
initial snow and initial free water. Groups can remain absent as native defaults;
at least one row is needed to define the named parameter set.

`SnowRemoval` separates threshold, out-of-system fraction, impervious/pervious
fractions, immediate melt, optional transfer fraction and typed destination.
References survive catchment/snowpack renames and participate in deletion checks.
Run checks reject nonphysical fractions/depths and positive transfer without a
destination, which can otherwise access invalid native memory. A receiving
catchment without pervious snow area is diagnosed as ignoring the transfer.

The fixed engine has two relevant numerical differences:

- Its snow coefficient conversion multiplies by the temperature factor instead of
  dividing. The physical US-to-SI coefficient factor is `25.4 * 1.8`, but preserving
  the fixed engine's internal coefficient requires `25.4 / 1.8`. `basis="engine"`
  uses the latter pinned rule; `basis="physical"` uses the former. Both choices
  remain explicit. Native snow/runoff tests verify engine conversion across all
  six flow units and demonstrate different snow histories under physical factors.
- Transfer between catchments uses surface fractions without the ratio of their
  areas. A recipient with twice the area receives the same snow depth, therefore
  twice the transferred volume. A native test reproduces this and the model warns
  when transferring between unequal areas. No hidden parameter compensation or
  claim of fixing the bundled solver is made.

The manual permits omitting Fsub in REMOVAL. Native 5.2.4 requires that numeric
field even when the transfer is zero, and reports ERROR 203 otherwise. Import
preserves the documented short form with a diagnostic; explicit normalization
emits zero. `for_run` checks the actual projected input and requires that repair.

## Sources, ordering and units

Rainfall series are model resources with consumer-declared units: intensity uses
in/h or mm/h, while volume/cumulative data use in or mm. Shared rainfall series
must have consistent gage forms and recording intervals; each gage's snow factor
remains independent. Active rainfall series cannot simultaneously serve a
different consumer in the fixed native engine. Unused gages are distinguished
from used gages for these runtime checks.

`FileRainfall(file=FileReference(...), station=..., units="IN"|"MM",
start_date=None)` owns no data values. Its file units remain unchanged when the
model changes US/SI, because the rainfall importer converts from the declared file
units. External series files used through TIMESERIES remain subject to the shared
resource conversion restrictions; these two input formats are different.

The fixed reader requires station and unit tokens even for external formats that
ignore them. A manual-style FILE gage missing these fields stays source-owned and
cannot pass executable-document checks; callers must inspect the format and supply
appropriate values. The library does not guess a user-prepared station name.
Same station IDs in different files and conflicting configurations of one shared
file station are diagnosed before execution. Separate [file preflight](2.0-files.md)
checks availability and [user-prepared rainfall data](2.0-data-files.md), including
record-date selection. The eight [historical archive formats](2.0-historical-rainfall.md)
have dedicated read/edit/write and interval inspection. Their native SAVE-cache
and independent USER comparisons are documented in that guide;
[checked RAIN I/O](2.0-native-io.md) also covers runtime failures through
Runner workers. Remaining domain and release qualification continues.

Native series recording intervals round to the nearest second, while numeric
FILE intervals truncate to whole seconds. The importer retains original tokens,
records any coercion, and stores the effective whole-second duration. Normalized
output uses unambiguous clock notation; both paths have native comparisons.

Area, width, depression storage and infiltration values carry their own dimensions.
Slope and percentages are not lengths. Curb length is in the user's chosen buildup
units and does not follow hydraulic US/SI conversion; map positions/polygons also
remain unchanged. Rain file paths rebase in an export copy without reading files.

Native SUBAREAS uses the impervious fraction already assigned by SUBCATCHMENTS.
Native SUBCATCHMENTS also resets local adjustment pointers. The hydrology feature
therefore owns these dependent rows together and writes declarations before their
subareas/infiltration/local patterns. A hydrology edit regenerates that group,
including affected local ADJUSTMENTS; global climate rows retain separate ownership.
Repeated subarea, infiltration, symbol and snow-group assignments retain the final
values while untouched source preserves all original rows.

Inputs whose subareas or local adjustments precede the owning catchment are
preserved, but `for_run` reports the native state-order difference. Explicit
normalization repairs the order to match the typed configuration. Native tests
demonstrate both the differing raw results and the corrected results.

Invalid multirow objects remain source-owned as a whole. Recognizing their header
does not claim a partially parsed aggregate. Identity order follows declarations,
not the position of polygon or associated parameter rows.

## Validation and limits

Ninety hand-authored combinations cover five infiltration methods, three rainfall
forms, two unit systems and three subarea routing modes. Reconstructed models
match complete hydraulic histories, mass balances and precipitation/snow/
evaporation/infiltration/runoff OUT series. Other tests cover equivalent half-hour
storms, all three local adjustment effects, catchment/outfall runon, external IN/MM
files after relocation, shared snow correction, all removal destinations, repeated
assignments and the documented native differences.

Cross-unit hydrology tests compare catchment OUT variables using float32-aware
tolerances; they do not promise strict equivalence of the connected Storage node's
hydraulic state, whose native area/volume constants differ as documented in the
[node guide](2.0-nodes.md). Snow transfer and melt-coefficient differences also
remain explicit limitations of the fixed profile.
