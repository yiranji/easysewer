# Hydraulic event periods

`EVENTS` restricts when SWMM performs hydraulic routing. Between event periods,
the engine retains the previous hydraulic state and ignores network inflows;
hydrology continues over the simulation duration. This changes calculated
results. See section 8.3 of the [EPA SWMM 5.2 manual](https://nepis.epa.gov/Exe/ZyPURL.cgi?Dockey=P10145M6.TXT).

```python
from datetime import datetime
from easysewer.model import Model
from easysewer.model.events import RoutingEvent

model = Model.from_inp("network.inp", strict=True)
model.update_events(periods=(
    RoutingEvent(start=datetime(2020, 1, 1, 1), end=datetime(2020, 1, 1, 3)),
    RoutingEvent(start=datetime(2020, 1, 2, 1), end=datetime(2020, 1, 2, 3)),
))
model.to_inp("event-periods.inp")
```

`model.events` is an immutable `EventSchedule`. Its `periods` tuple retains input
order and duplicate periods, including repeated EVENTS sections. INP periods
have no names: one record at `Ref(collection="swmm:events", key="schedule")`
owns the sequence. Tuple positions are edit positions, not persistent IDs.
Replace `periods` to insert, delete, edit or reorder entries. An empty tuple
removes event restrictions. The same record supports Model JSON and ScenarioPatch.
Flow-unit conversion does not change event times.

Cache-condition comparisons include the event schedule as a physical input.
Changed events cannot satisfy `require_match`. Older cache evidence lacking
event facts remains inspectable but is not assumed to prove a match.

Starts and ends use local `datetime` values without time zones. End must follow
start. Input dates accept numeric or three-letter months. Clock forms, decimal
hours, and times beyond midnight are decoded; 24:00 advances to the next day.
As in native SWMM, fractional seconds in colon clock syntax are truncated and
diagnosed. Decimal hours retain subsecond values at Python microsecond
resolution; a precision reduction is diagnosed. Export uses decimal hours for
subsecond values because native colon clocks cannot retain them.

The model preserves the entered sequence. The fixed engine sorts events by
start time at startup, then clips each overlapping end to the next event's
start. It does not merge overlapping intervals. Overlaps produce a warning;
unsorted input produces an informational diagnostic. Neither is silently
rewritten into a different schedule. Periods outside the simulation are allowed,
as they are in the native engine. An empty schedule and a nonempty schedule
entirely outside the simulation have different meanings.

Untouched source bytes and comments are retained. Editing the schedule rewrites
the owned rows as one ordered block. Trailing columns ignored by SWMM are
diagnosed and removed only when normalized or edited. Invalid rows retain their
source locations and block semantic export. Failed changes leave the previous
schedule intact.

Verification compares full OUT bytes and normalized RPT content for both
packaged solver families, including overlapping, nested, equal-start, unsorted,
outside, next-day and subsecond cases. Adding an event changes hydraulic output;
clearing it restores the unrestricted result. TAGS, LABELS, PROFILES and the
complete metadata acceptance remain separate work.
