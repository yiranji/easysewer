# Scenarios and runtime configuration

Three document kinds separate model state, edits and execution: `easysewer:model`, `easysewer:scenario`, and `easysewer:run`. Each uses schema `1.0`, independently of the package version.

## Finite model edits

```python
from datetime import timedelta
from easysewer.model import Model, Ref
from easysewer.scenario import ScenarioPatch, SetFields, FieldChange

model = Model.from_inp("network.inp", strict=True)
patch = ScenarioPatch(
    profile=model.profile.key,
    flow_units=model.units.flow_units,
    operations=(SetFields(
        target=Ref(collection="swmm:options", key="settings"),
        changes=(FieldChange(name="rule_step", value=timedelta(seconds=20)),),
    ),),
)
patch.to_json("scenario.json")
result = ScenarioPatch.from_json("scenario.json").apply(model)
result.model.to_inp("scenario.inp")
print(result.changes)
```

The original model is never edited. Operations execute in their declared order
on a copy, and the complete graph must validate before a result is returned.
Forward references can be resolved by later operations. Failure returns no
partially edited model. This is a modeling transaction, not native execution;
`validate(for_run=True)` and [Runner](2.0-runner.md) perform execution checks.

Each operation targets an explicit collection and single/composite key:

| Operation | Behavior |
| --- | --- |
| `AddRecord` | Requires an absent identity and matching record identity |
| `ReplaceRecord` | Replaces an existing record without changing its identity |
| `SetFields` | Changes declared **JSON field names**, independent of Python attribute names |
| `AssertRecord` | Requires absence (`value=None`) or the exact typed record value |
| `RenameRecord` | Uses reference-aware graph renaming, including derived composite keys |
| `RemoveRecord` | Protects references; cascading removal must be explicit |
| `MoveRecord` | Moves within an ordered collection, before a key or to the end |
| `ChangeContext` | Explicit conversion or reinterpretation of flow units/offsets; force-main equation supports reinterpretation |
| `ChangePollutantUnits` | MG/L ↔ UG/L conversion or explicit label-only reinterpretation of one pollutant and its consumers |

Field updates preserve unspecified values and distinguish `None`, zero and false.
Nested values such as cross-sections, climate sources and control AST nodes use
the Model JSON codecs. There is no arbitrary attribute traversal or dotted-path
assignment. Updating the three contextual options as ordinary fields remains
protected by the model. Flow-unit conversion has an explicit engine/physical
basis. The optional starting `flow_units` precondition guards numeric payloads;
omitting it means the caller deliberately uses the target model's current units.

`ChangePollutantUnits(target=Ref(collection="swmm:pollutants", key="TSS"),
units="UG/L", mode="convert")` uses the feature-owned [concentration conversion
protocol](2.0-pollutant-units.md), including shared series agreement and rollback.
Its target must be a scalar pollutant ID. `mode="reinterpret"` changes only the
label; count/mass conversion is not inferred. Pollutant units cannot be changed
through ordinary `SetFields`/`ReplaceRecord` operations. A conversion requires a
valid model at that step, so resolve temporary forward references first.

`ScenarioResult.changes` contains actual before/after values and collection
positions per operation, including propagated references and cascaded changes.
`ScenarioResult.patch` retains the exact applied patch and its metadata.
Assert operations fail when their exact wire values differ; they do not collapse
boolean/integer values or timestamps with different `fold`. This also means
preconditions can intentionally reject a separately normalized/rebuilt model.

## Unknown operations and trusted extensions

[Scenario JSON Schema](scenario-1.0.schema.json) describes the envelope and
operation shapes. Target-dependent field validity and graph constraints remain
application checks. Unknown operations or fields inside an operation are retained
as a whole `OpaqueOperation`; applying a patch containing one fails before any
handler is invoked. Unknown root fields and unavailable required capabilities
also block execution. A newer minor version is retained and diagnosed; unknown
major versions fail. An unchanged loaded patch preserves original JSON bytes,
including omitted defaults, BOM and spacing.

An explicit `MigrationRegistry.upgrade(document, target="1.0")` can migrate
either kind before loading, returning changes and unmapped paths. Each format
uses its own declared transitions; no automatic package-version migration is
inferred. Tests use labeled synthetic 0.9 fixtures, not an invented historical
production format.

`extensions` contains explicitly informational metadata. It is retained on the
patch and does not change model state. Behavior that depends on an extension must
declare a required capability and a corresponding operation, rather than hiding
an executable instruction in metadata.

Trusted code may explicitly register an `OperationSpec` on a `ScenarioRegistry`,
with a namespaced key, immutable operation type, encode/decode/apply functions
and a schema document. No payload imports code or discovers plugins. Applying
uses a registry snapshot. Loading again with an expanded registry promotes an
opaque operation; merely supplying a handler at execution does not reinterpret
an already loaded opaque operation. Custom handlers are trusted Python code and
must limit changes to the supplied model copy; this API is not a sandbox for
handler side effects.

## Declarative execution configuration

```python
from easysewer.model import FileReference
from easysewer.runtime import RunConfig, ReportReadOptions

config = RunConfig(
    output_directory=FileReference(
        path="runs/storm-1", base_directory="D:/project",
        flavor="windows", direction="output",
    ),
    backend="swmm:standard",
    report_read=ReportReadOptions(encoding="gb18030"),
)
config.to_json("run.json")
paths = config.resolved_paths()  # Lexical INP/RPT/OUT plan; creates no files.
```

RunConfig holds input/output directories, backend identity, artifact stem,
overwrite/failure-retention policy, wall-clock progress and cancellation polling
intervals, optional wall-time limit, and report decoding/table preferences.
Model simulation periods and SWMM time steps belong in Model/ScenarioPatch.
Callbacks and cancellation tokens are runtime objects and are never serialized.

Paths retain their lexical flavor/base/direction when a config moves. Relative
paths without a base require an explicit resolution context. Output stems are
portable filenames; they cannot contain directory traversal. `resolved_paths()`
does not establish permissions, check collisions or enforce overwrite policy;
those are Runner responsibilities.
The separate [file preflight](2.0-files.md) can inspect Model file consumers and
their declared outputs. Runner combines it with captured inputs and reservations
for all main and declared output artifacts.

[Run JSON Schema](run-1.0.schema.json) and the explicit field codec reject damaged
types. Unknown optional settings are preserved and block `validate_support()`;
unknown tagged settings variants fail to load instead of becoming a valid config.
Unknown extension settings require caller-declared support. Capability checks
use supplied backend/capability information and perform no native discovery.
`preserve` means retain undecodable report bytes, never `errors="ignore"`.

Runner now implements these configuration policies with actual backend probing,
snapshots, cancellation, failure retention and rollback during output publication.
`native_call_timeout` defaults to 30 seconds per RPC, `step_batch_size` to 100,
`file_inspection_limit` to 64 MiB and `normalize_inp` to false. Whole-run deadlines
remain separate from native-call limits. Passing `validate_support()` alone still
does not probe a library or execute anything. See [Runner](2.0-runner.md) for
its precise guarantees and remaining structured result work.
