# Candidate 2.0 hotstart state documents

Runner also records [continuation conditions](2.0-cache-conditions.md) separately
from format/layout identity. HOTSTART4 is a partial state document, including
when the producer end and consumer start match. Known produced HOTSTART artifacts
carry `partial` applicability; omitted LID, RDII and numerical history prevents
claiming a complete checkpoint.

`easysewer.io.hotstart` reads, edits and writes the complete stored state of
SWMM HOTSTART versions 1–4. The supported representation is little-endian
int32/float32/float64, verified with the bundled Windows engine reporting 52004.
The module neither imports native code nor runs a simulation.

## Layout and state are separate

A hotstart file has counts and a flow-unit flag, but no object IDs or type
inventory. Reading requires an explicit immutable `HotstartLayout`:

```python
from dataclasses import replace
from easysewer.model import Model
from easysewer.io.hotstart import HotstartData, HotstartLayout

producer = Model.from_inp("producer.inp", strict=True)
layout = HotstartLayout.from_model(producer)
state = HotstartData.read("final.hsf", layout=layout)

first = state.nodes[0]
edited = replace(state, nodes=(replace(first, depth=2.0), *state.nodes[1:]))
edited.write("edited.hsf")
```

The layout describes ordered `StateObject` nodes/links, `CatchmentLayout`
subcatchments, `StatePollutant` pollutants with concentration units, landuse IDs
and flow units. Catchments declare their effective infiltration method and any
groundwater aquifer/snowpack binding. These bindings determine optional blocks.
Every state record carries its ID; construction rejects mismatched order,
types, dimensions and version-specific block presence.

`from_model(model, normalize=False)` follows the physical order of the INP
that `model.to_document(normalize=...)` exports. Native object indices follow
input section occurrences, which can differ from Model collection order.
Use the exact producer export when establishing historical identity. A new
normalization or export can change order without changing counts.

The automatic adapter currently understands the owned hydraulic, infiltration,
snow, [quality/land-use](2.0-quality.md) and [groundwater](2.0-groundwater.md)
domains. Unknown source content or unregistered state variants raise
`LayoutUnavailable`. It never
silently guesses their absence. Such files can still be read with an explicitly
constructed layout established from the actual producer. A manual layout does
not implement an otherwise unsupported Model domain.

## Stored fields and numeric policy

| State | Fields |
| --- | --- |
| Catchment, v3–4 | Three ponded depths, runoff, six infiltration values; optional groundwater and three snow surfaces; runoff/ponded quality and per-landuse buildup/sweep time |
| Groundwater, v3–4 | Moisture, absolute water-table elevation, flow, maximum infiltration volume per area |
| Each snow surface | Snow depth, free water, cold content, antecedent temperature and antecedent snow |
| Node, all versions | Depth, lateral inflow, pollutant quality; v4 storage adds residence time |
| Link, all versions | Flow, depth, setting, pollutant quality |
| Legacy v1–2 | Additional per-node quality slots preserved even though the current engine discards them |
| Legacy v2 | Two float32 groundwater values for **every** catchment, including those without groundwater |

`InfiltrationState.named_values` exposes the engine fields. `with_values(...)`
edits them by name; the stored six-value tuple includes reserved slots, which
are retained even if nonzero. Horton variants use `tp, Fe`; Green-Ampt variants
use `IMD, F, Fu, Sat, T`; Curve Number uses `S, P, F, T, Se, f`.
Green-Ampt `Sat` must be 0 or 1. The method is supplied by the layout and is not
encoded in the file.

All state values must be finite. Node/link and legacy groundwater values are
rounded to float32 at construction, including ordinary single-precision
underflow. Values exceeding float32 range are rejected. Other stored fields
are float64. This makes the immutable object describe the actual bytes it will
write. Signed zero and finite reserved values survive read/write unchanged.
Truncation, trailing bytes, header mismatches and optional-block mismatches are
errors. Byte lengths are checked before decoding the body.

State values use **internal engine units**, even in SI projects: hydraulic
depth/elevation in feet, flow in cubic feet per second and residence time in
seconds. Groundwater maximum infiltration volume is an equivalent depth in
feet, despite the native field's volume name. Pollutant concentrations follow
their declared units; buildup is a different mass quantity and is not a
concentration. No automatic unit conversion is performed. Negative flow or
elevation can be meaningful, so finite checks do not indiscriminately reject
negative numbers. Complete physical appropriateness requires model-specific
validation beyond this document codec.

Versions 1–2 omit newer runoff state; versions 1–3 omit storage residence time.
Changing `version` with `replace` requires explicitly supplying/removing the
corresponding blocks. Nothing is silently discarded or filled. A v1 node count
whose low byte is ASCII `2`, `3` or `4` aliases a later signature in the native
reader; new v1 documents with such counts are rejected.

`to_bytes()` reconstructs the complete binary representation. For a valid
unchanged file it is byte-identical, with no hidden unparsed payload.
`write()` encodes before atomic replacement; a failure preserves the old file.
Model INP/JSON store file references only and do not embed this external data.

## Explicit identity manifests

Parsing with a target layout cannot prove that the producer had those IDs,
types or methods. `HotstartManifest` records an explicit **caller assertion**
and binds it to the exact state bytes:

```python
from easysewer.io.hotstart_manifest import HotstartManifest
from easysewer.runtime import check_files

# producer_layout must come from independently established producer context.
manifest = HotstartManifest.asserted(state.to_bytes(), layout=layout)
manifest.write("final.hsf.manifest.json")

# consumer already has a USE HOTSTART binding to this exact state file.
checked = check_files(consumer, interface_manifests={"HOTSTART": manifest})
checked.report.raise_for_errors()
```

The manifest verifies SHA-256 plus ordered IDs, object kinds, infiltration
methods, groundwater/snowpack bindings, pollutants/units, landuses and flow
units. IDs compare with SWMM's ASCII case-insensitive rule. Changes to bytes,
order or meaning fail verification even when header counts still match.
Optional `producer_input_sha256` and `engine_sha256` record provenance; the
preflight does not authenticate them or verify a currently selected backend.
A checksum alone does not prove how a file was produced. Creating a manifest
from an arbitrary file and the target model adds no independent origin proof.
[Runner](2.0-runner.md) creates evidence from actual producer bytes, executed INP,
loaded backend and native object order. This is observed provenance, not a signature.

The UTF-8 sidecar has schema `easysewer.hotstart-manifest/1`. Decoding rejects
duplicate, missing, extra and unknown-schema fields; it performs no dynamic
class loading. Sidecars are read/written only through explicit calls and never
auto-discovered. The manifest is a separate file and is invalidated by state
edits; writing the state does not rewrite its provenance.

## Preflight states and limits

| Situation | Status |
| --- | --- |
| Known target layout, no manifest | `state_checked`, with a positional-identity warning |
| Known target layout, matching caller manifest | `validated`, with an informational assertion/provenance notice |
| Target layout unavailable, no manifest | `header_only`, with a layout warning |
| Target layout unavailable, manifest supplied | `partial`: all payload bytes checked under the asserted layout, target compatibility unresolved |
| Wrong bytes/counts/layout/manifest | `invalid` |

`check_files.complete` remains false when warnings or other incomplete inputs
exist. An unused manifest, including when the byte budget prevents inspection,
is diagnosed. A custom HOTSTART inspector cannot silently bypass a supplied
manifest. [RUNOFF/RDII cache manifests](2.0-runoff-cache.md) use the same
explicit-evidence policy with their own format-specific layouts.

Even successful file preflight does not establish that a restart is physically
appropriate after model parameter edits, or guard against files changing
after inspection. HOTSTART is not a full simulator checkpoint: the reviewed
format omits LID state and other runtime histories. No continuous-run/restart
equivalence or restoration of omitted processes is promised. Runner captures
resources and records snapshot/backend identity; physical reuse still requires
domain-specific assessment.

## Validation and limits

Pure tests independently pack all four versions, five infiltration methods,
optional states and quality combinations; test every truncation and nonfinite
body values; and check ordered identity, strict manifests and atomic failures.
Native tests cover five methods under US/SI, all optional blocks with two
pollutants and two landuses, legacy-format consumption and source-order changes.
Unedited bytes and complete native object/system/RPT results agree. A depth edit
changes actual results and matches an independent byte-patch oracle. Both
pollutants' OUT time series are checked for the full-state fixture.

The primary references are the tagged v5.2.4
[hotstart.c](https://github.com/USEPA/Stormwater-Management-Model/blob/v5.2.4/src/solver/hotstart.c),
[infil.c](https://github.com/USEPA/Stormwater-Management-Model/blob/v5.2.4/src/solver/infil.c),
[gwater.c](https://github.com/USEPA/Stormwater-Management-Model/blob/v5.2.4/src/solver/gwater.c),
[snow.c](https://github.com/USEPA/Stormwater-Management-Model/blob/v5.2.4/src/solver/snow.c)
and [input.c](https://github.com/USEPA/Stormwater-Management-Model/blob/v5.2.4/src/solver/input.c).
The tagged writer's multi-pollutant buildup loop writes the pollutant count
instead of one double for each value. The previous Linux standard binary
reproduced this defect: one catchment, one land use and two pollutants produced
247 bytes where the v4 reader layout requires 231. Runner rejected that file
before publication; the previous candidate wheel independently reproduced it.

The [standard native build](../native/standard/README.md) now fixes the C count
and records the pinned EPA source, patch, compiler options and binary digests.
Direct SAVE/USE tests cover two catchments, two land uses and 0/1/2/8 pollutants
under US/SI, with independent mass and byte-position checks. Header and scalar
reads are checked, trailing/nonfinite values are rejected, read-only input works,
and write/close failures report 334 without hiding an existing primary error.
The Python layout protection remains strict; old malformed files are not repaired
by guessing. Engine version 52004 alone still does not prove matching patches.
The [custom native build](../native/flexible_ponding/README.md) independently
applies the shared checked-I/O/resource patches while retaining ABI 201 and its
already-corrected buildup count. Other native I/O audits remain open. Actual
Windows Python 3.10 and Node/browser WASM pure-module execution have passed the
documented qualification groups; a formal pure wheel and the remaining platform
and browser matrix are separate release gates.

[LID deployments](2.0-lid.md) now participate in Model layout checks without inventing binary state fields. USE HOTSTART with active LIDs reports `lid.hotstart_state`: initial saturation is reapplied, and clogging/drain state is not restored.
