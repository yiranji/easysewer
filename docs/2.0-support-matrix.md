# Support inventory and evidence scope

The [machine-readable inventory](2.0-support-matrix.json) records 57 SWMM 5.2.4 sections, 356 variant groups, implementation owners, test modules and boundaries. Having a codec or test for a section does not prove every input combination has been verified.

Seven sections and 39 groups previously completed 312 individual gate reviews. Their evidence binds the source and packages from those runs and is now marked `historical_gates_verified`. The other 50 sections and 317 groups still require exhaustive item-by-item review. Historical evidence is not promoted to acceptance of current source.

## Auditing

The default audit checks inventory consistency, test entry points and native option spellings:

```console
python tools/audit_support_matrix.py --native-source PATH_TO_SOLVER_SOURCE --output NEW_AUDIT.json
```

The native source directory must contain `keywords.c`, `text.h`, `project.c` and `dwflow.c` from the pinned version. Specify a local historical archive to additionally verify file digests and gate-entry completeness:

```console
python tools/audit_support_matrix.py --native-source PATH_TO_SOLVER_SOURCE --evidence-root build/docs-cleanup-20260930/archive --output NEW_HISTORY_AUDIT.json
```

`--evidence-root` neither reruns tests nor establishes that old evidence remains valid for current source. A successful audit still reports `full_acceptance: false`. See the [development archive](development-archive.md) for historical material and [testing](2.0-testing.md) for current verification entry points.
