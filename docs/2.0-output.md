# Candidate OUT results

`easysewer.io.output.OutputReader` reads SWMM 5.2.4 OUT files without loading a
native library or requiring NumPy/pandas. It owns one file and supports explicit
`close()` or a context manager. Entering a context does not initialize it twice;
repeated close is safe. IO, decoding and result-data failures close the file.
Argument and missing-selection errors can be handled inside the same context.

The legacy `easysewer.OutputAPI.SWMMOutputAPI` adapter requires output I/O
revision 1, initializes one native handle and supports explicit `close()`.
`SWMMOutputError` carries the failing `operation` and SMO `code`. Native series
ranges remain nonempty and end-exclusive. See the [native reader contract](../native/output/README.md)
for allocation ownership, diagnostic failed-run footers and the differences
between legacy native queries and portable result queries. Neither reader
needs network access.

Use the result of a successful run to bind queries to its actual artifact:

```python
from easysewer.model import Ref

with result.open_output() as output:
    depth = output.series(Ref(collection="swmm:nodes", key="J1"), "swmm:depth")
    concentration = output.series(
        Ref(collection="swmm:nodes", key="J1"), "swmm:concentration",
        pollutant=Ref(collection="swmm:pollutants", key="TSS"),
    )
    system_flow = output.series(None, "swmm:inflow")

peak = depth.maximum()
depth.to_json_document().write("node-depth.json")
```

`RunResult.open_output()` checks the saved file size, streams its SHA-256, and
compares actual metadata with that run's captured identities. Editing the Model
does not rename, reorder or convert existing results. Changed artifacts fail.
The returned immutable `ResultSeries` contains object and pollutant references,
variable key, units, actual saved dates, zero-based period numbers, values,
missing reasons, sampling semantics and source identity. It remains usable after
the reader closes. `ResultSeries.from_json_document()` restores that versioned
value contract without a Model, reader or native library.

## Selection and units

Object names come from OUT, not from the Model or engine node array. ASCII case
matching follows SWMM while preserving the actual spelling. A REPORT subset can
exclude an otherwise valid model object; querying it raises `NotRecordedError`.
Pollutants are a separate `Ref` dimension, never a positional variable key.

Call `output.available_variables("swmm:nodes")` to inspect recorded definitions.
Built-in keys include:

| Collection | Keys (each prefixed `swmm:`) |
| --- | --- |
| subcatchments | rainfall, snow_depth, evaporation, infiltration, runoff, groundwater_flow, groundwater_elevation, soil_moisture, concentration |
| nodes | depth, head, volume, lateral_inflow, inflow, overflow, concentration |
| links | flow, depth, velocity, volume, capacity, concentration |
| system | temperature, rainfall, snow_depth, infiltration, runoff, dry_weather_inflow, groundwater_inflow, rdii_inflow, external_inflow, inflow, flooding, outflow, storage, evaporation, potential_evaporation |

Concentration is available only when pollutant columns were recorded. It uses the
actual MG/L, UG/L or #/L entry for the selected pollutant. Flow uses the OUT flow
unit; depth/head, volume and velocity use its US/SI family. Rainfall/infiltration
are in/h or mm/h; evaporation/PET are in/day or mm/day. Capacity means area/full
area for conduits and speed/opening setting for pumps/regulators. System storage
includes nodes and links. Observed values retain their saved units. Captured
[result applicability](2.0-result-applicability.md) can mark an inactive process
or absent binding as unavailable; such numeric non-results return `None` with a
reason. Partial/unknown observations retain their numbers and explicit scope.

## Sampling is part of the result

Dates are read from each selected binary record in the timezone-free model
calendar. They are not synthesized from a current Model or from the header's
saved start. `start` and `stop` select zero-based periods with an exclusive stop.
The selected range's timestamps are checked for finite, strictly increasing
values, including the preceding record at a chunk boundary. Unread records are
not claimed to have passed a full data scan.

`depth.maximum()` means the maximum of the saved observations, with the first
time in a tie. Its statistic is `easysewer:saved-observation-maximum`; it is not
the RPT/native internal-routing-step peak. It returns an explicit no-observation
or all-missing reason when appropriate and reports the number of missing values.
Integrating sampled rates is not automatically an exact solver balance.

REPORT AVERAGES is retained from the run and persisted in its execution record:

* Node and ordinary link results use an arithmetic mean of routing-step results,
  not a duration-weighted mean.
* Pump/regulator capacity keeps the last setting even when averages are enabled.
  The reader uses the actual link type stored in OUT for this distinction.
* Subcatchment results retain report-time values. System flow channels use the
  state at reporting; total inflow combines runoff and routing inflows. System
  storage follows the producer's average/non-average save path. These channels
  are not all labeled as averages.

FlexiblePonding's node overflow and system flooding semantics are propagated
from the backend. They describe external/ordinary system loss, rather than
silently labeling retained ponding as flooding loss.

For an external OUT, use `OutputReader(path, encoding="utf-8")`. The encoding is
for identifier bytes and is retained in source metadata; legacy encodings require
an explicit choice. Unicode filesystem paths do not pass through C `fopen`.
Bare OUT contains neither the producer's custom ABI nor the REPORT AVERAGES
switch, so those interpretations remain `producer-unspecified`. Do not infer
them from the presence of a 52004 engine-version integer.

## Bounded reading and lifetime

```python
with result.open_output(max_series_values=10_000, max_buffer_bytes=256*1024) as output:
    for chunk in output.iter_chunks(
        Ref(collection="swmm:links", key="P1"), "swmm:flow", chunk_size=1_000
    ):
        consume(chunk.times, chunk.values)
```

The metadata byte budget defaults to 64 MiB. `max_series_values` bounds a materialized
series or chunk (default one million observations); use iteration for larger
selections. The result buffer defaults to 1 MiB; if a complete block does not fit,
the reader seeks to selected timestamps and values. These limits bound source
payload allocations and observation counts, not total Python/OS memory overhead.
Chunk iteration does not retain earlier chunks. The caller owns the reader's
lifetime, including when abandoning an iterator. Read operations on one reader
are serialized; interleaved iterators use absolute offsets.

Initialization and each read check file state; run-bound readers additionally
verify the digest on open. This detects ordinary modification, truncation and
replacement of run artifacts, not arbitrary concurrent adversarial modification.
Nonfinite values fail by default. Explicit `invalid_values="preserve"` instead
returns `None` with `nonfinite_source_value`, retaining source identity; zero is
never used to conceal missing/corrupt observations. Nonfinite dates always fail.

## Adding variables

`OutputVariables.with_variables()` returns a new immutable registry. A plugin
can supply a namespaced key, recorded code, units and semantics without changing
the query or `ResultSeries` type. Duplicate keys/codes and collisions with actual
pollutant columns are rejected. Unknown recorded codes remain queryable as
`swmm:unknown-<code>` with an unknown unit and semantics until a definition is
provided. The file itself and its variable-code metadata remain available.

The profile is explicitly 5.2.4. New binary layouts require a reviewed profile
adapter. This reader does not migrate the old `SWMMOutputAPI` class in place.
[RPT documents and tables](2.0-report.md) provide 43 native summary, status, input and
diagnostic codecs, printed object observations and separate LID results. These
preserve printed precision and dry-time gaps. Additional status adapters and the
remaining migration/release gates continue separately.

Reference: SWMM 5.2 manual, Chapter 9/Table 9-1, and tagged
[SWMM 5.2.4 output.c](https://github.com/USEPA/Stormwater-Management-Model/blob/v5.2.4/src/solver/output.c).

## Cooperative metadata reads

`OutputMetadata.read(path, checkpoint=...)` and
`OutputMetadata.from_stream(stream, checkpoint=...)` accept an optional
no-argument callback. Built-in identity, property and variable traversal checks
between batches. Calls nested inside an active work scope inherit that scope.
Ordinary reads and a no-op callback produce the same complete metadata and
malformed-input errors; byte limits and strict short-read rejection are unchanged.
An override of `from_stream` still receives the original encoding and limit
arguments when called by `read`, without a newly forced callback keyword.

The stream overload keeps the caller-owned stream open on success, parse failure
and callback failure. Interruption may leave its cursor advanced; a subsequent
metadata read seeks from the required positions and can retry on the same
seekable stream. The path overload closes its owned stream. Callback exceptions
retain their original identity and chain rather than becoming parse errors.
Callbacks must not mutate the source. A single read, decode, allocation or other
C/OS operation cannot be forcibly interrupted; this is not a hard deadline.
