# Candidate 2.0 RUNOFF and RDII cache documents

Runner now offers separate [cache production-condition evidence and reuse
intents](2.0-cache-conditions.md). These supplement the byte/layout contracts
below and do not change what the native cache format stores.

`easysewer.io.runoff_cache` reads, edits and writes all stored fields of the
little-endian SWMM 5.2.4 RUNOFF and binary RDII formats without importing a
native library. Records and arrays are immutable values; edits use
`dataclasses.replace`. Valid unchanged files write byte-identically. Writers
encode before atomic replacement, preserving an existing file on failure.

## RUNOFF

```python
from dataclasses import replace
from easysewer.io.runoff_cache import RunoffLayout, RunoffData

layout = RunoffLayout.from_model(producer)
data = RunoffData.read("runoff.bin", layout=layout)
first = data.frames[0]
sample = replace(first.samples[0], runoff=first.samples[0].runoff * 1.1)
edited = replace(data, frames=(
    replace(first, samples=(sample, *first.samples[1:])), *data.frames[1:],
))
edited.write("edited.bin")
```

The header contains catchment and pollutant counts, a flow-unit flag and a
frame count. It has **no object IDs and no absolute start date**. Reading needs
an explicit `RunoffLayout` with flow units, ordered catchment IDs and ordered
`StatePollutant` IDs/concentration units. The current automatic Model adapter
uses the actual exported INP order, including [typed pollutants](2.0-quality.md),
and rejects unknown source content. An explicit layout
can describe such files, but does not prove compatibility with that target.

Each `RunoffFrame` stores positive `step_seconds` and one `RunoffSample` per
catchment. Samples contain rainfall, snow depth, evaporation, infiltration,
runoff, groundwater flow, groundwater elevation, soil moisture and every
pollutant concentration. Their order and quality dimensions must match the
layout. All stored numbers, including the time step, are quantized to finite
float32 at construction. Values use **project units**, including rainfall
rate, depth, flow, groundwater elevation and declared concentration units;
soil moisture is a fraction. No implicit unit conversion is performed.

`duration_seconds` sums the stored steps. Native reuse advances a relative
runoff clock and clamps its final time to the simulation duration. The codec
does not assign a calendar origin or claim that the original rainfall dates
match a consumer's start date. Exact byte length, counts, unit flag, finite
values and positive steps are checked before accepting the data.
Successive steps must also advance the native double-precision millisecond
clock; a positive value too small to advance that clock is rejected. There is
no arbitrary minimum time step. The qualified native libraries perform their
own [complete RUNOFF I/O checks](2.0-native-io.md), including runtime reads.

## Binary RDII

`RdiiData.read(path)` needs no layout to decode the bytes. It contains a
positive whole-second `step`, ordered native `node_indices` and `RdiiFrame`
records. Each frame stores float64 `native_time` and float32 `flows`.
`native_time` is SWMM days since 1899-12-30; the `.time` property is a convenient
Python datetime view and retains neither additional precision nor timezone
information beyond that view. The original native double is kept for writing.

RDII binary flows are **CFS even in SI projects**. Its header contains no flow
unit flag and no node names. Use `RdiiLayout(nodes=..., bindings=...)` to
establish the full native node order and each `RdiiBindingIdentity`'s receiving
node/hydrograph ID. `RdiiLayout.from_model(model, normalize=False)` follows the
actual exported INP order; use the same normalization policy as the producer.
`data.validate_layout(layout)` checks bounds and requires an RDII binding at
every cached node, matching the binary reader's requirement.

Frames may have gaps. Overlapping or reversed intervals, nonfinite values,
duplicate indices and partial frames are rejected. A dry simulation can write
**only a header and indices, with zero frames**; this is valid and is tested
against native production and reuse. The format has no stored frame count,
so a complete frame-aligned prefix is structurally valid. The document alone
cannot detect that a longer original file was shortened at a frame boundary.

RDII text interfaces remain `RoutingInterface` documents with explicit header
IDs/units and different native binding behavior. A binary manifest cannot be
applied to a text file. Model's FILES references retain the existing native
process-working-directory rule for RDII paths.

## Explicit positional identity evidence

```python
from easysewer.io.cache_manifest import CacheManifest
from easysewer.runtime import check_files

# Obtain this layout from independently established producer context.
manifest = CacheManifest.asserted(data.to_bytes(), layout=layout)
manifest.write("cache.manifest.json")
checked = check_files(consumer, interface_manifests={manifest.kind: manifest})
checked.report.raise_for_errors()
```

The manifest schema is `easysewer.cache-manifest/1`. It binds SHA-256 to either
RUNOFF catchment/pollutant order and units, or RDII full node order and nodal
hydrograph bindings. IDs compare using SWMM's ASCII case-insensitive rule.
Optional `producer_input_sha256` and `engine_sha256` record caller-supplied
provenance. Strict JSON rejects duplicate/unknown fields and unknown schemas;
reading and writing are explicit, with no sidecar discovery or class loading.

This is a **caller assertion**, without authentication of how bytes were
produced. It does not record all rainfall, dates, RTK/IA, area, hydrology or
quality parameters, and cannot establish physical suitability or freshness of
a cache. Constructing evidence from an arbitrary file and the consumer's
current IDs supplies no independent producer proof. [Runner](2.0-runner.md) now
records actual producer inputs, backend/resource snapshots and cache bytes;
this observed evidence does not certify physical reuse or authenticate an author.

With an understood target and no manifest, preflight reports `state_checked`
with a positional-identity warning. Matching explicit evidence yields
`validated` and an informational assertion notice. Unknown target dependencies
remain `partial`, even if all bytes match the asserted layout. Incorrect bytes,
identity, units or bindings are invalid. A custom inspector cannot bypass
supplied evidence; unconsumed evidence warns. Model/run validation, physical
reuse appropriateness and files changing after preflight are separate gates.

## Validation and limits

Independent packed fixtures cover all sample fields, zero/one/two pollutants,
float32 edits, truncation, nonfinite values, dimensions, ordered identity,
strict manifests and atomic failures. Native tests read and rewrite real
RUNOFF caches in CFS/CMS, including two pollutants and groundwater, and compare
full result series plus both pollutant series. RPT comparisons normalize only
the echoed cache filename. RDII tests cover monthly production, empty caches,
reuse and identity checks. Editing either cache's flows changes real hydraulic
results and matches an independent byte-edit oracle.

References are official v5.2.4
[runoff.c](https://github.com/USEPA/Stormwater-Management-Model/blob/v5.2.4/src/solver/runoff.c)
and [rdii.c](https://github.com/USEPA/Stormwater-Management-Model/blob/v5.2.4/src/solver/rdii.c).
The tests compare original-cache reuse with rewritten-cache reuse, without
assuming native cached and uncached runs reproduce every internal state.
[Groundwater](2.0-groundwater.md) now has a typed Model domain and native cache
checks. Full runtime provenance,
large-cache performance and actual cross-platform execution remain open gates.

[LID](2.0-lid.md) native tests verify byte-preserving cache read/rewrite/consume. RUNOFF stores aggregate subcatchment runoff, including LID drainage, without its separate outlet/removal factors. USE RUNOFF skips LID state calculations; Model warns about omitted detailed performance and rejects run configurations requiring distinct drain destinations or removal. Native alternate-outlet tests prove the routing/quality difference. A valid cache layout does not establish physical reuse compatibility.

The qualified native builds now correct evaporation and groundwater recovery
under `easysewer:runoff-physics:1`. See the complete
[field and state contract](2.0-runoff-replay.md), including interpolation,
zero-area catchments, informational rainfall, current-gage controls and partial
HOTSTART state. A byte-correct edit of the rainfall column does not change
reported rain or rain-gage controls. Existing producer evidence with an older
engine hash is not silently upgraded to the new numerical policy.
