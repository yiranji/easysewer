# Candidate shared resources

The candidate `easysewer.model.Model` owns `curves`, `timeseries` and `patterns`
as independent ID collections. Rainfall, climate, boundary conditions and controls
refer to these resources; no consumer owns or clears all time series.

```python
from datetime import timedelta
from easysewer.model import Model, Ref
from easysewer.model.network import Outfall, SeriesBoundary
from easysewer.model.resources import InlineTimeSeries, SeriesPoint

model = Model()
model.timeseries.add(InlineTimeSeries(id="Stage", points=(
    SeriesPoint(time=timedelta(), value=1.0),
    SeriesPoint(time=timedelta(hours=1), value=1.5),
)))
model.nodes.add(Outfall(id="O", elevation=0, boundary=SeriesBoundary(
    series=Ref(collection="swmm:timeseries", key="Stage"),
)))
model.timeseries.rename("Stage", "BoundaryStage")
model.convert_units("CMS")
model.to_inp("model.inp")
```

This example uses the default CFS model units before conversion. It demonstrates
resource ownership, references and export; a runnable drainage network also needs
its links and analysis period.

## Data and INP representations

`Curve(id, kind, points)` uses `CurvePoint(x, y)` records. All 12 fixed-profile kinds
are recognized: STORAGE, SHAPE, DIVERSION, TIDAL, PUMP1–PUMP5, RATING, CONTROL and
WEIR. The codec accepts a separate type declaration or points on the first line,
multiple pairs per line, continued/interleaved resources and repeated sections.
X values must increase strictly. An unused empty curve is retained with a warning;
a supported consumer requires nonempty data and the appropriate curve kind.

`InlineTimeSeries` contains `SeriesPoint(time, value)` records. A `timedelta` is
relative to the full simulation start (date plus start time); a timezone-free
`datetime` is an absolute local calendar timestamp. The parser resolves omitted
dates independently for each series. Relative points can precede absolute points;
after switching to a calendar date, subsequent points use explicit timestamps in
the domain model. Resolved points must increase strictly.

Negative values are valid for general time series. Numeric hours, negative elapsed
hours, over-24-hour clocks and multiple pairs per row are supported. Decimal times
are represented at microsecond resolution. Native clock notation truncates
fractional seconds; normalization emits a diagnostic. The writer uses numeric hours
for fractional seconds and explicit dates for calendar points, avoiding dependence
on another row's omitted date.

`FileTimeSeries(id, file=FileReference(...))` is a separate variant. Import does not
open or inline the external file. The reference retains its origin and input
direction; `to_inp()` rebases it in an export copy. Missing files can be modeled
without IO, while later backend preflight must check actual availability. Conflicting
FILE declarations and mixed inline/file rows currently remain source-owned with
errors instead of selecting one silently.
The separate [external data API](2.0-data-files.md) now reads/edits time-series
files, offers explicit inline materialization and checks their native date-state
rules through `check_files`; it does not make Model import perform hidden IO.

`Pattern(id, kind, factors)` supports MONTHLY, DAILY, HOURLY and WEEKEND. Explicit
factor count is retained, and `effective_factors` fills omitted native values with
1.0. The engine's 24-factor storage limit and unused factors beyond a monthly/daily
period are diagnosed. Negative factors are not silently changed.

Unchanged imported resources preserve their original bytes. Editing a resource
regenerates the codec's owned blocks in valid order and retains standalone comments
and unknown resources. A malformed resource is preserved as a whole; valid leading
rows are not detached from its unsupported or invalid continuation.

## Purposes, units and extensions

The graph handles existence, rename, deletion and shared references. Consumer
features additionally declare `ResourceUse` values with an exact reference path,
role, accepted kinds and dimensions. `model.resource_uses(ref)` returns those
declarations. Current network declarations cover TIDAL outfalls, TIMESERIES stage
outfalls, CUSTOM cross-sections, storage/diversion laws, custom inlets, pump curves,
outlet ratings and weir coefficient curves. Climate adds temperature/evaporation
series and MONTHLY pattern purposes; later consumers must add their own.
Conflicting declared dimensions are validation errors.

Standard curve axes use their declared kind, so storage area is not confused with
depth, SHAPE stays normalized, and pump volume differs from flow. General time
series require dimensional declarations from every consumer before conversion;
unbound or incompletely declared series are rejected. A shared sequence is converted
once regardless of the number of references. WEIR axes are depth and the dedicated
weir coefficient dimension; CONTROL still requires consumer-specific rules and
remains restricted until those consumers are implemented. External file values are not rewritten by model conversion; a change
that would alter those values fails atomically and requires a separate explicit
data-conversion operation.

Features may declare `unit_transforms: tuple[UnitTransform, ...]` for exact value
types. Each transform receives a `ConversionContext` with source/target units,
profile, scalar conversion and read access to the immutable source graph and
resource-use declarations, plus `convert_value` to delegate conversion of nested
children. Duplicate registrations fail. Tests demonstrate an
independent sensor conversion and a temperature-series consumer without adding
type branches to Model or the generic conversion traversal.

## Validation and limits

The tests cover resource roundtrips, ordering, invalid blocks, references, file
rebasing, dimensions, extension hooks and rollback. Tagged SWMM 5.2.4 comparisons
exercise all curve/pattern syntax, a fully typed CUSTOM section, relative/calendar
stage series, tidal boundaries, actual weekday/weekend dry-weather patterns, and
an external FILE after moving its INP. Complete hydraulic histories and mass
balance match; stage-series unit conversion also matches within strict tolerance.
