# 2.0 interface files and external resources

Typed FILES bindings provide explicit inventories, read-only preflight and editable routing text. Runner captures active inputs, reserves declared outputs, and records ownership and hashes.

## FILES bindings

```python
from easysewer.model import Model, FileReference
from easysewer.model.files import InterfaceFile

model = Model.from_inp("network.inp", strict=True)
model.files.add(InterfaceFile(
    kind="HOTSTART", mode="SAVE",
    file=FileReference(path="final.hsf", direction="output"),
))
model.to_inp("runs/network.inp")
```

`model.files` is an ordered collection keyed by `(kind, mode)`. USE references
must have input direction and SAVE references output direction. The documented
combinations from SWMM 5.2 Appendix D, printed page 336, are:

| Kind | Modes | Native identity dependency |
| --- | --- | --- |
| RAINFALL | USE or SAVE | External station IDs and rain gage configuration |
| RUNOFF | USE or SAVE | Subcatchment/pollutant order and flow-unit flag |
| HOTSTART | USE and/or SAVE | Object order, counts, subtypes and state layout |
| RDII | USE or SAVE | Node indices for binary data; node IDs for text |
| INFLOWS | USE | Header node and pollutant IDs; data rows are positional |
| OUTFLOWS | SAVE | Current outlet node and pollutant IDs |

RAINFALL/RUNOFF/RDII each have a single active native slot: repeated input
assignments use the last value. HOTSTART has separate input/output slots, whose
paths must differ. Source bytes retain all assignments until the feature is
edited or normalized; the structured graph records their final native meaning.
Creating both USE and SAVE for a single-slot kind is a validation error.

Native keyword-prefix matches and ignored trailing tokens have diagnostics.
Two-token directives without a filename are preserved as native no-ops.
Undocumented NO/SCRATCH assignments remain source-owned with their affected
slots; they are not silently converted into USE/SAVE. Invalid INFLOWS/OUTFLOWS
mode combinations are errors. Unknown directives remain visible in the source
and support report. Preserved source does not mean validated runnable input.

## External identity and units

Attaching a USE binding registers external dependencies with the ordinary
record store. Relevant additions, deletions, renames, reordering and subtype
changes are rejected before mutation. HOTSTART also protects coupled hydrology
state; RAINFALL protects gage configuration. RDII also protects its nodal
bindings and hydrograph configuration. HOTSTART/RUNOFF reject flow-unit
changes because relabeling the model does not convert binary data.

These guards survive copies, JSON reconstruction and scenario transactions.
They conservatively apply even if current options disable the consumer. SAVE
bindings do not have the same historical identity restriction. Numeric edits
that preserve the relevant layout remain possible; this does not establish that
an old state is physically appropriate for the edited model.

To deliberately rebuild or remap an external resource, remove the USE binding,
perform the model and external-data changes, then attach the verified resource.
There is no automatic remapping of binary state in this increment. Path rebasing
and explicit resolution use an internal permission for that operation only.

## Path bases and file inventory

`model.file_uses()` returns immutable `FileUse` declarations containing the
owning Ref, exact nested field path, FileReference, namespaced consumer role and
format, file/directory kind, access requirements, necessity and activation.
Currently this covers FILES, external time series, climate files, rain gage
files, temporary directories and optional GUI background images.

Most native paths are relative to the input file directory. **SWMM 5.2.4 RDII
interface paths are relative to the process working directory.** Import therefore
does not invent an INP-directory base for relative RDII paths. Bind that context:

```python
resolved = model.resolve_files(
    input_directory="D:/project", working_directory="D:/simulation-work",
)
resolved.to_inp("D:/relocated/network.inp")
```

Resolution returns an independent model with absolute references and performs
no filesystem access. An existing explicit base takes precedence over supplied
context. All references, including inactive ones, need a resolvable base for
this explicit operation. RDII export with a bound base writes an absolute path;
default rebasing of an unbound relative RDII reference is rejected. Explicit
`path_policy="preserve"` retains its literal process-relative meaning.

RAINFALL USE makes the original rain gage data files inactive; native SWMM reads
the cache instead. Other activation follows native rainfall/routing/RDII options
and required model objects. Qualified packaged RAINFALL/HOTSTART/RUNOFF inputs
require `read` access and open with `rb`. External libraries may have
different I/O behavior; a reported engine version alone does not establish these
patches. [RAIN](2.0-native-io.md) and [RUNOFF](2.0-native-io.md) boundary
guides describe cache checks and error handling.

## Read-only preflight

```python
from easysewer.runtime import check_files

checked = check_files(resolved, overwrite=False, max_bytes=64 * 1024 * 1024)
checked.report.raise_for_errors()
for check in checked.checks:
    print(check.use.role, check.resolved_path, check.inspection)
```

Preflight checks resolution, host path flavor, existence, expected resource
kind, accessible inputs, output overwrite policy and writable parent paths.
It rejects output/input and output/output aliases, including existing hardlinks
and resolvable inactive inputs. It does not create directories, open output
files, run SWMM or import native libraries. Required failures are errors;
optional resources and incomplete checks have visible warnings.

`report.is_valid` means no implemented check found an error. `complete` also
requires no warnings and complete format validation for active required input
files. A file over the explicit byte budget is `limited`, not validated.
`inspect_data=False` leaves input format checks incomplete. Model validation,
backend compatibility, runtime output ownership and input capture are handled
separately by Runner; calling this read-only preflight alone cannot prevent files
changing afterward. Host access checks are
not a guarantee that a later write or native open will succeed.

| Input format | Inspection in this increment |
| --- | --- |
| Routing/RDII text | Header, frame dimensions, ordered node labels, shared frame times, finite data, chronology and native buffer limits; RDII FLOW-only/node checks |
| RUNOFF binary | Complete stored samples, counts/units and exact sizes; `state_checked` without identity evidence, `validated` with an explicit matching manifest and understood target |
| RAINFALL binary | Station headers, offsets, intervals, finite/increasing samples, required station matches and nonempty data |
| RDII binary | Complete flows, sparse/dry frames, native time, node-index bounds and nodal bindings; `state_checked` without identity evidence, `validated` with an explicit matching manifest and understood target |
| HOTSTART binary | Version 1–4 complete stored state, exact length and finite values under known layout; `state_checked` without identity evidence, `validated` with an explicit matching manifest; unstructured target dependencies remain partial |
| External time series | Data grammar, temporal order, native buffers and declared rainfall consumers; mixed relative/calendar anchors have a warning |
| User-prepared rainfall | Station and record-date selection, chronological minute data, form/units context, nonnegative selected values and float range |
| Climate | USER_PREPARED/GHCND/TD3200/DLY0204 syntax, units/flags, actual starting month, missing/defaulted days and consumed physical values |
| Historical NWS/Canadian rainfall data | Eight formats, native date filters/intervals/flags/accumulations, nonempty cache and saved chronology; missing data and ambiguous states remain diagnosed |
| GUI background image | Optional resource; image format verification pending |

## Editable routing/RDII text

`easysewer.io.routing` provides `RoutingInterface`, `InterfaceConstituent` and
`InterfaceFrame`. They represent the documented text format in manual section
11.7, printed pages 196–200: FLOW with one of six flow units, optional named
quality constituents, node IDs, reporting step and frames of constituent values.

`RoutingInterface.read(path, encoding=...)` retains untouched bytes.
`dataclasses.replace(document, ...)` creates an edited value that writes a
canonical representation; `write()` atomically replaces a file after encoding.
Collections are immutable tuples, times are local whole-second datetimes, and
all node rows in a frame must share a timestamp and match header order. These
checks preserve the positional layout; qualified routing builds also validate
ASCII case-insensitive row identities. Use an explicit BOM-free ASCII-compatible encoding. Input buffers
must be immutable bytes; embedded CR cannot masquerade as a native newline.

## Extensions and evidence

Feature codecs may declare a `file_uses(store, profile)` hook. The framework
checks existing owners, exact field addresses and duplicate declarations.
Undeclared nested FileReferences remain visible as `core:undeclared` consumers
with unknown formats. `check_files(..., inspectors={format: callable})` accepts
explicit trusted inspectors returning `InterfaceInspection`. Codecs can also
register mutation guards; they run before graph changes and persist in clones.
This mechanism lets future domains add file consumers without changing Model.

`check_files(..., checkpoint=callback)` accepts a trusted no-argument work
check. Runner supplies its cancellation/deadline check automatically. File reads
use bounded chunks; built-in text, binary and document-validation loops poll
between work batches. An interrupted inspection does not return a partial
`FilePreflight` as if it had completed. Checkpoint exceptions preserve their
identity and exception chain instead of becoming file/format diagnostics.
The scope is local to the current execution context and is restored on exit.

Custom inspectors retain their existing keyword arguments and are checked
before and after invocation. Arbitrary custom code and a blocking filesystem
call cannot be forcibly interrupted by these cooperative checks. Text decoding,
sorting and other individual built-in operations also finish before the next
check; this API does not promise a hard real-time latency ceiling.

Inspectors can declare `InterfaceInspection.required_capabilities` for valid
formats requiring particular execution support. `check_files` accepts explicit
`backend_capabilities`; unknown facts leave requirements pending and missing
declared capabilities are errors. Runner supplies its qualified backend probe.
See [routing I/O](2.0-native-io.md) for zero-pollutant target support and the
native mapping, interpolation, ownership and error contracts.

Tests cover all ten documented kind/mode combinations, last assignments,
transaction rollback, source-free JSON, extension consumers/guards, path
relocation, aliases, malformed/truncated data and atomic write failures.
Seven fixed-engine integration tests generate and reuse HOTSTART, RUNOFF,
RAINFALL, RDII and OUTFLOWS/INFLOWS artifacts. They compare native results with
independent literal FILES directives and prove the RDII working-directory rule
in an isolated process. Structured [RDII](2.0-rdii.md) now supports seasonal
hydrographs, JSON/scenarios and unit conversion; additional native tests verify
binary production, edits, reuse and explicit identity evidence.
A one/two-pollutant hotstart fixture also checks the reader's expected byte
layout. The bundled binary does not reproduce the excess buildup-state write
suggested by the official tag's `saveRunoff` source. Matching version numbers do
not establish identical native builds; artifact provenance remains a release gate.
