# Candidate 2.0 rainfall-dependent inflows

`easysewer.model.rdii` provides seasonal HYDROGRAPHS and nodal RDII records for `Model`.

Runner's [RDII condition policy](2.0-cache-conditions.md) separately compares
rainfall/RTK/abstraction/area conditions and antecedent start/coverage. A binary
cache can match a shorter run with the same start. A later start retains a
different antecedent history and needs an explicit decision to freeze it; a dry
header-only cache does not establish unlimited future coverage.

```python
from easysewer.model import Model, Ref
from easysewer.model.rdii import UnitHydrograph, HydrographResponse, RdiiInflow

model = Model.from_inp("network.inp", strict=True)
model.hydrographs.add(UnitHydrograph(
    id="Seasonal", rain_gage=Ref(collection="swmm:raingages", key="Rain"),
    responses=(
        HydrographResponse(month="ALL", response="SHORT", fraction=.15,
            time_to_peak=1, recession_ratio=2,
            maximum_abstraction=.1, recovery_rate=.2, initial_abstraction=.025),
        HydrographResponse(month="FEB", response="SHORT", fraction=.2,
            time_to_peak=.5, recession_ratio=1),
    ),
))
model.rdii.add(RdiiInflow(node=Ref(collection="swmm:nodes", key="J"),
    hydrograph=Ref(collection="swmm:hydrographs", key="Seasonal"), sewer_area=2))
model.validate(for_run=True).raise_for_errors()
model.to_inp("with-rdii.inp")
```

The example requires an existing rain gage `Rain` and receiving node `J`.
`model.hydrographs` is keyed by group ID; `model.rdii` by its receiving node.
References participate in rename, dependency checks, deletion guards, copies,
transactions, source-free Model JSON and scenario patches. The three new JSON
type tags are `swmm:rdii.group`, `swmm:rdii.response` and `swmm:rdii.inflow`.

## Seasonal assignment semantics

Each group keeps an **ordered tuple of assignments**. An assignment selects
ALL or one of JAN through DEC, and SHORT, MEDIUM or LONG. ALL assigns that
component to all twelve months. A later row replaces only its selected
month/component; a later ALL also replaces earlier month-specific assignments
for that component. It does not clear either of the other two components.
Missing components produce no RDII. `group.for_month(1)` returns the effective
SHORT/MEDIUM/LONG records or `None`, preserving their original month labels.

Both modern per-component rows and the old three-R/T/K-triple row are read.
The legacy optional initial-abstraction triple applies to all three responses.
An untouched source keeps its original syntax and comments; normalization or
editing writes ordered modern rows. Optional trailing IA fields remain absent
when represented by `None`. If a later optional value is present, INP requires
zero placeholders for earlier omitted values; reparsing those placeholders
produces explicit zeros with the same native meaning.

Native months use their first three letters, while response keywords match
their full prefix. Accepted noncanonical spellings receive diagnostics and
normalize to canonical names. Ignored trailing columns are diagnosed. Repeated
nodal assignments retain their last value; original source references are also
checked before running preserved input, and normalization removes replaced
nodal assignments. Malformed input keeps the entire
affected group's original records unclaimed and invalid; export will not
silently emit a partially parsed group.

Rain-gage assignments have an additional native effect: **every assigned gage
is activated**, even if a later row supplies a different gage to this group.
Controls can observe rainfall from an earlier gage. `rain_gage` is the final
RDII source, while `prior_rain_gages` retains the ordered earlier references.
They remain graph dependencies and survive normalization and source-free JSON.
Removing those earlier declarations can change hydraulic results; native tests
demonstrate this difference. To remove them deliberately, explicitly update
`prior_rain_gages=()`. Nonempty prior assignments require a final gage.

## Dimensions and validation

| Field | Meaning and units |
| --- | --- |
| `fraction` | Fraction of rainfall entering this response |
| `time_to_peak` | Hours from onset to peak |
| `recession_ratio` | Recession time divided by time to peak |
| `maximum_abstraction` | Maximum initial abstraction, inches or mm |
| `recovery_rate` | Abstraction recovery, inches/day or mm/day |
| `initial_abstraction` | Abstraction already used at the start, inches or mm |
| `sewer_area` | Contributing sewer area, acres or hectares |

`convert_units()` converts the three IA depths/rates and sewer area, as well
as the rain gage's ordinary data dependencies. It preserves R/T/K. External
rainfall still requires its existing explicit data-conversion workflow.

The native engine truncates peak and base durations to whole seconds; base is
`T * (1 + K) * 3600`. The candidate exposes these values as
`native_peak_seconds` and `native_base_seconds`, warns on truncation and on a
positive fraction whose base becomes zero, and rejects signed-long overflow.
For each month's active components the native accepted ratio sum is at most
1.01; sums above one within that tolerance warn. Initial abstraction already
used above its maximum also warns and is retained, without silently clamping.

Local field validation rejects nonfinite/negative parameters and invalid
types. As elsewhere in Model, ordinary editing may create an invalid draft;
validation/export and validated transaction completion enforce the checks.
Generating RDII requires each used group's rain gage. USE RDII or disabled
rainfall/RDII suppresses that generation-only requirement. Local data and
reference integrity checks still apply.

An attached USE RDII dependency protects node identity/order, nodal bindings
and hydrograph configuration. This conservatively includes area/response edits
and unit conversion that would edit them. Detach the binding before deliberate
changes, then attach a resource whose provenance and intended reuse have been
established. A SAVE binding does not carry this historical restriction.

## Validation and limits

The basis is the local SWMM 5.2 manual, printed pages 397–399 (RDII and
HYDROGRAPHS), and official v5.2.4
[rdii.c](https://github.com/USEPA/Stormwater-Management-Model/blob/v5.2.4/src/solver/rdii.c).
Pure tests cover all months/components and optional IA tails. Native tests
exercise cross-month responses, legacy rows, ALL ordering, initial abstraction,
US/SI conversion, JSON/scenario edits, earlier gage activation in controls and
actual changes to hydraulic results.

Binary and text resource behavior is documented in
[runoff caches](2.0-runoff-cache.md) and [interface files](2.0-files.md).
The [native RDII boundary](2.0-native-io.md) describes checked frame reads,
generation arithmetic, write/close errors and explicit rain-gage binding.
The binary cache contains flows, not the hydrograph parameters that produced
them. Backend/Runner production-condition evidence is described in
[cache conditions](2.0-cache-conditions.md). Hydrologic checkpointing has its
own qualified scope. The [joint RDII extension acceptance](2.0-architecture.md)
now covers shared groups, ordered monthly overrides, real output oracles and
fresh-parent continuation across a month boundary on three installed environments.
Final release gates remain tracked in [architecture acceptance](2.0-architecture.md).
