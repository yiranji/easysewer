# Native file I/O contracts

This guide collects input-format rules, file ownership and failure behavior. Length limits differ by format; do not apply INP limits to climate or rainfall files. Current library identity is established by packaged build records and runtime capability probing.

See [resource management](2.0-resource-management.md) for publication and recovery, and [testing](2.0-testing.md) for verification methods.

## Climate streams and calendar advancement

Standard revision 12 and custom native I/O revision 10 include climate I/O revision
1. Both export `swmm_getEasySewerClimateIO() == 1` and record `climate_io: 1`
in their build records. Qualified binary hashes advertise
`easysewer:climate-io:1`; an engine version, exported marker or caller-provided
digest does not establish this capability for an unknown library. Custom ABI
201 and FlexiblePonding policy 2 are unchanged.

### Climate records

USER_PREPARED, TD3200, DLY0204 and GHCND records use bounded physical lines and
complete-file validation, including rows beyond the simulation window. LF,
CRLF and a complete final record without a newline are accepted. Content is
limited to 1022 bytes per physical line, excluding its terminator. USER station
identifiers may exceed the old 79-byte buffer boundary within that line limit.
NUL, DOS EOF markers, embedded CR, malformed fields, nonfinite values, invalid
dates and backwards month order are rejected before use.

The reader retains the original missing-value and conversion rules. Within a
month, days may repeat or be interleaved; the later nonmissing observation wins
for each day and variable. Different stations feed the same daily slots. Missing
days carry the previous value forward. Initialization does not backfill from days
before the requested start: temperature starts at 70 F, evaporation and wind at
zero. The requested start month must exist, although a valid zero-record monthly
row can establish that month. USER wind remains mph in SI projects, reflecting
the pinned native implementation rather than changing existing results.

Opening, reading, seeking and closing are checked. A clean EOF retains the last
available observations; a read failure stops calculation instead of retrying
forever. Repeated start/end on an open project resets or reopens the stream.
Owned handles are cleared when closed, including error paths and repeated close.
An existing engine error remains primary if cleanup also fails.

| Error | Meaning |
| --- | --- |
| 337 | Climate file could not be opened |
| 338 | Invalid climate record, read/seek/close failure or mapped file calendar overflow |
| 339 | Requested climate start month is absent |
| 361 | A climate consumer's external time-series stream could not be opened |
| 363 | A climate consumer's external time-series read/seek/close failed |

### Time-series and date state

Temperature and evaporation each own their traversal state and, for external
time series, a separate read-only stream. They borrow immutable inline entries
from the project. Sharing a series between these consumers therefore does not
advance the other consumer's cursor. Evaporation consumes every crossed event,
holds the last rate at EOF and applies the monthly adjustment once to the
unadjusted rate. The first entry remains the default before the series begins.

Climate advancement visits each intervening day, preserving previous maximum
temperature and the seven-day temperature average across large time steps,
month boundaries and leap days. Simulation dates and mapped file dates remain
separate. Nonfinite, backwards and out-of-calendar state requests stop with an
error. `datetime_timeDiff` retains its C `long` ABI, checks conversion bounds and
saturates intervals outside that type's range. Nonfinite inputs and `NO_DATE`
have no event interval; runoff event selection explicitly skips that sentinel.

### Python and Runner

`ClimateData` can preserve complete records without a final newline and long
USER station identifiers. `check_files(model)` parses the data without loading
a native library. A climate file also requires `easysewer:climate-io:1`: an
unknown capability set leaves execution qualification pending, an explicit set
without it is unsupported, and a qualified backend can proceed. Runner supplies
the probed backend capabilities and publishes only after successful completion
and cleanup. A failed replacement run preserves previously published artifacts.

This does not certify every external time-series consumer. The general native
table parser, mixed relative/calendar-date rewind semantics and non-climate
consumers remain separate work. Python's external time-series token bounds and
mixed-date diagnostics remain in place. Complete hydrologic checkpoints, RPT
text-write checks and the final distribution/platform matrix are also separate
release gates.

## Checked LID detailed reports

Installed standard revision 12 and custom native I/O revision 10 check the
separate detailed report streams selected by LID_USAGE. This complements the
[main RPT checks](2.0-native-io.md). It does not change simulation equations or
add complete checkpoint/resume support.

The libraries export `swmm_getEasySewerLidReportIO() == 1`; their adjacent build
records contain `lid_report_io: 1`. Only qualified binary hashes receive the
`easysewer:lid-report-io:1` backend capability. Reporting the same SWMM version,
ABI, or exported marker does not qualify an arbitrary external library.

Callers may require this evidence with
`RunConfig(required_capabilities=('easysewer:lid-report-io:1',), ...)`. Runner
rejects a backend without the capability before changing published reports.

### Failure and cleanup behavior

All nine header and three result write sites check formatting and stream errors.
Negative formatting returns and truncated intermediate rows are errors. Pending
streams are flushed at existing public report boundaries using a dirty queue;
unchanged boundaries do not scan every deployed LID. Close detaches and releases
each stream once, including after incomplete project initialization.

A report write, flush, or close failure reports error 306 and the detailed report
path. An earlier native failure remains primary; cleanup failures are retained
separately. Repeated close is safe. A new project resets failure state only after
the existing owner has been closed. The dry-period counter saturates at two,
preserving the existing zero/one/multiple-period behavior without integer overflow.

Failed LID object allocation stops project initialization before input parsing.
Cleanup also tolerates a subcatchment whose land-factor array was never allocated.
Allocation/open errors retain the native 101/200 behavior appropriate to their
stage. These checks prevent errors being overwritten and partial cleanup crashing.

Direct native calls retain native file semantics and can leave partial reports.
Runner stages execution privately; a failed run does not replace existing
published or external detailed reports. Retained failed artifacts are explicitly
incomplete and do not constitute a successful result.

## 2.0 RAIN native I/O

Current packaged standard revision 16 and custom native I/O revision 14
retain the checked RAIN implementation. Earlier documented defaults were
standard revision 12 and custom native I/O revision 10;
see [current backend identities](2.0-backend.md). The custom accounting ABI remains 201 and its physical
policy remains `easysewer:flexible-ponding:incremental-volume:2`. Capability
claims require known binary hashes, independently qualified for each family.

### Format and inspection

The pinned native format contains a 10-byte `SWMM5-RAIN` stamp, a signed
32-bit station count, then 1037 bytes per station: 1025 bytes for a NUL-terminated
station ID and three signed 32-bit integers (interval, start offset, end offset).
Each payload record is a native 8-byte DateTime followed by a 4-byte float.
These widths and byte order describe the qualified little-endian x86_64 builds;
the format is not a portable serialization standard.

Both Python preflight and direct native loading check actual file/table sizes,
signed offset capacity, nonempty terminated IDs, positive intervals, ranges,
12-byte alignment within each range, native calendar limits, finite values and
strictly increasing dates. Required stations must exist and contain samples.
The first physical row wins for duplicate case-sensitive station IDs, matching
the pinned engine's lookup behavior. Unselected station ranges are checked too.
Gaps and adjacent stations with independent calendars are allowed. Shared and
overlapping aligned spans are merged for validation; this avoids checking the
same samples once for every duplicate header. No arbitrary station-count limit
is imposed. Finite negative values retain the native missing-data meaning.

Python preflight remains read-only and honors its byte budget. A successful
inspection is not a guarantee against later filesystem failures. Native runtime
reads check their own seek, read, tell, date and station-range boundaries.

### Read, write and failure behavior

RAIN USE opens `rb`; the original gage files are inactive. SAVE checks all header,
payload and backpatch writes, seeks, tells, flush and close. Station-name padding
is zero-filled, so regenerated cache bytes can differ from older uninitialized
padding without changing rainfall samples. A failed new SAVE or scratch cache
is closed and removed. Runner publishes a produced cache only on success and
preserves preexisting user outputs on failure.

| Error | Meaning |
| --- | --- |
| 318 | Existing rainfall sequence error |
| 319 | Invalid external rainfall format/data |
| 320 | Invalid RAIN binary structure or samples |
| 321 | Required station missing or empty |
| 322 | Native rainfall read/seek/tell/close failure |
| 324 | Native RAIN write/seek/tell/flush/close failure |

A later cleanup failure preserves the earlier primary error. Historical text
readers also check short fixed-field lines, online offsets, numeric conversions,
calendar/clock arithmetic and accumulated-period counters. Legacy ignored lines
remain ignored where the pinned format parser permits them; these changes do
not turn every unrecognized text line into a fatal error.

## Native RDII input and output

Current packaged standard revision 16 and custom native I/O revision 14
share RDII I/O revision 1; see [backend identities](2.0-backend.md).
Earlier documented defaults were standard revision 12 and custom native I/O
revision 10. The checks below retain their original qualification scope.
Both current families export
`swmm_getEasySewerRdiiIO() == 1`. Backend advertises `easysewer:rdii-io:1`
only for the qualified binary hashes; an external library's symbol or engine
version does not establish this capability.

### Reading interfaces

Binary `SWMM5-RDII` files retain the native layout: a ten-byte signature,
positive int32 step and node count, native int32 node indices, then sparse
float64 calendar dates with one float32 flow per listed node. Flows remain
internal CFS in every project unit system. Indices must be unique, in range
and bound to RDII nodes. Header-only dry caches are valid.

Text interfaces require one FLOW constituent, a supported flow unit, known
unique node names and complete eight-field data rows. Each row's node name
must match its position in the declared node list, and all rows in a frame
must have the same valid date. Text names can target nodes without an RDII
generation binding. Conversion uses the pinned solver's Qcf constants,
including `0.02832` for CMS. Binary files never apply this conversion.

The reader checks the whole file before returning a flow frame to routing,
including records beyond the simulation window. It distinguishes clean EOF
from a partial date or partial flow vector. It rejects nonfinite dates/flows,
invalid calendar bounds, duplicate or overlapping intervals, partial frames,
embedded NULs, overlong text lines and incorrect row labels. Sparse dry gaps
are allowed. Adjacent timestamps use the portable reader's `1e-9` day
tolerance for floating-point calendar rounding.

Runtime reads also validate into a pending vector and publish it only after
the entire frame is valid. USE files open read-only. Failure cleanup releases
arrays and file handles, and repeated close is safe. Complete preflight adds
one file scan and uses memory proportional to the number of listed nodes.
It does not establish production provenance or protect direct native callers
from another process modifying the input concurrently.

### Producing interfaces

All header, index, date and flow writes, plus the final close, are checked.
Existing primary errors remain primary. Generated flows must be finite and
representable as float32. A used hydrograph must explicitly name a rain gage
when generating RDII; it no longer silently inherits the first gage through
zero initialization. This generation requirement does not apply to USE RDII.
Unbound unused groups are safe to retain.

Modern and legacy RTK rows are checked before native integer conversion.
The legacy parser calls the setter after all three R/T/K fields are assigned.
Duration and allocation arithmetic is bounded, and the dry-event counter
uses a bounded int64 duration. Ordinary convolution equations and integration
order are unchanged.

| Native error | Meaning |
| --- | --- |
| 154 | A used RDII hydrograph has no valid rain gage for generation |
| 345 | Invalid RDII header, node mapping or frame |
| 346 | RDII write/close failure or unrepresentable generated flow |
| 347 | RDII read, position or input-close failure |

Native cleanup removes only engine-owned scratch paths. A failed direct SAVE
may leave a partial file at the caller's path. Runner's existing staging and
publication workflow keeps failed output from becoming a published cache.
Neither native cleanup nor Runner should delete an arbitrary caller-owned
SAVE path as a substitute for that publication workflow.

## Checked native RPT output

The shared native report patch checks all 503 formatted RPT write sites in the
fixed standard and FlexiblePonding source trees, together with buffered flush
and close. It does not change report formatting or simulation equations.

The separate LID detailed streams have their own
[checked I/O capability](2.0-native-io.md).

### Errors and visible output

- Failure to open the report keeps code 305.
- A formatted write, stream error bit, flush or close failure reports code 306
  (`error writing to report file`). Reporting that error does not recursively
  write to the damaged stream.
- An error present before report I/O fails remains the primary error. A report
  failure during cleanup is returned separately by close, allowing Session and
  Runner to retain cleanup diagnostics.
- Once report I/O is the primary error, later diagnostic writes cannot replace
  it. Opening a new project after close resets the report failure state.
- Successful open/start/step/stride/end/report boundaries flush pending report
  text. `swmm_writeLine` also flushes caller text; it has a void C signature, so
  direct callers query `swmm_getError` for its error status. Custom routing and
  save-results entry points check the report as well.

The initial banner is flushed before input parsing or opening simulation output.
A report failure there leaves a preexisting caller OUT untouched. Direct native
calls otherwise retain their native file semantics; Runner provides private
execution and controlled publication of complete artifacts.

### Project ownership

`swmm_open` and the one-shot `swmm_run` reject an already owned project with code
503, preserving an earlier primary error when present. The existing session must
be closed first. Rejection does not reset its lifecycle flags, close its streams
or truncate the proposed report destination.

Project cleanup clears freed hash-table pointers and the memory-pool ownership
flag. Control cleanup tolerates absent arrays and clears its expression/variable
counts. This matters when a normal project is followed by an early RPT failure:
the second project may close before its input objects have been allocated.
Report close releases its stream once; repeated close does not repeat a failed
stream operation.

Callers can require this qualification with
`RunConfig(required_capabilities=('easysewer:report-io:1',), ...)`. Runner uses
the probed backend capabilities and rejects a missing requirement before creating
execution artifacts or replacing existing outputs. A caller-supplied library
hash pins executable bytes; it does not grant this qualification by itself.

## Native routing interface input and output

Routing I/O revision 1 is included in current packaged standard revision 16 and
custom native I/O revision 14; see [backend identities](2.0-backend.md).
The earlier documented standard revision 7 and custom native I/O revision 5
also carry this interface revision.
Both current families export `swmm_getEasySewerRoutingIO() == 1` and record
`routing_io: 1`. Only qualified binary hashes advertise
`easysewer:routing-io:1`; a symbol, version number or caller-pinned unknown
digest does not establish that capability. The custom ABI remains 201.

The format follows SWMM 5.2 manual sections 11.7.3–11.7.5, printed pages
198–200. It has one FLOW column, optional named concentration columns, a
declared node list and complete timestamped frames. Nodes and pollutants
are matched by ASCII case-insensitive identity. Unknown nodes and columns
are ignored by routing; missing target pollutants receive zero interface
concentration. A matched pollutant must have matching concentration units.
All header rows are consumed even when the target has zero pollutants.

The native reader checks the entire input before opening SAVE OUTFLOWS,
including records beyond the simulation window. It checks physical line
bounds, complete headers and rows, unique names, valid calendars, matching
row labels, consistent frame timestamps, strict chronology and finite
values. USE is read-only. A complete last line needs no newline. Trailing
blank lines are accepted; an interior blank or partial frame is invalid.
The format requires at least one node and one complete frame for USE;
SAVE with no outlet nodes reports 353 before opening its output path.

Flows use the pinned solver's six Qcf unit conversions. All flows must
remain finite in internal CFS. Consumed flow in internal and target units,
and consumed concentrations, must fit float32 results. Finite ignored data
does not acquire those consumed-result limits. Negative flow is retained.
Interpolation is linear between recorded points, including irregular gaps;
there is no extrapolation before the first or after the final point.
The reporting step does not make a frame a constant-flow RDII interval.

Runtime reads use a pending matrix: no row reaches interpolation until the
whole frame passes. All matrices are fully initialized and the initial
old/new frames both hold the first recorded sample. Dimension products are
checked before allocation. Memory scales with node and constituent counts,
and preflight adds one complete input scan. This is not a guarantee against
concurrent input modification by a separate process.

Reads, seeks, writes and closes propagate errors, preserving an existing
primary failure. Input/output identity is checked before truncation,
including hard-link aliases. Native SAVE retains the original text layout
and checks finite output values and line bounds. A failed direct SAVE can
leave partial caller-owned output; it never deletes that path. Runner uses
its existing staged publication transaction.

| Error | Meaning |
| --- | --- |
| 351 | Cannot open routing input/output |
| 352 | Input read, position or close failure |
| 353 | Invalid format/frame or no outlet for SAVE |
| 354 | Output formatting, write or close failure |
| 355 | Matched pollutant concentration units differ |
| 357 | Input and output refer to the same file |

### Portable inspection and execution requirements

`RoutingInterface` remains editable without a native library. Row identity
is case-insensitive and unchanged bytes remain preserved. Format inspection
returns `InterfaceInspection.required_capabilities`. A pollutant-bearing
INFLOWS file targeting a zero-pollutant model requires
`easysewer:routing-io:1`, because the uncorrected engine cannot consume its
header. This requirement describes execution, not a malformed file.

`check_files(..., backend_capabilities=None)` leaves such requirements
pending. Explicit capabilities that omit a requirement produce an error;
matching capabilities permit execution validation. Caller-supplied facts
are assertions, not native discovery. Runner supplies its backend probe,
including digest-based capability qualification. The same gate applies to
explicit custom inspectors. Inspection never loads a native library.

`RunConfig.required_capabilities` accepts exact versioned IDs such as
`easysewer:routing-io:1`; version 2 does not implicitly satisfy version 1.
This does not change collection-key syntax or domain-registry capabilities.

## Candidate 2.0 RUNOFF native I/O

Current packaged standard revision 16 and custom native I/O revision 14 share
the checked RUNOFF lifecycle; see [backend identities](2.0-backend.md).
Earlier documented defaults were standard revision 12 and custom native I/O
revision 10. The checks below retain their original qualification scope.
Custom ABI 201 and its ponding/accounting policy remain unchanged. Build records
pin the source, shared recipe and platform binary bytes; arbitrary external
libraries do not gain these capabilities from an engine version alone.

### Binary contract

RUNOFF has a 12-byte `SWMM5-RUNOFF` stamp and four signed 32-bit integers:
subcatchment count, pollutant count, flow-unit flag and frame count. The header
is 28 bytes. Each frame contains one float32 time step in seconds, followed by
eight hydrologic float32 values and one float32 per pollutant for each
subcatchment, in native object order and project units. The frame count is
backpatched at byte 24 when SAVE closes. Qualified builds are little-endian
x86_64; this is not a platform-neutral file standard.

Startup checks the full header, matching model counts/units, positive frame
count and exact payload length before allocating one frame. Checked arithmetic
prevents count/size overflow. Every declared frame is checked for finite values,
a positive time step and advancement of the native double-precision millisecond
clock, including frames beyond the consumer's requested duration. Finite
negative hydrologic values are retained; this is a format check, not a new
physical constraint. No arbitrary step or frame-count ceiling is added.

File positions use 64-bit seek/tell APIs on both platforms. Unlike RAIN offsets,
RUNOFF file positions are not stored as signed 32-bit values in the format.
The current qualification does not claim a multi-gigabyte workload benchmark.

### Runtime and failure handling

USE opens `rb`. Each complete frame is read into a buffer and validated before
changing any subcatchment state or its runoff clock. A short read, nonfinite
payload or nonadvancing step therefore cannot partially apply a frame. The final
frame also checks for trailing bytes. Requesting another frame after the
declared count returns 327; it does not perform an extra EOF read.

SAVE checks header/payload writes, count backpatch, seek/tell, flush and close.
Errors close and clear the handle, free the frame buffer and remove a failed
new SAVE file. An existing primary simulation error is retained. A startup
failure returns before opening later HOTSTART files. Runner's separate output
transaction preserves old user artifacts and publishes no produced cache on
failure.

| Error | Meaning |
| --- | --- |
| 323 | Cannot open the RUNOFF file |
| 325 | Incompatible header, frame structure, values or clock |
| 326 | RUNOFF write, backpatch, seek/tell, flush or close failure |
| 327 | The declared frames end before the consumer's run |
| 329 | RUNOFF read, seek/tell or close failure |

Direct-C tests bypass Python preflight and cover malformed files, readonly
reuse, six flow units, multiple pollutants and partial startup cleanup. Linux
fault injection exercises actual C I/O and Runner workers, including partial
and corrupted runtime reads with unchanged runoff state. Both source families
have independent sanitizer and new/old cache-byte and OUT comparisons.

## Solver OUT I/O

Solver OUT I/O revision 1 is included in current packaged standard revision 16
and custom native I/O revision 14; see [backend identities](2.0-backend.md).
The earlier documented standard revision 9 and custom native I/O revision 7
also carry this interface revision.
Both current families export `swmm_getEasySewerSolverOutputIO() == 1` and record
`solver_output_io: 1` in their build records. Qualified binary hashes advertise
`easysewer:solver-output-io:1`. A caller-provided digest, engine version or
exported marker alone does not grant this capability to an unknown library.
Custom ABI 201 and FlexiblePonding policy 2 are unchanged.

This boundary is the solver's writer and its internal saved-value/report
reader. The separate SMO output library has its own
`swmm_getEasySewerOutputIO()` marker and [reader contract](2.0-output.md).

### Writes and completion

The solver checks header, property, time-step and footer writes, seeks, tells,
flushes and closing the OUT stream. It rejects nonfinite float properties and
results, invalid saved dates, overflowing record dimensions and period counts.
Result positions use checked 64-bit arithmetic. The three metadata offsets in
the fixed SWMM footer remain signed 32-bit fields; oversized metadata is
rejected rather than silently narrowed. Each result write explicitly seeks its
expected position, so an earlier read cannot determine where it appends.

Errors use the native codes 308 (size limit), 309 (write/seek/flush/close) and
311 (result read). Failed allocation retains native error 101. A partial frame
does not increment the period count or receive a success footer. End flushes
the stream; close releases it exactly once and propagates a close error.
Calling close on a started model also performs checked completion. A secondary
close error does not overwrite the engine's first error. Python diagnostics
identify when the returned close code differs from that retained error.

A direct C caller still owns a named output file and must check every return
code, including close. A late flush/close failure can leave a syntactically
valid file; parsing it does not establish successful completion. Scratch output
is removed on close. Runner publishes staged results only after end, report
and close succeed, preserving an existing publication when these calls fail.

### Reads and lifecycle

Report and saved-value reads check seeks, complete item counts, finite values,
periods and object indexes before dereferencing model arrays. Failed result
reads clear result buffers; report generation stops before formatting missing
dates or stale values. System results following a link are read from the
position after all reported links.

`swmm_report()` rejects a closed project (501), a project without output (502)
and a simulation still in progress (503). Saved-value queries retain the
existing zero-return convention for unavailable stages and invalid indexes.
An actual failed read sets the engine error, available through `swmm_getError`.
Starting again after end releases old result buffers before allocating new
ones. Average reporting handles empty node/link selections without relying on
the platform's `calloc(0, ...)` behavior.

## 2.0 native time-series I/O

Standard revision 10 and FlexiblePonding native-I/O revision 8 introduced time-series
I/O revision 1. The current revisions 11/9 retain it and add [checked RPT output](2.0-native-io.md).
Both export `swmm_getEasySewerTimeSeriesIO() == 1`. Runtime grants
`easysewer:timeseries-io:1` only to the qualified binary hashes. User libraries
retain their executable-code trust boundary; supplying an expected digest or
reporting SWMM 5.2.4 does not prove these corrections are present.

### File grammar and calendar

External `[TIMESERIES] ... FILE` records support `time value` or
`month/day/year time value`, one value per physical row. Three-letter month
names are also accepted. Time can be decimal elapsed hours or `HH:MM[:SS]`,
including hours greater than 24; negative elapsed times use decimal hours.
Fractional clock seconds retain native truncation, with a Python diagnostic.
Numeric values must be finite ASCII decimal numbers; hexadecimal values,
nonfinite values and trailing numeric junk are rejected.

Rows are bounded to 1,022 bytes excluding LF or CRLF. A complete final row needs
no newline. Blank rows and semicolon comment rows are recognized before token
parsing. Long numeric fields and comments within the row boundary are supported.
NUL, SUB and embedded CR are rejected. Columns after date/time/value retain
the existing ignored-column behavior; a third token on a time/value row instead
selects dated-row grammar and is not an inline comment.

Before an explicit date, elapsed times use the full model start, including its
time of day. After one, omitted dates continue the recorded day. Rewinding resets
the initial anchor, so validation and simulation agree for mixed files. Effective
timestamps must fall within years 1–9999 and strictly increase. Files are scanned
through EOF during native validation, including records after the run's end.

### Independent state and consumer behavior

Sequential iteration and interpolation have separate cursors. An interpolation
query may move backwards, including after a previous query reached EOF, without
changing another sequential consumer's position. Inline series retain one owned
entry list; lookup cursors borrow that immutable list. External cursors own
separate read-only streams. Climate temperature and evaporation retain separate
consumer state, even when they reference the same series.

Inflow, outfall stage, control-rule and external buildup interpolation preserve
the reference arithmetic for ordinary finite values. Exactly the final timestamp
returns its recorded value, including a one-point series. Outside the extent,
the caller's extend flag selects endpoint holding or zero. Opposite, individually
finite endpoint values use a weighted interpolation fallback if the ordinary
difference overflows.

Rain gages retain interval-based step holding rather than interpolation. The
existing restriction on sharing a rain series with other consumer types remains.
The engine is still serial and process-isolated; cursor separation does not make
native global state thread-safe.

### Errors and ownership

Allocation failure reports 101, opening an external series reports 361, and
malformed/read/seek/close failures report 363. Duplicate or decreasing validation
timestamps report 173. Closing releases each owned stream and cursor once,
without freeing borrowed inline entries. A cleanup error does not replace an
earlier primary error; Runner records both and does not publish partial results.

The checked parser and independent cursor changes apply to both pinned solver
families through the shared source recipe. The correction does not change public
Model record constructors or the existing solver ABI. Build provenance records
the shared recipe, prepared source hashes and `timeseries_io: 1`.

Verification includes independent calendar/cursor oracles, malformed late rows,
long fields, repeated sessions, shared consumers, injected allocation and file
failures, and comparisons with previous solver results. Linux native probes also
run with address, undefined-behavior, float-conversion and leak checks. Temporary
fixtures and detailed evidence remain outside the source repository.
