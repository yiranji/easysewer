# Pure Python distribution

The `pyodide` profile in `packaging_profile.json` describes modules for modelling,
INP/JSON, validation, pure result readers and archive inspection. It excludes
native libraries and execution workers. Importing the package and the 2.0
Model is supported. Private native adapters use explicit unavailable stubs and
raise `NativeCapabilityError`. The old public API modules are removed.
Pure OUT readers remain available through
`easysewer.io.output`. This profile does not supply a WebAssembly solver.

Build it from the source checkout or source distribution:

```text
python tools/build_pure.py --output dist/pure
```

The selected interpreter needs setuptools 77.0.3 or later and wheel. Use `--python PATH` for a
separate build interpreter. The output directory must not already exist. The
tool copies declared modules and replacement stubs into a temporary build,
checks the wheel inventory and native exclusions, and writes `pure-build.json`
with per-module provenance. It does not modify the native source package.

The native and pure distributions have the same package name and version. Install one variant in each environment; keep their artifacts in
separate directories. The pure wheel is tagged `py3-none-any`, contains no
bundled native libraries, and can be installed without fetching dependencies.

The PyPI release uses the native wheel and source distribution. Keep the pure
wheel for local or browser deployments: its filename is identical to the native
wheel's filename, so both cannot be uploaded as separate variants of one release.
