# Treatment expressions

The candidate `easysewer.model.Model` owns TREATMENT through a separate
`model.treatment` relation collection keyed by `(node_id, pollutant_id)`.
`Treatment(node, pollutant, kind, expression)` is immutable and keyword-only;
its two identities are Refs, `kind` is `C` or `R`, and `expression` is the shared
non-executing arithmetic AST. Nodes and pollutants need no new optional arrays.

```python
from easysewer.model import Ref
from easysewer.model.treatment import Treatment
from easysewer.io.inp.treatment import TreatmentExpressionCodec

# model already contains node Tank and pollutants TSS and Lead.
codec = TreatmentExpressionCodec()
model.treatment.add(Treatment(
    node=Ref(collection="swmm:nodes", key="Tank"),
    pollutant=Ref(collection="swmm:pollutants", key="TSS"),
    kind="C",
    expression=codec.parse("TSS * EXP(-.05 * HRT)", pollutants=model.pollutants),
))
model.treatment.add(Treatment(
    node=Ref(collection="swmm:nodes", key="Tank"),
    pollutant=Ref(collection="swmm:pollutants", key="Lead"),
    kind="R",
    expression=codec.parse(".2 * R_TSS", pollutants=model.pollutants),
))
```

The parser never evaluates Python code. It supports the shared signed-number and
right-associative power grammar, arithmetic operators and all 19 fixed native
functions. Concrete leaves are:

| Leaf | Meaning |
| --- | --- |
| `TreatmentProcessVariable(name)` | HRT, DT, FLOW, DEPTH or AREA |
| `TreatmentConcentration(pollutant=Ref(...))` | The referenced pollutant's concentration at this node |
| `TreatmentRemoval(pollutant=Ref(...))` | The referenced pollutant's computed fractional removal at this node |

Unknown arithmetic nodes/functions or treatment record variants require an
explicit feature adapter. They cannot silently pass through the writer or unit
conversion as if their additional semantics were understood.

## Native numerical meaning

`C` computes a target node concentration. The fixed native solver clamps it
between zero and the untreated mixed node concentration; treatment cannot create
additional pollutant. `R` computes fractional removal, clamped to 0–1, and applies
it to influent concentration, with the resulting node concentration also capped
at its untreated mixture. It skips ordinary removal treatment without inflow.
Zero concentration also short-circuits removal evaluation. Model retains the
supplied expression, including constants outside these ranges, and delegates the
calculation and clamping to the native engine.

Concentration leaves follow the treatment kind of the **referenced pollutant**,
which can differ from the owning formula's pollutant. A referenced pollutant
with C treatment supplies its untreated mixed node concentration; R treatment
supplies influent concentration. A pollutant without a treatment equation has
the default R context. The manual's general inlet-concentration wording does
not fully describe this source/binary behavior. Changing one pollutant's C/R
kind can therefore change another formula's meaning.

Removal leaves recursively evaluate the other pollutant's removal at the same
node. A pollutant with no treatment equation has zero removal and produces a
Model warning, not a missing-treatment reference error. Removing a treatment
record preserves those pollutant references and their new zero-removal meaning.
Removing the pollutant itself is protected by normal graph dependency checks.

Removal cycles are Model errors, including self-cycles and dependencies that
reach a cycle. Concentration references do not recurse and may be circular.
Validation checks the structural dependency graph even if a particular zero-flow
or zero-concentration simulation would skip evaluation. The bundled 52004 binary
did not report the tested mutual removal cycle; source also has an error-code
comparison inconsistent with the value assigned on recursion. Model validation
does not depend on the native engine catching that condition.

Pollutant collection order is semantically significant. At zero inflow, an
earlier R pollutant gets a cached zero removal, whereas an earlier C formula can
recursively evaluate a later R pollutant before the main loop skips it. The Model
preserves pollutant order in INP/JSON; `pollutants.move()` is an explicit change
and native tests demonstrate the changed history. Merely sorting formulas by
their dependencies would not preserve SWMM behavior.

Any treatment equation at a storage node suppresses that pollutant's ordinary
storage first-order decay. `R=0` and `C=Q0` therefore differ from no equation,
even when their explicit removal is zero. Native tests verify this distinction.

| Process variable | Fixed-engine quantity |
| --- | --- |
| HRT | Hydraulic residence time in hours; zero at non-storage nodes |
| DT | Current routing time step in seconds |
| FLOW | Inflow to the node in the project's flow units |
| DEPTH | Average old/new depth in ft or m |
| AREA | Average old/new surface area in ft² or m² |

HRT at a non-storage node produces a warning. The fixed engine returns zero for
`SGN(0)`, despite the manual listing +1 at that boundary; native arithmetic tests
cover it without substituting a Python evaluator.

## Names, source ownership and persistence

Native lookup first matches a complete process keyword prefix, then an exact
pollutant name, then `R_` followed by an exact pollutant name. Thus FLOWER means
FLOW even if a pollutant is named FLOWER, and an actual pollutant named R_TSS
takes precedence over the TSS removal variable. Function names are recognized
by the math lexer before variable lookup. Process aliases are diagnosed and
canonicalized on normalized/edited output.

Programmatic concentration/removal leaves must be representable in the ASCII
arithmetic identifier grammar and resolve to the intended leaf. A rename that
introduces a process/function/removal-name collision creates a validation error
and cannot be exported. Use a validating transaction when a coupled rename must
remain atomic. Ordinary pollutant IDs outside that grammar are still usable as
treatment targets with formulas that do not spell them as concentration leaves.

INP accepts compact `C=...`, spaced `C = ...`, quoted expression tokens and the
native first-character result prefixes. Repeated node/pollutant assignments use
the final equation; every row in the group must parse before ownership is
claimed. Untouched text retains original bytes and comments. Editing or explicit
normalization collapses repeated assignments and uses canonical C/R syntax.
Bad groups do not expose an earlier valid equation as a silently partial model.

Native preflight checks all source assignments, including overwritten references
to a pollutant later deleted from the Model. Normalize those obsolete assignments
explicitly. It also checks physical input-line capacity and the math lexer's
254-character token payload limit. Long aliases/numeric spelling can often be
normalized to a short equivalent; known over-capacity input is never sent to
native tests. General large-expression simplification/performance remains an
overall release gate.

Four explicit JSON tags represent the relation and the three leaf kinds, all
sharing the existing arithmetic node tags. Source-free Model JSON rebuilds the
complete equations. Graph renames update formula Refs and derived relation keys;
delete protection, cascading removal, cloning and scenario record operations use
the same store contracts as other domains.

## Units, scenarios and state files

Hydraulic conversion substitutes new FLOW/DEPTH/AREA variables divided by their
conversion factors into the original empirical formula. AREA uses the square of
the length factor. FLOW also changes when switching within one US/SI system,
such as CFS to GPM. HRT, DT, concentration and removal leaves keep their units.
Constants and nonlinear functions are not dimensionally guessed.

The [public pollutant-unit protocol](2.0-pollutant-units.md) handles MG/L ↔ UG/L.
Every concentration leaf of the converted pollutant is replaced by the new leaf
divided by its conversion factor. A C formula targeting that pollutant also
multiplies its final output by the factor. R output and removal leaves remain
dimensionless. Other pollutants' formulas are updated wherever they reference
the converted concentration. `ChangePollutantUnits` scenarios apply this same
atomic transformation. Reinterpretation changes only the label by explicit user
request. Repeated conversions may enlarge the AST; algebraic simplification is
not claimed.

Treatment adds no new HOTSTART/RUNOFF fields. Automatic layouts now accept its
owned records; native tests generate, read, byte-exactly rewrite and reuse both
state/cache files with treatment and two pollutants. Actual histories agree.
This does not authenticate producer snapshots or establish physical suitability
of changing model parameters while reusing a cache; runtime provenance remains
part of the unfinished release gates.
