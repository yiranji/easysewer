# Candidate pumps and regulators

`Model.links` reads and writes conduits, pumps, orifices, weirs and outlets. Native behavior here is pinned to SWMM 5.2.4.

## Typed parameters

| Link | Supported parameters and variants |
| --- | --- |
| `Pump` | `curve=None` for ideal pumping, PUMP1–PUMP5 curve references, initial ON/OFF state, startup and shutoff depths |
| `Orifice` | SIDE/BOTTOM, offset, dimensionless discharge coefficient, flap gate, `timedelta` opening time, CIRCULAR/RECT_CLOSED section |
| `Weir` | TRANSVERSE/SIDEFLOW/V-NOTCH/TRAPEZOIDAL/ROADWAY, crest offset, discharge coefficient, flap gate, end contractions, end coefficient, surcharge permission, roadway width/surface, coefficient curve and appropriate section |
| `Outlet` | Offset and flap gate, `FunctionalRating(coefficient, exponent, basis)` or `TabularRating(curve, basis)`, with HEAD/DEPTH basis |

Links share the node-reference graph, rename/delete checks, vertices, source
bindings and ordered emission. Associated XSECTIONS may appear before their owners
in INP. Regulator shapes are checked against their hydraulic type; pumps and outlets
do not need a section.

```python
from datetime import timedelta
from easysewer.model import Ref
from easysewer.model.network import Orifice
from easysewer.model.geometry import CrossSection, Circular

model.links.add(Orifice(
    id="Gate", inlet=Ref(collection="swmm:nodes", key="Tank"),
    outlet=Ref(collection="swmm:nodes", key="Outfall"),
    orientation="SIDE", offset=0.2, coefficient=0.65,
    gated=True, opening_time=timedelta(seconds=60),
    section=CrossSection(geometry=Circular(diameter=1)),
))
model.convert_link_offsets("ELEVATION")
model.convert_units("CMS")
```

The example assumes those nodes exist and the starting model has the intended
unit system. Coordinates and vertices remain map coordinates during hydraulic
unit conversion.

## Optional fields and source preservation

`None` retains an omitted parameter; zero and false remain explicit. INP syntax
requires some interior defaults to reach later fields. Pump status defaults to
ON, depths to zero, and an absent or `*` pump curve means ideal pumping. The writer
can use the native three-field ideal form. Weir optional slots support `*`, while
the roadway width slot requires a number. Required offset slots materialize zero
in DEPTH mode when omitted in a newly constructed Model.

Orifice opening time is written in decimal hours. Native input does not accept
clock syntax there. The candidate uses Python `timedelta` microsecond resolution;
finer source precision produces a diagnostic. Unedited source retains the original
token; rebuilding or editing that field uses the representable duration. This is
not an arbitrary-precision duration API.

Bare FUNCTIONAL/TABULAR outlet relation keywords are read as DEPTH-based aliases;
normalized output explicitly includes `/DEPTH`. Negative functional coefficients
or exponents can be preserved as drafts but are rejected by `for_run` physical
checks. Zero coefficients and zero exponents are representable.

Unknown variants, invalid rows, duplicate declarations and undocumented
non-conduit LOSSES/XSECTIONS remain source-owned with diagnostics. They are not
silently dropped or advertised as fully structured. Unsafe graph transformations
remain blocked while such source-owned records exist.

## Units and reference rules

Pump curve axes are volume/flow for PUMP1 and depth/flow for PUMP2–PUMP5. Outlet
RATING curves are depth/flow. A functional outlet `Q = C * H**E` converts C by
`flow_factor / length_factor**E`; numeric overflow aborts the whole conversion.

Ordinary weir coefficients have units CFS/ft**2.5 or CMS/m**2.5, regardless of the
selected model flow unit. The SIDEFLOW exponents also sum to 2.5, including reverse
flow. WEIR curves have depth and this coefficient as their axes. They and shared
pump/outlet curves are converted once and remain linked through renames.

The fixed engine uses three distinct rounded constants that must not be merged:

| Quantity | US → SI factor used by engine conversion |
| --- | --- |
| CFS to model CMS flow | `.02832` |
| Ordinary weir coefficient | `.028317 / .3048**2.5` |
| ROADWAY user coefficient | `.552` |

`basis="physical"` instead uses exact physical factors; it is a distinct policy,
not a promise of identical native output. ROADWAY uses its own coefficient rule,
even when a positive width and recognized surface activate the built-in HDS-5
coefficient tables. Weir end coefficients and WEIR curve ordinates retain ordinary
weir units.

All modeled link offsets now support DEPTH/ELEVATION conversion. Conduits use each
endpoint's invert; orifices, weirs and outlets use the inlet invert; pumps have no
offsets. `Offset.NODE_INVERT` writes `*` and requires ELEVATION mode. Conversion
uses the native zero clamp for negative heights rather than carrying an ineffective
negative depth into the other mode. Native downstream-crest adjustment is diagnosed
separately and is not written back silently to the source model.

Feature unit transforms now receive `ConversionContext.convert_value` for nested
values, so a compound rule can delegate section conversion to registered geometry
rules. Calling it on the same enclosing value would recurse; use it on children.
This is a candidate extension facility pending the full planned extension trials.

## Verified native differences

The manual and the pinned implementation differ in details:

- The native reader supports a WEIR coefficient-curve reference in the thirteenth
  token, after the roadway slots, for all weir types.
- An omitted trapezoidal end coefficient is zero, not a copy of the main
  coefficient. Native tests compare omission, explicit zero and a nonzero value.
- End contractions are stored as a nonnegative real value, so fractional source
  values are preserved.
- ROADWAY ignores flap gates, end contractions/coefficient, surcharge permission
  and the user coefficient curve in its flow calculation. Diagnostics expose
  these inactive parameters; reverse-flow tests demonstrate the ignored gate.
- Steady/kinematic routing requires regulator links to leave a Storage node.
  Positive pump startup depth must exceed shutoff depth; zero startup has different
  native semantics. These errors are diagnosed before running.
- The native reader ignores barrels, culvert code and unused geometry slots,
  including rectangular side exclusions, for regulators. The reader retains those
  tokens in source with a warning; the semantic section and normalized output omit
  them. Even nonnumeric ignored barrel/culvert tokens must not inherit conduit
  validation rules. Explicitly constructing inactive section fields also warns.

[roadway.c](https://github.com/USEPA/Stormwater-Management-Model/blob/v5.2.4/src/solver/roadway.c),

## Validation and limits

The regulator tests cover 17 variants across three routing modes and two unit
systems (102 raw-input/rebuilt-Model comparisons), plus all six flow units
(102 dynamic-wave comparisons). These compare the full node depth, volume,
link flow and overflow trajectories and mass balance, with positive flow checks
for the raw-input cases. Unit comparisons use 1e-8 trajectory and 1e-7 mass-balance
tolerances. Non-storage inlet fixtures isolate link conversion from the previously
documented native storage-volume conversion discrepancy.

Additional native tests exercise coefficient curves, both roadway surfaces,
both orifice shapes/orientations, timed gate opening, actual pump startup/shutoff,
reverse-flow gates, surcharge permission, end contractions, offset markers and
native rejection of invalid topology/depth limits. The control text and DWF forcing
in these original tests are deliberately appended fixtures. Subsequent
[FLOW/DWF](2.0-inflows.md) and [control-program](2.0-controls.md) increments provide
their candidate Model codecs and independently rebuilt native comparisons.

This increment does not complete whole-network topology/physical validation,
legacy scenario migration, runtime sessions, result readers, cross-platform
execution or the complete 2.0 release gates. Existing storage and transect native
limitations still apply.
[Model JSON](2.0-json.md) now persists all implemented link and parameter variants.
