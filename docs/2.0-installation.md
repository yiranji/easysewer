# Installation

Python 3.10 or later is required. Install the published 2.0 release from PyPI:

```console
python -m pip install easysewer==2.0.0
python -c "from easysewer import Model; print(Model())"
```

Version `2.0.0` is a final release. A fresh `pip install easysewer` selects the latest compatible final release. To upgrade an existing installation, use `python -m pip install --upgrade easysewer`. The 2.0 API does not support 1.x callers.

## Install a local build

Before publication, install the built wheel instead. From the repository root:

```console
python -m pip install dist/2.0.0/native/easysewer-2.0.0-py3-none-any.whl
python examples/v2_first_run.py runs/first-example
```

## Check the simulation backend

The PyPI distribution and local native package include **x86-64 Windows and
Linux** libraries, for **64-bit Python**. Simulation requires compatible native
libraries; the wheel's `any` tag does not promise native execution on every
operating system or architecture. The bundled Linux solvers require **glibc
2.33 or newer** and the OpenMP runtime **`libgomp.so.1`**, in addition to
`libm.so.6` and `libc.so.6`. macOS, ARM, 32-bit Python and musl-based Linux do not
have a compatible bundled solver. Pure modeling and result reading remain
independent of those solver requirements.

Backend probing determines actual availability by loading the library in a
disposable process and checking its ABI:

```python
from easysewer.runtime import StandardBackend

info = StandardBackend().probe()
print(info)
if not info.available:
    raise RuntimeError(info.reason)
```

Use `FlexiblePondingBackend().probe()` for the custom solver. In contrast,
`easysewer.get_native_capabilities()` is a lightweight file/platform check:
`True` means a candidate file exists for this runtime ABI, not that the system
loader can load it. It does not start a process or load a native library.

If the probe reports `libgomp.so.1` missing, install the system OpenMP runtime
(`libgomp1` on Debian/Ubuntu or `libgomp` on Fedora/RHEL) using your system's
package manager. A `GLIBC_2.33 not found` failure requires a compatible Linux
runtime or a solver rebuilt for that target; reinstalling the same wheel does
not lower its glibc requirement. Do not replace system libc files manually.
See the [standard build recipe](../native/standard/README.md) and
[custom build recipe](../native/flexible_ponding/README.md). An explicitly
selected compatible user library is checked separately and is not restricted
by the bundled-library platform list.

For a local package without native libraries, install the wheel with the same name under `dist/2.0.0/pure/`. This is a separate local build, not a second PyPI variant. Install one package variant per environment. The pure package provides neither a native solver nor a WebAssembly solver; success on host Python does not establish browser support. See the [pure Python build guide](2.0-pure-python.md).

The core runtime has no third-party Python dependencies. Quick Start plotting requires Plotly, and interactive notebook execution also requires Notebook/Jupyter; these are example dependencies. Rebuilding packages requires setuptools 77.0.3 or later and wheel. See [testing, builds and publishing](2.0-testing.md).
