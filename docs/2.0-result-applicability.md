# Candidate result applicability

Result presence and physical applicability are different questions. A native
RUNOFF replay can emit a structurally valid groundwater summary filled with
initial values. The table parser must preserve that evidence without presenting
those numbers as recomputed groundwater statistics.

`ResultApplicability` accompanies tables, columns, series and saved-observation
maxima. Its immutable `status`, `reasons` and `evidence` are portable data:

| Status | Meaning |
| --- | --- |
| `computed` | The relevant process ran in the captured execution scope |
| `replayed` | Values originate from sampled interface data |
| `partial` | Values/state have an identified omission or limited time scope |
| `not_computed` | The requested calculation was skipped |
| `not_applicable` | The required process or object binding was inactive/absent |
| `unknown` | Available evidence does not establish the scope |

These are not guarantees of numerical accuracy, conservation, calibration or
physical cache compatibility. `partial` and `unknown` retain observed numbers;
callers must examine their reason codes before using them. For a known
`not_computed` or `not_applicable` numeric observation, the value is `None` and
its missing reason identifies the cause. Raw OUT/RPT artifacts remain unchanged.
RPT cell tokens, source spans, printed precision and complete text are retained.

## Captured execution evidence

`ResultContext` stores a versioned policy, immutable namespaced facts and
evidence identifiers. The current `swmm:result-context:1` policy derives facts
from captured supported input and a known native implementation. Runner binds
the context to the executed input and backend hashes. Process sessions use the
same rules for supported input captured around native open; opaque or oversized
input and unverified libraries remain unknown. An early explicit `session.end()`
limits computed results to `swmm:simulation-ended-early`.

Unrecognized policies and additional facts survive `to_data()`/`from_data()`;
unknown policies or unregistered variable scopes make no computed claim.
Deserialization does not load code or turn evidence strings into an attestation.
A caller-supplied context is an assertion by that caller.

New groundwater scopes list their canonical object identities in sorted order.
The list describes membership, so moving or relocating a keyed GROUNDWATER row
does not change result applicability. This also keeps Runner and a fresh resume
worker consistent when they reconstruct the same input through different source
projections. Existing context arrays retain their original order when read and
resaved; the `swmm:result-context:1` data format is unchanged.

A bare OUT does not encode replay mode, process options or backend identity,
so its applicability remains unknown. An RPT's exact runoff-interface notice
can establish replay and invalidate hydrologic summaries, even without a
Runner. If that notice is absent, replay must come from explicit captured
context; absence of the notice does not establish recomputation. Conflicting
explicit context and a printed replay notice are rejected.

## RUNOFF and continuity

During USE RUNOFF, runoff/quality/groundwater continuity tables, catchment
runoff/washoff summaries and LID water balances are not recomputed. Their
numeric cells are unavailable in typed queries. The runoff-interface notice
itself remains readable text. Table `status` still describes parsing/presence,
so `status == "present"` alone is insufficient for using a numeric result.

Routing and routed quality remain computed when those processes are active.
Cached catchment fields are `replayed`, including restored groundwater fields
when the catchment has a groundwater binding. A groundwater field without a
binding is `not_applicable`. Current gages supply rainfall. System evaporation
is `partial` when replay omits a bound groundwater system's evaporation; no
missing groundwater evaporation is invented.

`MassBalance` exposes `applicability("runoff" | "flow" | "quality")`.
Unavailable percentages become `None`; `raw_percentages` retains the three
unmodified native C return values in that order. With REPORT DISABLED, the
qualified standard backend does not finalize continuity calculations, so its
zero getter values are unavailable. The qualified custom ABI 201 backend still
finalizes continuity independently of report printing; its active routing and
quality balances remain usable. Unknown backend behavior remains unknown.
Suppressing report text does not disable routing values recorded in OUT.

HOTSTART produced after replay has `ProducedCache.applicability.status ==
"partial"`: initialized/inherited infiltration, subarea, snow, LID and buildup
states are not made into complete hydrologic continuation state. Existing
manifest checks and physical-reuse warnings remain in force.

Known HOTSTART artifacts from ordinary computation are also `partial`: version
4 omits LID, RDII, control and numerical integration history. The
[continuation condition policy](2.0-cache-conditions.md) can report `matched`
while the artifact remains a partial state. It does not make adjoining runs
equivalent to uninterrupted computation.

```python
table = run.report_table("swmm:groundwater")
print(table.status, table.applicability.status, table.applicability.reasons)

with run.open_output() as output:
    series = output.series(None, "swmm:evaporation")
    print(series.applicability.status, series.applicability.reasons)

print(run.mass_balance.flow_percent)
print(run.mass_balance.applicability("flow"))
```

## Persistence and limits

Series/table JSON now writes contract `1.1`, including applicability. Readers
accept `1.0` as legacy data with unknown applicability. Context propagates
through chunked OUT reads, report detail projections and series maxima. Runner
execution records retain context, raw continuity values and cache applicability;
individual archived report-table JSON retains its cell-level missingness.

Native binaries and raw artifacts are unchanged by this layer. Direct C clients
still need to handle native report limitations; the typed APIs neither rewrite
the report nor change its hash. Broader process/variable scope coverage, complete
physical cache-reuse evidence and the other 2.0 release gates remain separate
work. [RunResult archives](2.0-result-archive.md) preserve the complete captured
result, including these applicability fields. Unknown scope is retained
explicitly while that coverage is extended.
