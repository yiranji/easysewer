# Candidate field inspection

`Model.inspect_field(ref, path)` returns separate facts about a **current** field:
its value, Python constructor default, JSON omission default, and explicitly
registered unit/profile-default/effective-value semantics. These facts are not
interchangeable. A `FieldFact` has a status; only `known` has a value. A known
`None` is different from `unknown`, `required`, `not_applicable`, `invalid`, or
`ambiguous`. Constructor default factories are not executed by a query.

```python
from easysewer.model import Model, Ref

model = Model.from_inp("network.inp")
owner = Ref(collection="swmm:options", key="settings")
info = model.inspect_field(owner, "rule_step")
print(info.value, info.semantics.default, info.semantics.effective)
print(info.provenance.status, info.changed)
for declaration in info.provenance.declarations:
    if declaration.raw_text is not None:
        print(declaration.span, declaration.raw_text, declaration.role, declaration.contributes)
    for token in declaration.tokens:
        print(token.span, token.raw, declaration.role, declaration.contributes)
```

Paths are one attribute name or a nonempty tuple of attribute names and
nonnegative tuple indexes. Queries address dataclass fields and tuple items,
never arbitrary object properties. An absent current record/path raises
`KeyError`. Field facts are derived and are not separate JSON graph values.

## Original input and current values

The original token includes exact raw spelling, quote state, source span and
decoded-document character offsets. It is captured from the imported document;
queries do not serialize the model or read files. Record lineage follows the
[record provenance contract](2.0-provenance.md).

`FieldProvenance.status` distinguishes `explicit`, `derived`, `omitted`, and
`unknown`. An omission is asserted only when the codec declares complete field
coverage. A malformed known input prevents that claim. `unknown` may still have
partial declarations and a decoded original value; that value is not proof of a
valid input or engine default. Lifecycle states `created`, `untracked`, and
`unavailable` retain the meanings in record provenance. `absent_path` means the
original record has no such path.

`Model.field_provenance(ref, path)` explicitly queries a path **in the original
record**, including its original tuple indexes. It remains useful after a
current variant or sequence changes. It does not identify current unnamed
sequence items. `inspect_field` returns `untracked_path` for indexed current
paths or changed container types, rather than borrowing the former item's
source. `changed` is then unknown. For safely corresponding named fields,
`changed` compares decoded original and current values; it is not an edit log.

Source-bearing JSON rederives declarations from the stored original document and
registered codecs and preserves the record association ledger. Old JSON without
that ledger and portable JSON cannot claim an original omission. Source bindings
do not change the authoritative current graph or the JSON envelope version.

## Current coverage

All 43 analysis options have declared field/token coverage and profile semantics.
Repeated assignments retain original tokens and identify contributors. The
`FLOW_ROUTING NONE` token derives `ignore_routing`; its routing declaration
retains the preceding/default algorithm rather than overwriting it. That retained
token is labelled `retained` and is not a value contributor.

Option defaults are profile input defaults. Effective values use the existing
option resolver, including step adjustments, dynamic-wave zero defaults, and
the reporting calendar's start fallback/clamping. Duration units describe public
`timedelta` values in seconds; original syntax may use a clock or decimal hours.
Diagnostics explain adjustments and invalid context; this query does not prove
that an entire model can run.

Other records can expose current values and labelled constructor/JSON facts, but
their source/unit/default/effective contracts remain `unknown` until explicitly
declared. MAP/BACKDROP and LABELS now also have explicit declarations and scoped
semantics, including nested extents, coordinates, lexical file context and anchors.
Junction and conduit core fields, conduit losses, and coordinate/vertex sources
also have contracts. This is not completion of the full R04/R05/R11 field matrix.
Other node/link types and nested geometry contracts, contextual dimensions, curve/time-series
consumers and result metrics still need coverage and acceptance.

Map coordinate units follow explicit MAP/BACKDROP order, independently of the
hydraulic flow units. Missing units and `NONE` leave coordinate units unknown;
degrees do not imply a CRS. Bounds and image state depending on ambient GUI or
image data are not invented. Deprecated OFFSET/SCALING tokens have exact sources
but no active GUI effect; their unit semantics remain explicitly unknown. Label
font sizes use points; omitted font/size/bold/italic defaults differ from equal
explicit tokens. Label positions describe stored declarations, not rendered
pixel geometry. Original label paths use the original decoded tuple indexes;
current indexed queries still refuse an unproven identity association.

Junction input defaults for maximum/initial/surcharge depth and ponded area are
zero; constructor omission remains `None`. Effective maximum depth includes
supported adjacent conduit crowns. Circular fill raises the offset and reduces
the open height, preserving the crown. Standard sizes, DUMMY's internal TINY
depth and transect/street full depths are supported. Upstream regulator crown
adjustments and unregistered geometry/resource preprocessing remain `unknown`;
the query does not substitute the input default. Ponded area is `not_applicable` while surface
ponding is disabled. These queries describe the current structured graph, not
unparsed original rows, and are not an assertion that the whole model can run.

Conduit offset INP columns are required. A Python `None` in DEPTH mode is written
as zero by the exporter; this is separate from an INP omission default. In
ELEVATION mode, `*` means the endpoint invert, not absolute elevation zero.
Effective offsets use heights above the **declared** endpoint inverts, including
negative-height clamping and circular fill. That convention stays attached to
the named endpoint when the solver reverses internal orientation. Length and
Manning n queries describe physical input parameters, not lengthened numerical
length or derived friction factors. Initial flow retains the declared direction;
maximum flow zero means no imposed limit. Optional LOSSES defaults are resolved
individually and for the aggregate object. None of these are live solver values.

Network source queries retain required columns, explicit zero/asterisk markers,
derived reference namespaces, repeated last-assignment coordinates and separate
LOSSES/XSECTIONS rows, including nested shape parameters. Vertices use original tuple indexes and the
same current-identity guard as labels. Malformed or duplicate known rows prevent
false complete-source/omission claims.

## Independent extensions

Codecs return `FieldBinding` and `FieldCoverage` entries in `FeatureData`.
Bindings name an original record `Ref`, a field path, a claimed physical line,
zero-based token indexes, a role (`value`, `marker`, `derived`, `retained`) and a
contribution flag. Multiple tokens can contribute to one field and one token can
affect multiple fields. The decoder resolves assignment order. Coverage asserts
complete understanding of the original field's input, including omission.
Import validates original paths, decoded record ownership, feature/line ownership,
token bounds and duplicate claims. Unknown codecs cannot acquire guessed claims.
Only `derived` bindings can depend on another record's line within the same
decoded feature. The target must still be decoded by that feature; foreign-feature
and direct cross-owner claims fail. `FieldDeclaration.source_owners` identifies
the original owners of the supporting tokens. MAP priority demonstrates this:
a BACKDROP unit declaration can contribute to MAP's derived order marker.

`FieldLineBinding` supports a complete physical line in a feature's explicitly
declared `raw_sections`. It has the same owner/path/line/role/contribution checks,
without token indexes. Its `FieldDeclaration` has `tokens=()`, exact `raw_text`
and a `span` covering the decoded line, excluding its newline. An empty string
is a real blank-line declaration; `None` denotes a token declaration. The original
document and its digest retain encoding and newline bytes. This representation
does not invent tokens for title prose, comments or encoded annotation chunks.

A codec's immutable `field_rules` tuple registers exact dataclass type/attribute
`FieldRule` values. Their resolvers receive `FieldContext` and return immutable
`FieldSemantics`; invalid returns and conflicting registrations fail explicitly.
Rules obey active profiles and schema snapshots. Resolvers must be pure and must
not mutate the supplied store, access native libraries or perform external I/O.
Constructor/JSON defaults are inspected independently of these semantic rules.
`FieldRule.root_type` optionally restricts a rule to an exact root record class.
An active scoped rule takes precedence over a general value-type rule. This lets
shared `Point`/`Ref`/`FileReference` types retain context-specific meanings without
claiming support for unrelated records. `ModelSchema.field_rules(profile)` lists
the declarations with their scopes; a scoped rule is not universal type coverage.
## Cross-section field contracts 

Nested `section.geometry` parameters now have explicit syntax bindings for all
26 built-in variants, including standard-size code precedence and resource IDs.
Bindings use the codec's declared parameter order, also for extension syntax;
they never infer INP columns from dataclass order. Duplicate or malformed
XSECTIONS rows prevent a false completeness/omission claim. Regulator columns
ignored by the native reader remain `retained`, with `contributes=False`.

`inspect_field(link, ("section", "geometry", "full_depth"))` distinguishes a
stored `None` selected by a standard size code from the effective native table
dimension. Code-based dimensions have derived provenance; original inactive
dimension tokens in the third-slot form are retained separately. Tables have
23 ellipse and 102 arch codes, in inches, converted to the model's units.
Out-of-range codes produce diagnostics and block export.

Geometry field rules are scoped to Conduit, Orifice and Weir owners. Barrel and
culvert input defaults are 1 and 0 for numeric conduit sections; these inputs
are not applicable to reference sections or regulators. RECT_OPEN side
exclusions are likewise inapplicable to regulators. Force-main roughness units
depend on the configured friction equation. Rounded-bottom/top radii report
the native minimum of half the declared width independently of the raw value.
RECT_OPEN's numeric input slots remain required even though Python `None` for
side exclusions is exported as zero. Barrel counts above 127 and culvert codes
above the native signed integer range retain their raw values and provenance,
but their effective values are explicitly unknown. The native barrel `char`
can reject or wrap these inputs; inspection does not promise portable counts.

Junction effective maximum depth additionally handles standard-size sections,
DUMMY's internal TINY depth, and referenced transect/street preprocessing. It
preserves native arithmetic order, including the pinned transect elevation
offset conversion, and rejects nonfinite or collapsed depth. Queries operate
on the structured graph without native library loading. They do not certify
all hydraulic geometry conditions or provide live simulation values.
Resource field contracts and the complete physical/topological validation
matrix remain pending. These additions do not freeze the public API or complete
R04/R05.

## Pump and regulator field contracts 

Pump, Orifice, Weir and Outlet declarations have explicit field source bindings,
including nested node/curve references, outlet relations, optional placeholders
and decimal-hour opening times. Opening time is a model duration measured in
seconds; its original INP token remains available. Coordinate units require an
explicit MAP/BACKDROP declaration, independently of flow units.

Regulator offsets report height above the declared upstream invert. ELEVATION
inputs and invert markers are converted before clamping; only dynamic-wave
routing raises a crest below the downstream invert. Junction maximum depth
includes upstream regulator crowns. Pumps and bottom orifices do not extend
these crowns; outlets use the native DUMMY depth. Storage and Divider maximum
depth follow the additional node contracts below. These are not live hydraulic
observations.

Pump initial status and start/stop depths are configured initial conditions.
Curve references are checked for their consumer type. Functional outlet
coefficient units depend on the selected flow unit and declared exponent;
ordinary weir coefficients use the native US/SI units. Unknown outlet rating
extensions do not inherit native crest semantics.

ROADWAY gates, end coefficients/contractions, surcharge flags and coefficient
curves are hydraulically inapplicable even when their parsed declarations are
retained. Positive roadway width and a recognized surface select native variable
coefficient tables. For other weirs, a coefficient curve supersedes the scalar
coefficient; end contractions apply to transverse/sideflow flow and the end
coefficient also applies to partially open V-notch flow. These facts describe
parameter applicability, not instantaneous coefficients, settings or flows.

Source `contributes` refers to the structured declaration: a parsed ROADWAY gate
still contributes to its stored value. Road width/surface columns discarded by
the non-ROADWAY reader instead have `role="retained", contributes=False`.

## Storage, Divider and Outfall field contracts 

Field bindings follow each grammar's variable column positions: six storage
shapes and their two seepage forms, four divider laws, and five outfall boundary
types. CYLINDRICAL's required but ignored third shape parameter is retained as
a noncontributing declaration on `shape`. A scalar conductivity and a full
suction/conductivity/deficit triple retain their distinct source forms. Duplicate
or malformed node rows prevent a false complete provenance claim.

Storage maximum and initial depth remain required INP inputs. Omitted surcharge
and evaporation fraction default to zero. Open storage retains its declared
maximum depth; positive surcharge enables adjacent crown expansion. Divider
maximum depth uses crown expansion and its four optional numeric inputs default
to zero. Initial-depth queries report invalid values above adjusted maximum plus
surcharge. These queries do not certify full storage volume/geometry validity.

Zero conductivity disables native storage exfiltration: the aggregate `seepage`
effective value is `None`, while configured data and provenance remain intact.
Suction and initial deficit are then inapplicable. Functional-storage coefficient
units express area divided by depth to its exponent. Divider-weir coefficients
use the selected flow unit divided by length to power 1.5, unlike link-weir
coefficients. Coordinate and polygon units still require explicit map metadata.

Dynamic-wave routing makes a divider law and its diversion target hydraulically
inapplicable. Missing/disconnected targets and invalid weir ranges remain errors
because native validation still checks those declarations. Standard routing's
active diversion additionally requires a link leaving the divider. A `*` target
records an explicit absent reference; it does not make native validation optional.

Outfall gate and route-target defaults are false and absent respectively. Fixed
stage is an absolute elevation, not a water depth. Tidal and series boundaries
retain configured references, not time-varying stage values. Curve consumer kinds,
missing references and locally invalid resources are checked; inspecting an
external time-series reference performs no file I/O and does not establish that
the file is available. Extension shapes, laws and boundaries require their own
contracts and do not acquire built-in semantics by subclassing.

## Shared curve, series and pattern contracts 

Resource source bindings cover complete groups across noncontiguous rows and
repeated sections. A malformed group has no partially claimed structured record.
The first identifier spelling contributes to `id`; continuation spellings are
retained declarations. Curve pairs, time/value pairs and individual pattern
factors have explicit original paths. A carried calendar date records both the
earlier date token and the current clock as derived sources. Current tuple indexes
still have `untracked_path` provenance; `field_provenance` addresses original
indexes, including after replacement or reordering.

Fixed curve kinds supply intrinsic axis dimensions. CONTROL curves and series
require dimensional declarations for every reference through the schema's
registered `resource_uses` hooks. Conflicting declarations are `ambiguous`,
incorrect axis counts/kinds or fictitious reference paths are `invalid`, and
missing or unsupported unit declarations are `unknown`. A fixed curve retains
its intrinsic units when an extension omits a declaration; this does not certify
that extension's compatibility. Known stored ordinates with unknown units are
configured numbers, not a claim that the consumer is runnable.

Inline series effective `points` contain model-local Python datetimes. A relative
timedelta uses the complete simulation start, including its clock; absolute
timestamps remain unchanged. Resolved order and calendar overflow are checked.
The effective time unit label is `model-local datetime`, while `value` preserves
the original timedelta or datetime. These timestamps do not promise bitwise
identity with native floating DateTime, or evaluate interpolation.

Pattern `factors` defaults to ones for the declared period, pads short tuples and
excludes stored factors beyond that period from its effective vector. Factors
after position 24 in INP remain noncontributing source tokens. For an existing
tuple index, `inspect_field(ref, ('factors', index))` reports a dimensionless
multiplier and input default one, or `not_applicable` beyond the period. Missing
indexes are not fabricated. WEEKEND activation still depends on the consumer's
calendar; a queried vector is not an instantaneous multiplier.

External-series `file` returns the configured FileReference without file I/O.
Its unit describes the expected data ordinate, not the filename. Nested file
fields have no physical unit; path is explicit and base directory, flavor and
input direction are derived lexical metadata. No availability or contents check
is implied.

`FieldContext.resource_uses` provides the registered consumer query. Optional
`FieldRule.resolve_item` explicitly enables semantics for a tuple field's direct
items; the resolver receives the dataclass container, attribute name, selected
value and full indexed path. Item constructor and JSON defaults are
`not_applicable`. Existing rules without this callback keep unknown item
semantics; nested dataclass fields continue using their own exact-type rules.

## Rain-gage, catchment and infiltration contracts 

The hydrology codec binds complete RainGage and Subcatchment groups, including
SYMBOLS, POLYGONS, SUBAREAS and INFILTRATION. Field positions follow each source
variant rather than dataclass order. Replaced rows remain in declaration history
with `contributes=False`, including optional fields omitted by the final row.
An original field can consequently have an explicit historical declaration and a
final value of `None`; inspect contributions to distinguish those facts. The
unused second Curve Number column is retained without contributing to parameters.
Malformed or duplicate primary declarations prevent partial group ownership.

Gage intervals are model timedeltas in whole seconds. Their raw tokens retain
numeric-hour or clock syntax, including the different series-rounding and
file-truncation rules. Series source references and file station/units/date
filters describe configuration, not current rainfall. A file gage's effective
format and interval remain `unknown`: detected formats and rainfall-interface
headers can replace the input declarations. Querying neither opens an external
file nor asserts its availability. File units describe the declared user-file
format; historical formats have their own units. Position and polygon units come
from explicit MAP/BACKDROP metadata, independently of flow units.

Catchment area uses acre/ha, width uses ft/m, slope and impervious fractions use
input percentages, and curb length keeps the user-defined length convention.
Effective impervious percentage is capped at 100. Subarea routing defaults its
optional percentage to 100; zero or fully impervious area fractions force the
route to OUTLET, where the routing percentage is not applicable. Negative
subarea fractions caused by zero-storage percentages above 100 are invalid.
These facts do not include a live runoff distribution or seasonal pattern values.

Infiltration method inherits the project option unless explicitly declared.
Parameter types must match that resolved method. Horton omitted maximum volume
is zero (no limit), and zero drying time becomes the pinned engine's 1e-6 days
before computing its regeneration coefficient. Curve Number is clamped to
[10, 99]. Effective aggregate infiltration contains the resolved method and
adjusted input parameters; it does not expose evolving soil state, infiltration
capacity or internal ft/s constants. A missing infiltration group is invalid
when pervious runoff area exists, and not applicable when none exists. A missing
subarea group is likewise invalid for nonzero area and not applicable for zero
area. Explicit extension variants require their own exact-type contracts.

Configured references are checked for missing or locally invalid targets; an
outlet name present in both node and catchment collections is ambiguous. Existing
native-order validation still rejects SUBAREAS before its primary declaration
unless explicitly normalized. These contracts do not replace complete topology,
rainfall-sharing, file-format or physical-run validation.

## Snowpack and local monthly-adjustment contracts 

SNOWPACKS provenance distinguishes the four independently replaced parameter
groups. Original identifiers retain their first spelling; later group assignments
keep history without contributing superseded values, including omitted optional
transfer fractions and destinations. ADJUSTMENTS INFIL/DSTORE/N-PERV declarations
bind their catchment key from the second token and pattern from the third. Each
assignment has independent last-write contribution. Malformed groups remain
unclaimed as a whole. Rename/rekey and JSON preserve original coordinates.

Omitted snow-surface rows resolve to native zero parameter objects. Their base
temperature is zero internal degrees Fahrenheit, converted to the model's
temperature units; this differs from an explicitly supplied zero Celsius.
Plowable fraction and full-cover depths also default to zero. A missing removal
row has zero transfer fractions and is represented by effective `None`, without
exposing the unused internal threshold sentinel. Missing nested paths are not
fabricated: query the aggregate default to inspect an omitted surface.

For a declared surface, initial free water is capped at free-water fraction times
initial snow depth. These are shared input parameters; consumer catchment area
fractions can make actual initial surface state zero. Melt coefficients use
in/hour/F or mm/hour/C; other depths use in/mm. Negative physical parameters,
reversed melt bounds and removal fractions totaling more than one are invalid.
The last rule follows the existing physical-run guard, which is stricter than
native SWMM's 1.01 input tolerance.

The documented short REMOVAL row can omit Fsub in the model, where normalization
supplies zero. Native input still requires that column; the original short row
remains rejected for direct execution until explicitly normalized. A positive
transfer requires a destination; an explicit invalid reference is rejected even
when its transfer fraction is zero. Destination queries are not applicable when
there is no transfer or the recipient lacks a snowpack/pervious area fraction.
The configured aggregate retains its fractions even when a destination is
inactive. Native transfer uses surface fractions without a catchment-area ratio;
these facts do not certify mass conservation for unequal-area recipients.
Extension recipients, snowpacks, surfaces and removal variants require explicit
contracts rather than inherited built-in applicability.

Local adjustment fields retain configured MONTHLY pattern references, not a
multiplier selected for a guessed date. An omitted assignment is effective None:
the corresponding base/global behavior remains. In particular, local INFIL
overrides the global conductivity adjustment instead of multiplying it. DSTORE
and N-PERV affect pervious-area behavior and have their own runtime rules for
nonpositive factors. Missing targets and wrong pattern kinds are invalid;
extension patterns require their own contracts. Parameter-source ordering guards
and full physical/run validation remain separate.

## Climate configuration contracts 

Climate facts describe static configuration and effective defaults, never the
instantaneous temperature, wind, evaporation rate or calendar-selected factor.
They include each built-in temperature/evaporation/wind variant, snowmelt and
depletion parameters, monthly adjustments, and their references. Unknown
extension values or resource types do not inherit built-in semantics. Invalid
local values, missing dependencies, incompatible recovery patterns and known
physical-run constraints are reported explicitly; queries do not open files.

Omitted groups use the profile's native defaults, including the constant ambient
temperature. That resolved ConstantTemperature is a fact, not a new writable INP
source variant. Query the aggregate for defaults of absent nested paths. Required
monthly/depletion rows still require all twelve/ten values; tuple-item facts only
address existing indexes. Nonpositive conductivity adjustments become one.
Temperature increments use delta F/delta C, distinct from absolute temperatures;
wind uses mile/h or km/h and evaporation uses in/day or mm/day.

ClimateFile.units reports the configured/default GHCND selector. It does not
certify the units of an unread file: other detected formats apply their own
temperature, evaporation and wind rules. The effective file start date follows
the simulation date when omitted. A missing path can still have known static
configuration; file availability and full run validation remain separate. Bare
evaporation FILE requires explicit normalization to its twelve default pan
coefficients, even when those effective defaults can be inspected.

Sources preserve keyword assignments and exact numeric/reference tokens. FILE
sets both the shared file and temperature mode; subsequent TIMESERIES changes
temperature mode without erasing the file. Repeated modes and optional tails
retain noncontributing historical tokens. RECOVERY and DRY_ONLY remain independent
of the chosen evaporation source. Original tuple-index provenance can be queried
with field_provenance; inspect_field does not infer identities for unnamed items
after edits. Whole malformed climate groups remain unclaimed.

## Pollutant and inflow contracts 

Pollutant fields expose configured concentrations, decay/growth per day, and
optional native defaults: snow-only false, no co-pollutant, and zero co-fraction,
DWF concentration and initial concentration. A co-fraction is not applicable
without a co-pollutant. When units differ, its label explicitly identifies the
target/source concentration units: native combines their numerical values
without automatically converting MG/L, UG/L or count/L.

External FLOW, concentration and MASS inflows have separate exact-type contracts.
Omitted baseline is zero; scale and mass factors default to one. The scale factor
applies only to a time-series term, not to the baseline, and is not applicable
without a series. A baseline pattern remains a configured reference, not a factor
selected for an assumed date. Negative configured inflow/scale values remain
inspectable; a supplied mass conversion factor must be positive. MASS baseline
units remain user-defined mass-rate units. Its factor converts to the pollutant's
mg/s, ug/s or count/s before native internal volume scaling; it is not assumed to
be a dimensionless conversion between arbitrary external units.

DWF patterns preserve four optional source slots and empty markers. The aggregate
effective tuple keeps source positions and clears entries superseded by a later
pattern of the same kind. Empty/overridden individual slots are not applicable.
This tuple is not the native internal array indexed by pattern kind. WEEKEND
replaces HOURLY on weekends; no current flow/concentration or calendar multiplier
is computed by inspection. References and dimensions are validated against the
actual pollutant/resource declarations, and conflicting shared-series dimensions
are explicit. Non-outfall concentration requires external FLOW at the same node.
Extension resources and node types need explicit contracts.

Source facts retain optional tails, empty slots, ignored FLOW/CONCEN factor
columns, co-pollutant placeholders/unpaired ignored names, and superseded rows.
Composite node/constituent identities survive rename/rekey and JSON. Original
record provenance remains distinct from current unnamed tuple-item identity.
Native source-order guards still apply to overridden references and shared
rainfall-series side effects; static field facts do not replace full run checks.

## Land-use and buildup/washoff contracts 

Land-use sweeping defaults are zero. Availability is a fraction, while washoff
removal efficiencies are percentages. Coverage and initial loading preserve their
composite identities. Loading units are lb/acre, kg/ha or count per area; only a
positive initial loading overrides native antecedent-dry-period buildup. Queries
do not calculate starting or instantaneous surface loading.

Buildup supports NONE, power, exponential, saturation and external series. AREA
uses the selected unit system; CURBLENGTH uses the user's curb unit without
assuming feet or meters. Power coefficients include the configured exponent of
days. Saturation half-time is the third numeric input slot; its second slot is
parsed but unused. Exponential buildup's third slot is likewise unused. These
slots remain inspectable as original inputs but have no effective formula value.
External series require consistent consumer-declared mass/count loading-rate
dimensions. MG/L and UG/L both use the same lb/kg surface mass units.

Exponential washoff coefficients use inverse hours and runoff intensity raised
to the declared exponent. Rating coefficients produce mg/s, ug/s or count/s from
the declared flow unit raised to that exponent. EMC uses the pollutant's
concentration unit; its parsed exponent is unused. Omitted active removal
efficiencies are zero percent; NONE has no applicable removal parameters.
NoBuildup's AREA placeholder is not an active normalization rule.

Sources track each COVERAGES/LOADINGS pair independently, including repeated
pairs on the same line. Formula histories interpret each historical variant's
own columns; overwritten and ignored inputs remain distinct from contributing
assignments. Malformed groups remain unclaimed. References, conflicting shared
series and coverage totals are checked; extension types require their own
contracts. These static facts do not replace complete physical/run validation.

## Seasonal RDII contracts 

Hydrograph facts retain ordered ALL/monthly assignments for SHORT, MEDIUM and
LONG responses. Later assignments replace only the affected month/type slots.
An ALL row can remain applicable in some months after a monthly override; a row
superseded in every month has no applicable effective value. Queries identify
the applicable months without choosing a current simulation date. Equal repeated
rows retain distinct source positions. Aggregate effective responses preserve
their order and supply zero for omitted abstraction parameters.

Time-to-peak remains in configured hours and the recession ratio remains
dimensionless. Native peak and base durations truncate independently to integer
seconds, and the query reason reports both durations. Rewriting just the peak
to truncated hours can change the base and the complete result. Initial
abstraction above the maximum remains configured rather than being clamped.
Depths use in/mm, recovery uses in/day or mm/day, and sewer area uses acre/ha.

Prior rain-gage assignments remain live references because native input activates
every assigned gage. The final gage supplies RDII. Missing gages on used groups
are invalid when RDII generation is enabled; interface USE and ignore options
change that generation requirement. Monthly fraction totals use responses with
nonzero native base durations and reject totals above 1.01; full model validation
also reports the native tolerance warning between 1 and 1.01.

Sources cover modern rows and legacy triples, including their shared month and
abstraction tokens, positional response types, prior gages and overwritten nodal
RDII assignments. Original tuple positions are queried through field_provenance;
they are not inferred as stable identities after editing. Malformed groups stay
unclaimed. Extension response/resource types need explicit contracts. These
facts describe static configuration, not live convolution or interface flows.

### Groundwater and empirical expressions

Aquifer and groundwater queries expose configured inputs. Omitted local bottom
elevation, water-table elevation and moisture inherit the referenced aquifer;
an omitted threshold uses the receiving node invert. Explicit zero remains an
input, and zero fixed surface depth selects the live node depth without making
that runtime depth available through a static field query. Native saturation
clamps are initialization state, not equivalent replacements for those inputs:
the initial infiltration limit still depends on the configured water table.

Tension slope follows the fixed solver's length units (ft/m). Groundwater flux
uses cfs/acre or cms/ha; it does not switch to GPM or LPS with the flow-unit scale.
Coefficient units include the configured exponent. AQUIFERS evaporation patterns
must be monthly, and invalid references or inherited elevation/moisture ranges
prevent a known effective value. Extension types require their own contracts.

GWF root expressions have LATERAL groundwater-flux or DEEP rain-intensity units.
Variable leaves expose their native dimensions. Empirical constants and
intermediate arithmetic retain an explicit unknown unit with a reason, even
when their configured values are known. Queries do not execute expressions or
impose guessed dimensional constraints. Expressions without a groundwater
binding are inactive.

Sources retain optional missing markers (including native numeric sentinels),
historical assignments and exact original expression token positions. Repeated
numbers and variables are tracked separately. Expression source bindings are
derived at INP-token granularity: a quoted formula is one physical token shared
by its leaves, not a claim of character-level provenance. The parser preserves
native signed-number and right-associative power behavior. Unit conversion
continues to transform variables and the final result explicitly.

### Layered LID controls and ordered deployments

LID queries cover all eight kinds, their layers, pollutant removals and active
or disabled deployments. Required layers remain required. Optional absent layers
remain absent configuration; inspection does not insert internally derived
green-roof storage or manufacture a finite input ratio for a rain barrel's
100-percent internal void space. Pavement/storage void ratios and clogging
factors retain their input meaning rather than returning native void fractions
or scaled clogging volumes under the original field names.

Omitted regeneration parameters and drain heads become zero; omitted storage
cover becomes false, following the fixed engine. Layer aggregates fill these
representable defaults. Zero surface depth removes the effective vegetation
fraction; absent or zero-thickness input storage removes the drain offset.
Ordinary drain coefficients have rain-intensity / rain-depth^exponent units;
roof disconnection uses a gutter-capacity rain intensity. Conventional drain
parameters are not applicable to green roofs or swales, roof disconnection
ignores them except its coefficient, and drain delay applies only to barrels.

Deployment area is per replicate. Group checks sum replicated areas and capture
percentages using native tolerances. Omitted pervious capture is zero, and an
omitted drain destination inherits the parent catchment outlet. At >=99.9%
impervious area, return to the pervious subarea becomes false. A node drain
shadowed by a subcatchment of the same name is ambiguous. Detail-report queries
describe lexical output references and never open files.

Original sources distinguish stateful type/layer assignments, ignored DRAINMAT
rows, optional omissions/markers, repeated removal pairs and their contributors.
Usage IDs belong to Model/JSON; INP import assigns ordinal IDs, so duplicate
parent/control pairs remain independent ordered records. A disabled deployment's
remaining tokens are retained as inert source text, with no inferred numeric
units, file access or drain references. Original tuple positions are available
through field_provenance; edited tuple items do not acquire inferred identities.

## Transects, streets and inlets

Built-in surface roots expose static input units, applicable defaults and
effective configuration. Transect meander and width slots are required in INP;
explicit zero selects one. NC inheritance is resolved before the current
transect applies its meander adjustment. Sources include preceding NC values
and X1 factors that contributed across records, with their original owners.
Multiple elevation/station pairs retain distinct token positions.

Coordinates remain original configuration, not an internal hydraulic table.
The elevation-offset unit label is nominal length: the pinned engine applies
its length factor twice to this input. The explanation identifies this special
rule; engine-preserving conversion uses the profile power. Existing SI bank
rounding restrictions remain in force.

Street omissions resolve to zero except two sides. Backing slope and roughness
are not applicable at zero backing width; ignored nonnumeric tokens remain
traceable. Generic grate splash velocity defaults to zero, street-curb throat
to VERTICAL, and DROP_CURB has no throat input. Repeated components and usage
rows replace the earlier whole assignment, including optional-tail omissions.

Inlet usage defaults to one inlet, zero clog/flow-limit/local dimensions and
AUTOMATIC placement. This query preserves configured placement and does not
infer native topology degree or captured flow. Missing references, incompatible
conduit shapes and invalid custom-curve purposes are invalid; extension designs
and geometry require explicit contracts. Custom curves retain their existing
DIVERSION or RATING consumer dimensions.

## Controls

Variables, arithmetic expressions and ordered rules expose configured values,
units and original clause/token positions. An omitted priority is zero; omitted
ELSE actions form an empty tuple. Equal-priority rule order and repeated actions
remain significant. Queries do not evaluate live premises, target settings,
clipping, PID history or the last controller selected by short-circuit evaluation.

Stored durations use seconds in field queries. Native condition input uses
numeric hours or clock text, while PID integral and derivative tokens use
minutes. Calendar dates and month/day values retain their typed meaning. Numeric
thresholds inherit the operand dimension where determinable; incompatible
arithmetic and state-dependent CURVE/PID axes remain explicitly unknown.

Rainfall intensity uses in/h or mm/h and accumulated rainfall uses in or mm.
The fixed engine reuses attribute codes for certain direct rainfall windows;
their status/time/calendar interpretation is preserved and diagnosed. Named
numeric expressions avoid the comparison-token collision. An unused gage can
return zero at runtime, and OUTLET SETTING premises return MISSING in the pinned
engine; static queries retain these compatibility limits rather than inventing
live values. Invalid action targets and dependent symbols invalidate the queried
statement. Unrelated rules sharing a variable's ID do not share its validation
identity.

Expression provenance uses the shared parser's character spans, including
repeated symbols, quoted formulas, signs and powers. A custom parser override is
honored, but without its own trace contract expression provenance stays unknown.
Unknown statement syntax preserves the whole original control program. Original
sources survive rename, JSON, result archives and supported checkpoint recovery.

## Treatment expressions

Treatment queries retain the configured node, pollutant, C/R kind and arithmetic
tree. A C equation declares output in its target pollutant's concentration units;
an R equation declares a removal fraction. These inputs are required. Absence of
an equation is not a default zero-removal equation: their native decay behavior
can differ. Literal values remain configured values, even when native evaluation
will clamp a removal to [0, 1] or an effluent concentration to the current value.

Process symbols expose native input units: HRT in hours, DT in seconds, FLOW in
user flow units, DEPTH in ft/m and AREA in ft2/m2. HRT is zero at non-storage
nodes; depth and area use old/new-state averages. The query returns the symbol
and its meaning, not a live measurement. Concentration leaves use the referenced
pollutant's units and its treatment kind selects influent or mixed-node values.
Removal leaves are dimensionless; a missing equation yields zero at runtime
with a model-validation warning. Names shadowed by process prefixes, missing
targets and removal cycles are invalid. Unknown extensions stay unknown.

Empirical constants and intermediate expressions have no separately declared
unit. This differs from control arithmetic and does not prevent explicit
hydraulic/pollutant substitution during conversion. Field rules are scoped to
their exact domain, so shared arithmetic types do not overwrite each other's
contracts.

Sources follow the same decoded-token join and first-equals split as the parser.
They preserve quotes, aliases, repeated variables, signed powers and historical
assignments; only the final complete assignment contributes. For example C=Q0
is one original physical token. A malformed assignment keeps its whole
node/pollutant group unclaimed. Earlier-reference and native line/token-capacity
preflight still applies until explicit normalization. Custom parser overrides
run normally but have unknown expression provenance without their own trace
contract. Sources remain attached through rename, JSON, result archives and
supported checkpoint recovery.

## Project declarations

Title lines, JSON annotations, tags and ordered profile links expose configured
values with no physical unit. Title omission means an empty tuple; individual
lines have no omission default. Native reporting of the first three meaningful
title lines does not truncate stored prose or its field facts. Annotation strings
and numbers do not acquire implicit reference or unit semantics.

Title aggregate and original tuple-item sources include blank and comment lines.
Annotation keys and JSON text have derived sources pointing to every actual
encoded marker line. JSON restores these declarations by reparsing the preserved
INP; they are not a second independently serialized source ledger. Current tuple
items retain the `untracked_path` guard described above.

Tags retain original class/ID/text tokens and last-assignment contributors.
Profiles retain the first name and append link sources in their original chunks,
including repeated links. Missing targets are invalid; disconnected profile
paths retain the existing diagnostic without claiming to render the GUI. Known
malformed tag assignments or profile additions prevent a complete-source claim.
Unregistered extensions still require their own field rules.

## Reporting, interfaces and event calendars

Reporting facts use the complete reporting defaults declared by the profile.
Selection facts describe the final mode and cumulative explicit members; use
`model.effective_report` for the actual objects in native output order. `NONE`
does not clear previously named members, and `ALL` does not manufacture explicit
member declarations. Sources distinguish the final mode assignment from lines
that contribute members, preserve repeated IDs, and exclude ignored token tails.
Failed known report groups have unknown provenance rather than an omission claim.

Interface facts describe configured kind, disposition and lexical file context.
They do not open files or promise that a resource is active or compatible. USE
and SAVE HOTSTART have separate slots; other kinds retain one final native slot.
Historical declarations follow that final slot even when USE changes to SAVE.
RDII relative paths remain unbound to the INP directory because the native engine
uses its working directory. Ambiguous lexical failures prevent complete-source
claims for surviving slots.

Event facts retain input order and original start/end bounds. Native startup
sorts and clips overlapping intervals without merging them; this does not rewrite
the configured facts. Each datetime derives from its two actual date/time tokens.
An invalid row makes aggregate provenance unknown while independently proven
original item sources remain available. Tuple positions are not persistent IDs.

`DayTime.clock` and `day_offset` derive from the original clock token and use
local model clock and day units. Their effective values are components of the
effective parent option. For reporting, rollover, fallback and clamping reside
in effective `report_start_date`, so the effective reporting day offset is zero.
The original component values remain available in `FieldInfo.value`. The fixed
engine's RPT summary displays configured dates with clocks modulo 24 hours;
this display is distinct from the actual execution calendar and OUT timestamps.

Invalid raw TITLE lines remain in the preserved document with diagnostics during
permissive import. They are not encoded as invented valid title records; strict
import/export still rejects them. Valid title items keep their original sources,
while a partially invalid aggregate has unknown provenance.

## Sweeping calendar and temporary directory components

The `month` and `day` fields of `sweep_start` and `sweep_end` describe configured
calendar components, with no independent omission defaults. Their original
sources derive from the parent's single month/day token. The fixed native engine
converts season bounds using the non-leap year 1947, includes both endpoints and
supports seasons crossing New Year. Runtime compares those bounds with the
actual year's day number. Consequently a March 1 single-day season sweeps on
February 29 in a leap year, and the default January 1–December 31 season excludes
December 31 in a leap year. Field inspection preserves this engine behavior;
it does not reinterpret the configured month/day as an actual execution date.

The four `temp_directory` components describe the configured lexical reference.
The path comes from its value token; base directory and path flavor derive from
that context, and output direction derives from the `TEMPDIR` keyword. These
queries perform no file IO and do not promise directory availability. Malformed
later declarations prevent a complete-source claim for all affected components.

Runner creates an owned workspace under the configured temporary directory and
rewrites the prepared option to an owned scratch subdirectory. The packaged
native engines create scratch files under explicit `TEMPDIR` on both Windows
and Linux. This execution behavior is verified separately from lexical field
queries. Runner cleanup removes its own workspace and newly created empty
parent directories, while preserving pre-existing directories and external files.
