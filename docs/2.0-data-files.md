# 2.0 external time-series and user rainfall data

`TimeSeriesData` and `RainfallData` read and edit external data independently of Model/INP parsing. Reading a Model creates references without opening targets. Explicit `check_files(model)` inspects supported resource formats.

## Time-series documents

```python
from dataclasses import replace
from easysewer.io.timeseries import TimeSeriesData

data = TimeSeriesData.read("inflow.dat", encoding="utf-8")
data.report.raise_for_errors()
edited = replace(data, points=tuple(
    replace(point, value=point.value * 1.2) for point in data.points
))
edited.write("inflow-edited.dat")
```

The immutable `points` tuple uses the existing `SeriesPoint` value type. A
`timedelta` is elapsed time from the full simulation start, including its time
of day; a local `datetime` is an explicit calendar timestamp. Decimal hours,
negative elapsed hours, over-24-hour clocks, dated rows and omitted-date
continuations are supported. There is one value per physical line. Blank lines
and semicolon comment lines are retained in unchanged source bytes.

The supported grammar is `time value` or `date time value`, with ASCII whitespace
separators. Dates use month/day/year or the accepted three-letter month form.
After an explicit date, omitted dates continue that recorded calendar day;
an over-24-hour clock does not itself replace that day. Calendar output writes an
explicit date on each row. Fractional clock seconds follow native truncation and
produce a diagnostic; canonical output uses decimal hours for microsecond values.

The native external reader scans at most three tokens. Extra columns after a
dated row are preserved with a warning and omitted during normalization. An
inline comment after a two-column row changes the native field count and is
rejected. Repeated/decreasing times, empty data, invalid dates and nonfinite
numbers are errors. A physical row supports up to 1,022 encoded bytes, excluding
its LF or CRLF ending. Complete final rows need no newline. The checked reader
has no separate 49-byte token limit; comment lines use the same row boundary.
NUL, SUB, embedded CR, BOMs and non-ASCII numeric tokens are rejected.

### Relative prefixes and native rewind

A relative prefix is anchored at the full simulation start each time the
checked reader rewinds. Explicit dates change the continuation day for following
rows. The original prefix is therefore stable across preflight, initialization
and later lookups, including lookups after EOF.

To materialize timestamps independently of a model's simulation start:

```python
resolved = data.resolved(model.effective_options.start)
resolved.write("inflow-calendar.dat")
```

This returns a new document with calendar timestamps and checks the resulting
chronology. For the same simulation start it preserves the checked reader's
interpretation. It does not silently rewrite the original file.
All-relative files remain relative unless this explicit operation is requested.

### Materializing a file into Model

```python
from easysewer.io.timeseries import TimeSeriesData
from easysewer.model import Model

model = Model.from_inp("network.inp", strict=True)
reference = model.timeseries["Inflow"].file
data = TimeSeriesData.read(reference.resolve())
model.timeseries.replace("Inflow", data.as_inline("Inflow"))
model.validate(for_run=True).raise_for_errors()
model.to_inp("network-inline.inp")
```

`as_inline(id, start=...)` optionally resolves relative timestamps before creating
an `InlineTimeSeries`. Replacement retains the resource ID, so known consumers
continue to reference it. The usual transaction/reference/source constraints
apply. Its dimensional conversion then uses existing consumer declarations;
the original external file remains unchanged. Supplying a start makes relative
timestamps independent of later changes to the model's start time.

### Backend qualification

Parsing and editing a document do not load a native library. An external series
requires `easysewer:timeseries-io:1` for execution. `check_files(model)` validates
its syntax and chronology but leaves this capability pending. Pass explicit
`backend_capabilities` to resolve it; Runner uses the selected backend's probe.
An engine version or an exported marker alone does not establish qualification.
See [native time-series I/O](2.0-native-io.md) for cursor and error behavior.

## User-prepared rainfall

```python
from easysewer.io.rainfall import RainfallData

rain = RainfallData.read("rain.dat")
station = rain.station_series("Station01")
rain.write("rain-copy.dat")
```

`RainfallData.readings` contains immutable `RainfallReading(station, time, value,
record_date=None)` values. Multiple stations may be interleaved; each station's
times must increase strictly, and station matching uses ASCII case folding.
The file grammar is `station year month day hour minute value`. Rain form,
recording interval and IN/MM units remain properties of the consuming gage;
the document does not infer or convert them. Values may represent intensity,
volume or cumulative depth, including resets in the cumulative form.

Native format detection requires a data row within the first five physical
lines. Timestamps have whole-minute precision. Extended clocks such as `24:00`
are supported with an explicit `record_date`: the effective time is on the next
day, but native file-start-date filtering still uses the original record day.
Canonical writing preserves that distinction. The optional `start_date` of
`station_series()` uses the same record-date filter.

Parsing retains finite recorded values; physical preflight rejects negative
selected rainfall and single-precision overflow. It checks the selected station
and file start date, and reports form/units, record count and time range. For
external time-series rainfall, it additionally checks the gage interval against
the shortest sample interval and negative values for used consumers. General
time-series values can be negative, including temperatures and non-rainfall
resources. Unused rain gages are distinguished from known active consumers.

## Source bytes, encoding and validation boundaries

Unchanged `to_bytes()` returns the original immutable source bytes. Explicit
normalization or editing produces canonical data rows; original comments and
ignored trailing columns are not carried into that canonical representation.
`dataclasses.replace()` resets source provenance. Atomic `write()` encodes and
validates before replacement, preserving an existing target on failure.

Use an explicit BOM-free ASCII-compatible encoding. UTF-8 is the default;
strict decoding also supports specified legacy encodings. NUL, DOS EOF markers,
embedded bare CR, oversized native physical rows and scanner tokens are rejected.
Non-ASCII whitespace is not silently treated as a native token separator.

`check_files` remains read-only and uses an explicit byte budget. Its `complete`
flag means all implemented required input checks completed without warnings;
it does not prove all Model physics, a native backend or runtime output ownership.
Valid external time-series inspection shares the editable document parser and
sequence rules, but retains only endpoints, the minimum interval, sign facts and
diagnostics instead of complete point and interval collections. Mixed elapsed/
calendar timestamps are checked at their simulation-origin boundary. Invalid
sequence or resolution cases use full document validation to preserve complete
diagnostic paths and error precedence. Source bytes and decoded text still
occupy memory, and warning storage grows with the number of warnings; this is
not a constant-memory file reader. Editable `TimeSeriesData` still retains all
points. Inspections are not cached across consumers or file changes.
Unrecognized future rainfall formats remain visible as
`unsupported`. [HOTSTART state](2.0-hotstart.md) now has complete document
read/write and explicit manifests; [RUNOFF/RDII caches](2.0-runoff-cache.md)
also support full data documents and asserted identities. See
[interface files and preflight](2.0-files.md) for the complete status matrix.

## Validation and limits

The grammar follows SWMM 5.2 manual sections 11.3 and 11.6 (printed pages 192–193
and 195–196). Date-state behavior is checked against official v5.2.4
[input.c](https://github.com/USEPA/Stormwater-Management-Model/blob/v5.2.4/src/solver/input.c),
[table.c](https://github.com/USEPA/Stormwater-Management-Model/blob/v5.2.4/src/solver/table.c),
[datetime.c](https://github.com/USEPA/Stormwater-Management-Model/blob/v5.2.4/src/solver/datetime.c)
and [rain.c](https://github.com/USEPA/Stormwater-Management-Model/blob/v5.2.4/src/solver/rain.c).

Native tests compare actual file-based results with canonical files and inline
Model series, prove the mixed-date rewind difference, and verify independent
literal-data edits. Six US/SI and intensity/volume/cumulative rainfall cases
retain full hydraulic/system histories after canonical rewriting. A separate
extended-clock test proves that dropping the original record date would change
the native rainfall selection. These checks use the bundled engine reporting
version 52004; broader platform and native provenance gates remain open.
