# Candidate climate model

`Model.climate` spans TEMPERATURE, EVAPORATION and global ADJUSTMENTS. Source configuration is distinct from `effective_climate`, which resolves fixed-profile defaults without adding input rows.

For editable external climate file contents and preflight of all four native
formats, see [climate data documents](2.0-climate-data.md).

```python
from datetime import timedelta
from easysewer.model import Model, Ref
from easysewer.model.climate import (
    SeriesTemperature, MonthlyWindSpeeds, Evaporation,
    ConstantEvaporation, ClimateAdjustments, MonthlyTemperatureChanges,
)
from easysewer.model.resources import InlineTimeSeries, SeriesPoint

model = Model()  # default CFS / US units
model.timeseries.add(InlineTimeSeries(id="Air", points=(
    SeriesPoint(time=timedelta(), value=-10),
    SeriesPoint(time=timedelta(hours=24), value=40),
)))
model.update_climate(
    temperature=SeriesTemperature(series=Ref(collection="swmm:timeseries", key="Air")),
    wind=MonthlyWindSpeeds(values=(10.0,) * 12),
    evaporation=Evaporation(source=ConstantEvaporation(rate=.2), dry_only=True),
    adjustments=ClimateAdjustments(
        temperature=MonthlyTemperatureChanges(values=(9.0,) * 12)),
)
model.timeseries.rename("Air", "AirTemperature")
model.convert_units("CMS")
document = model.to_document()
```

This is a climate-editing example. A runnable project also needs its network,
analysis period and applicable hydrology. Temperature series allow negative values;
their consumer declaration supplies the temperature dimension independently of
other series used for stage, rainfall or evaporation.

## Supported configuration

| Setting | Candidate representation |
| --- | --- |
| Air temperature | `SeriesTemperature(series)` or `FileTemperature()` |
| Shared climate file | `ClimateFile(file=FileReference(...), start_date=None, units=None)`; C10/C/F labels |
| Wind | `MonthlyWindSpeeds(values=12 values)` or `FileWind()` |
| Snowmelt climate | `Snowmelt(snowfall_temperature, antecedent_weight, negative_melt_ratio, elevation, latitude, solar_time_correction)` |
| Snow area depletion | Separate impervious/pervious `ArealDepletion(fractions=10 values)` |
| Potential evaporation | `ConstantEvaporation`, `MonthlyEvaporation`, `SeriesEvaporation`, `TemperatureEvaporation`, `FileEvaporation` |
| Evaporation auxiliaries | Independent optional MONTHLY recovery-pattern reference and `dry_only` flag |
| Global adjustments | Additive temperature/evaporation and multiplicative rainfall/conductivity monthly values |
| Local adjustments | `SubcatchmentAdjustments` with typed target and MONTHLY pattern references for INFIL, DSTORE and N-PERV |

Constructors are keyword-only. Monthly records contain exactly twelve finite
numbers; ADC records contain ten fractions in [0, 1]. Structural validation
preserves physical drafts such as negative evaporation rates; implemented run
checks reject negative constant/monthly/inline-series evaporation, monthly wind
and pan coefficients. This is not exhaustive physical validation, including every
combination with monthly adjustments or external values.

The shared file and active temperature source are independent. A file can supply
wind/evaporation while a series supplies air temperature. Native FILE and
TIMESERIES assignments select the last active temperature source; normalized
output emits the shared FILE first and an active TIMESERIES second. Neither source
selection clears unrelated time series. Recovery and DRY_ONLY do not replace the
selected evaporation source.

The fixed profile supplies ambient 70 F, snowfall threshold 34 F, antecedent weight
0.5, negative melt ratio 0.6, elevation 0, latitude 40 degrees and solar correction
0 minutes. Missing wind/evaporation are zero; missing ADC/pan/multiplier values are
one. Omitted file start date resolves to the simulation start date. Explicit
absence, explicit zero and effective defaults remain separate. Nonpositive global
conductivity factors remain in the source model, with a warning; their effective
values are one, following the engine.

## References, units and source preservation

Temperature and evaporation series declare different dimensions. Conflicting
shared uses fail validation and conversion. References participate in rename,
deletion protection and graph transactions. Recovery and local adjustment patterns
must have MONTHLY purpose. General factors remain dimensionless.

Absolute temperatures use affine F/C conversion; monthly temperature *changes* use
only 5/9 or 9/5. Evaporation uses in/day versus mm/day, wind mph versus km/h, and
snowmelt elevation ft versus m. Latitude and solar correction remain unchanged.
The engine profile uses its 1.608 wind factor; physical conversion uses physical
definitions. ADC values do not change with units.

Climate-file import does not read external data. `FileReference` retains its source
directory; exports rebase the path in a copy. File formats differ in temperature,
evaporation and wind interpretation, so changing between US and SI with a climate
file fails atomically. An explicit C10/C/F label alone does not prove the external
data can remain unchanged. Changes within one unit system remain supported.

Unchanged valid source preserves its original text, including superseded rows.
Editing the climate feature regenerates its owned rows in valid assignment order.
Invalid or unsupported global rows leave the entire global climate group
source-owned, avoiding a partially recognized configuration. Local adjustment rows
are grouped independently by subcatchment. Even superseded native TIMESERIES and
RECOVERY references must exist in a preserved executable document; validation
requires repair or explicit normalization when they do not.

## Fixed SWMM 5.2.4 differences

The manual and tagged engine disagree in several places:

- Bare `EVAPORATION FILE` is documented but triggers native ERROR 203. Import
  preserves it with a warning; `for_run` rejects the preserved syntax. Explicit
  normalization emits twelve default pan coefficients and is verified to run.
- The default GHCN units label is F for US models and C for SI models, rather than
  the manual's C10. The default file date follows simulation start, rather than
  the first file record. Missing daily values retain the previous available value.
- Native default latitude is 40 rather than the manual's 50. Explicit resolved
  defaults reproduce the implicit temperature, evaporation and snow histories.
- User-prepared weather files ignore the C10/C/F label. Their temperatures and
  evaporation use the model unit system, but wind is read as mph even in SI. A
  rain-on-snow comparison verifies this against equivalent monthly wind inputs.
- Temperature-derived evaporation needs active file temperatures. A later air
  temperature series disables the daily temperature calculation while native
  still accepts the evaporation mode. Run validation rejects that combination;
  comparisons demonstrate that native otherwise uses the file's evaporation data.
- Without subcatchments, native OUT does not update climate fields through the
  runoff-output path and the climate file can remain open after end/close. A
  document-level warning identifies this case. Current backends isolate each session in a worker; checked stream cleanup is described in [native I/O](2.0-native-io.md).

## Validation and limits

Structured tests cover source alternatives, repeated assignments, file rebasing,
dimensions, defaults, references, invalid drafts and atomic failures. Native tests
compare reconstructed model output with source runs, including full hydraulic
histories, mass balance and OUT climate/snow/runoff series. Five evaporation modes
run in US and SI; GHCN fixtures cover omitted/F/C/C10 labels in both systems.
Temperature-series conversion covers all six flow units. Rainfall adjustments,
DRY_ONLY, soil recovery, conductivity, wind and ADC also have active-effect checks.

Local adjustments resolve to typed catchments and are written with their owning catchment declarations, avoiding native initialization resetting pattern references. Missing targets fail explicitly.
