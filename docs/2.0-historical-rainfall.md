# Candidate historical rainfall documents

`HistoricalRainfallData` reads, edits and writes the eight historical formats accepted by the SWMM rainfall reader. It complements USER `RainfallData`; file references remain separate from contents.

| Format | Native interval and amount |
| --- | --- |
| NWS_TAPE | HPCP: hourly; QPCP/QGAG: 15 minutes; integer hundredths inch |
| NWS_SPACE_DELIMITED | Same elements; optional station name; fixed native group columns despite the format name |
| NWS_COMMA_DELIMITED | Same elements, comma groups; no station-name layout in the native data reader |
| NWS_ONLINE_60 | HPCP header, hourly; integer hundredths or decimal inches |
| NWS_ONLINE_15 | QPCP header, 15 minutes; integer hundredths or decimal inches |
| AES_HLY | Element 123, hourly, tenths mm; three-digit year |
| CMC_HLY | Element 123, hourly, tenths mm; four-digit year |
| CMC_FIF | Element 159, 15 minutes, tenths mm; 96 daily slots |

```python
from dataclasses import replace
from easysewer.io.historical_rainfall import HistoricalRainfallData

rain = HistoricalRainfallData.read("archive.dat")
rain.report.raise_for_errors()
edited = replace(rain, records=tuple(
    replace(record, observations=tuple(
        replace(value, value=200)
        if value.hour == 3 and value.minute == 0 else value
        for value in record.observations
    )) for record in rain.records
))
edited.write("archive-edited.dat")
```

The example changes the source amount field; interpret its units and flags using
the table and rules below. It does not erase a missing or accumulated condition.

## Raw records and source bytes

`ArchiveRainfallRecord` contains `station`, `date`, `element`, immutable
`observations`, and NWS header metadata (`division`, `units_code`, `record_type`,
optional `station_name`). `ArchiveRainfallObservation` contains `hour`, `minute`,
`value`, `condition`, `quality`, and `decimal_inches`. Canadian clocks are fixed
by daily slot position. Decimal-inch tokens are only available in online files;
all other raw amounts are integers.

Unchanged `to_bytes()` returns original bytes. Editing or `normalize=True`
recreates the same physical format, including conditions, quality codes and
station metadata. Inactive header lines, original spacing, unused online suffixes
and Canadian trailing text are not canonical layout. Ignored trailing text and
an inconsistent NWS tape count are diagnosed; the canonical count is derived
from the actual groups. Canonical files are reparsed before an atomic replacement
and must preserve all document records. A failure leaves an existing target intact.

Format detection examines at most five physical lines. Online data additionally
requires an HPCP/QPCP heading on the first physical line and consistent date/value
columns. The ASCII layout must fit the native line buffer. Invalid dates, month
or day order, truncated daily slots, malformed amounts, unsafe integer widths,
BOM/encoding problems and ambiguous scanner fields are rejected. Numeric quality
codes next to space-padded values in Canadian/tape files can be consumed as part
of the amount by C `sscanf`; these ambiguous source rows are rejected instead of
being silently interpreted as a different depth. Canonical adjacent fields use
zero-padded numbers. Interspersed malformed records are not silently discarded.
Final NWS condition/quality codes may be omitted. Hour 25 or greater terminates
the current native row; that marker and subsequent groups remain in the document
with a warning instead of becoming rainfall intervals.

The parser accepts the documented station-name variant for the NWS space format.
The native comma data reader has no corresponding date offset for a station name;
that variant is not advertised as a usable archive format. Canadian non-rainfall
elements can follow a recognized rainfall first row, remain visible records and
are omitted only from the explicitly interpreted rainfall view.

## Effective rainfall intervals

```python
from datetime import date

view = rain.interpret(start_date=date(2020, 1, 30), max_periods=1_000_000)
view.report.raise_for_errors()
for period in view.periods:
    print(period.time, period.depth_inches, period.status, period.saved)
```

The result is `InterpretedRainfall(interval, periods, report)`. Each
`RainfallInterval` includes interval start `time`, original `record_date`, inch
depth or `None`, status, native-cache `saved` flag and source station. A status
of `missing` or `deleted` is distinct from an observed zero. Zero and negative
historical readings are not saved into the native cache; negative amounts have
a warning. Missing/deleted readings are also absent from that cache.

Native archive readers use interval-end timestamps. Canadian first slots are
labelled 00:00 internally and therefore start on the preceding day at 23:00 or
23:45. Date filters apply to the original record day, before that shift.
Online 00:xx is expressed by the reader as 24:xx of the previous day, with the
same resulting interval start. Multiple stations are consumed together; the
gage's station string does not filter an archive as it does a USER file. The
format overrides the gage's interval and supplies its own volume/units rules.

NWS `a` opens an accumulated period; `A` spreads its total evenly across all
inclusive intervals. A missing total of exactly 99999 increments missing
periods and leaves the anchor active in the native reader; later end markers
can still use it. An unanchored end is ignored with a diagnostic. Repeated starts,
unfinished accumulations and truncated fractional interval counts are visible.
Expansion is bounded by `max_periods`, and duplicate/decreasing saved timestamps
are rejected before producing a corrupt native cache.

The native reader calls `setCondition` for every reading. `{`, `}`, `[`, `]`,
and `M` mark those individual observations missing/deleted; blank intermediate
conditions reset the state rather than inheriting the opening bracket. In the
space format a blank condition can promote the following quality code into the
condition because `scanf` skips whitespace. Other NWS second quality codes are
not filters. Canadian quality flags are ignored; only value -99999 marks missing.
These behaviors are modeled explicitly and checked against actual caches.

## Float arithmetic and explicit USER materialization

`interpret` defaults to `arithmetic="reference"`, using rounded float division
following the reference source expressions. `arithmetic="float32_reciprocal_100"`
uses a float reciprocal for the constant division by 100. The pinned standard
build `easysewer:standard:5.2.4:12` disables fast-math and matches `reference` in
the verified NWS cases. The previous Windows 52004 binary matched the reciprocal
variant; its precise original compiler options remain unproven. The two methods
can differ by 1 ULP (for example, 60 hundredths produces approximately
0.600000024 versus 0.599999964 inches).
Version 52004 alone is not a guarantee that another binary uses the same method.
No native library is loaded implicitly to guess an arithmetic policy.
The current known standard revision 16 continues to declare `reference` through
its hash-bound backend identity; see [backend provenance](2.0-backend.md).
The revision 12 observations above remain the record of that arithmetic comparison.

```python
user = rain.as_user(
    station="Archive", start_date=date(2020, 1, 30),
    missing="omit", arithmetic="reference",
)
user.write("archive-user.dat")
```

The new file represents saved interval depths. Bind it as **VOLUME, IN**, using
`rain.interval`, and clear file date filters: filtering already happened before
materialization, and output dates now describe interval starts. Original record
dates, flags and station identities are not USER file fields. Missing/deleted
data requires explicit `missing="omit"`; the default rejects it. Conversion
diagnostics are carried onto the returned `RainfallData`. It does not modify the
Model or select a path automatically. Report observation counts/metadata can
differ after materialization even when the hydraulic and system time series agree.

## Preflight, tests and remaining work

`check_files` recognizes all eight archive formats before attempting USER syntax.
It validates selected dates, effective cache chronology, nonempty saved data,
and expansion limits, and reports the format's actual interval, inch volume
basis, record count and effective date range. Missing data, ignored flags, mixed
stations/elements and ambiguous accumulation conditions remain visible warnings.
Unrecognized future formats still report `unsupported`.

Tests use actual native SAVE RAINFALL files, independently decode the binary
cache and compare its timestamps and float values exactly for the selected
arithmetic policy. All eight formats are checked under US and SI models against
independent USER literals, with positive runoff, unchanged canonical results,
and actual runoff changes after edits. Additional cases cover fifteen-minute
QPCP/QGAG, accumulation/deletion/missing rules, station merging, date filters,
three-digit year rollover, decimal rounding and space-format flag promotion.

The basis is SWMM 5.2 manual section 11.3 (printed pages 192–193) and official
[rain.c v5.2.4](https://github.com/USEPA/Stormwater-Management-Model/blob/v5.2.4/src/solver/rain.c),
checked against the bundled Windows library. [HOTSTART state documents and
explicit manifests](2.0-hotstart.md) and [RUNOFF/RDII documents and manifests](2.0-runoff-cache.md) are implemented.
[Runner](2.0-runner.md), [result archives](2.0-result-archive.md) and
[captured production conditions](2.0-cache-conditions.md) describe execution,
storage and the supported reuse comparisons. Producer evidence records its
origin and comparison scope; it is inspectable data without a signed attestation.
Unstructured target-layout dependencies, remaining domain acceptance and final
cross-platform/native provenance release gates remain open.
