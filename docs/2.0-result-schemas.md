# RunResult archive schemas

The ten `result-archive-1.x.schema.json` files describe the structure of the
`result.json` envelope for each readable archive version, using JSON Schema
Draft 2020-12. They cover the closed typed records, primitive values, tagged
tuples and sets, blob references, compact report sources and versioned fields.
The envelope's `schema_version` selects the matching file.

For example, a file-only archive written by the current runtime uses
[1.3](result-archive-1.3.schema.json); a mixed file/directory resource graph uses
[1.9](result-archive-1.9.schema.json). The generator follows the codec's explicit
record declarations and rejects unregistered dataclass fields. Version rules
remain explicit, so newer directory fields cannot be accepted under an older
envelope merely by changing its version string.

## Validation boundary

Schema validation checks JSON structure. Always use `RunResult.load` to verify
an actual archive. The loader additionally checks:

- Blob files, complete byte counts and SHA-256 digests, duplicate digest keys,
  missing or extra content and source-backed report decoding.
- Artifact ownership, snapshot identity, cache bindings, completion flags and
  consistency across related records.
- Calendar strings using Python's ISO parser, normalized values, nested payload
  schemas, duplicate JSON keys and the codec's nesting limit.
- Exact Python scalar types. JSON Schema considers `1.0` an integer; the runtime
  can reject it where a field requires an actual Python `int`.

The schemas do not read original paths or blobs, run a solver, establish the
producer's authenticity or prove hydraulic accuracy. An unchanged manifest can
still pass a schema after a blob is corrupted; the regression test demonstrates
that `RunResult.load` rejects that archive.

## Development checks

From the repository root:

```powershell
python tools/build_result_schemas.py --check
python tools/qualify_result_schemas.py --validator-path PATH_TO_JSONSCHEMA_PACKAGES --destination NEW_EVIDENCE_DIRECTORY
```

The second command uses a development installation of `jsonschema`; it is not a
new EasySewer runtime dependency. The destination must not exist. Schema files,
both tools and the regression test are included in the source distribution
manifest.
