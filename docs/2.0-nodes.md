# Candidate storage and divider nodes

`easysewer.model.Model.nodes` now reads and writes JUNCTIONS, OUTFALLS, STORAGE
and DIVIDERS through the same ordered, referenced graph. This increment completes
the storage/divider positional codecs; it does not declare the entire 2.0 runtime
or every network preflight check complete.

```python
from easysewer.model import Model
from easysewer.model.network import Storage, ConicalStorage, Seepage

model = Model()
model.nodes.add(Storage(
    id="Tank", elevation=10, max_depth=5, initial_depth=1,
    shape=ConicalStorage(base_major_axis=20, base_minor_axis=10, side_slope=1),
    surcharge_depth=.5, evaporation_fraction=.7,
    seepage=Seepage(suction=3, conductivity=.2, initial_deficit=.3),
))
```

The example uses the default CFS context: hydraulic lengths are feet and the
seepage suction/conductivity use inches and inches/hour. Add the rest of the
network and analysis settings before requesting run validation.

## Storage variants and optional fields

| Type | Parameters |
| --- | --- |
| `FunctionalStorage` | coefficient, exponent, constant in `area = constant + coefficient * depth**exponent` |
| `TabularStorage` | `Ref` to a shared STORAGE depth/area curve |
| `CylindricalStorage` | major and minor axis lengths |
| `ConicalStorage` | base major/minor axes and side slope (run/rise) |
| `ParaboloidStorage` | major/minor axes at full height, plus that full height |
| `PyramidalStorage` | base length/width and side slope (run/rise) |

The optional field following the shape is **surcharge depth**, not ponded area.
The early candidate `Storage.ponded_area` field has been replaced accordingly.
The evaporation fraction follows it. `seepage=None` means no seepage assignment;
`ConstantSeepage(conductivity=...)` uses the native single-Ksat syntax, while
`Seepage(suction=..., conductivity=..., initial_deficit=...)` retains the three
Green-Ampt parameters. Zero conductivity is distinct from absent input.

Omitted optional values remain `None`. Writers insert zero only when a later
positional value requires an interior placeholder. Functional coefficients have
units of area divided by depth to the exponent; conversion uses a registered
type-specific rule and fails transactionally if the result exceeds finite
precision. Slopes, exponents and moisture fractions are not lengths.

The fixed 5.2.4 reader accepts **PARABOLIC**, although the user manual and the
native enum call the shape PARABOLOID. The domain type remains
`ParaboloidStorage`. The codec accepts both spellings, preserves untouched source,
and writes the actual native keyword. Source using the manual spelling receives
a diagnostic; `validate(for_run=True, normalize=True)` and
`to_inp(..., normalize=True)` explicitly select the corrected projection.

The cylindrical third shape slot must be nonnegative but is unused by native
SWMM. A nonzero value is diagnosed, retained in untouched source and normalized
to zero. Unknown variants, incomplete seepage triplets, duplicate IDs and invalid
fields remain unclaimed source with diagnostics rather than disappearing.

## Divider rules and graph checks

`Divider.diverted_link` references a link; `None` writes the native `*` placeholder
but fails run validation. Laws are `OverflowDivider`, `CutoffDivider(cutoff_flow)`,
`TabularDivider(curve)` and `WeirDivider(minimum_flow, height, coefficient)`.
The last four optional fields are maximum depth, initial depth, surcharge depth
and ponded area, with distinct omission states.

Tabular laws use DIVERSION flow/flow curves. Shared storage/diversion curves
participate in purpose checking, rename propagation and deletion checks, and are
converted once regardless of consumer count. A divider weir's coefficient has
units of flow divided by height**1.5; it is not the coefficient of a link weir
with a separate crest width.

Run checks verify the diverted link is attached, and for active division that it
leaves the node. Steady/kinematic routing permits at most two outgoing links;
incomplete pairs are diagnosed. Dynamic wave uses ordinary junction behavior,
so the diversion law is marked inactive. Native full-weir flow is `C * H**1.5`;
minimum flow above it is rejected and an equal endpoint is diagnosed.

## Native numerical and ordering limits

The implementation follows the fixed engine, including these observed limits:

- The engine's SI volume factor `.02832` differs from `.3048**3`. Dimensional
  storage conversion therefore preserves geometry, but cannot simultaneously
  preserve both native area and volume. Tests verify the resulting volume ratio
  analytically; the API does not claim identical cross-system storage hydrographs.
- For analytical storage seepage, the tagged initializer uses the bottom-area
  coefficient without the SI area conversion used for tabular storage. Equivalent
  rectangular functional/tabular examples match in CFS but differ in CMS when
  seepage depends on moisture/depth. This is diagnosed, not silently compensated
  by changing shape or soil data.
- That initializer has no PARABOLOID branch for seepage areas. Positive-conductivity
  paraboloid seepage is representable and writable, but run validation rejects
  the unsafe native combination. Zero-conductivity input remains supported.
- Nonlinear storage inversion in steady/kinematic routing passes a storage index
  to a node-indexed evaluator. Some layouts therefore depend on node declaration
  order. The model diagnoses affected layouts and preserves source/model identity
  order during normalization, renaming and unrelated edits; it does not silently
  regroup storage nodes and change the engine result.
- Kinematic routing has a `.001` normalized-area Newton stopping tolerance.
  Independent one-ULP inflow perturbations reproduce visible trajectory changes
  in the low-flow fixtures. Unit-converted steady/dynamic runs meet strict
  numerical comparisons; the kinematic comparison uses circular area reconstructed
  from depth, normalized flow and a corresponding continuity bound. This is a weaker
  engine-equivalence claim and is recorded separately.

These limitations are engine/profile findings, not reasons to replace the source
or silently change the user's geometry. Additional profile physical/default and
whole-network checks remain part of the ongoing runtime migration.

## Writer order as an extension contract

`encode()` order is retained, including repeated transitions between sections.
The generic renderer no longer groups non-contiguous rows by section. A feature
may declare `FeatureDescriptor.ordered_sections` for identity-bearing records.
When their identities/order change, its owned rows regenerate as a unit; ordinary
parameter-only changes still patch their existing rows. This avoids assigning a
new native index just because an object was renamed or changed node kind.

The network writer emits node and link declarations in collection order, then
their coordinates, sections, losses and vertices. Keeping auxiliary records in
separate passes avoids a header for every associated record while retaining the
meaningful identity order. Independent source comments remain preserved.

## Validation and limits

Tests compare 168 storage shape/option/unit-system/routing combinations, including
single-Ksat, complete Green-Ampt and explicit-zero forms, against fresh typed
models. Positive paraboloid seepage is excluded from native execution and tested
as a preflight error. Source and rewritten runs have identical initial states,
complete depth/volume/flow/overflow histories and mass balances.

Divider tests cover all four laws under three routing modes, all six flow units,
full-weir coefficient conversion, shared curve conversion, source/default forms,
and dynamic-wave equivalence to a junction. Further tests reproduce the manual
keyword error, surcharge-depth semantics, storage volume factors, seepage-area
difference, and multiple-storage ordering sensitivity.
