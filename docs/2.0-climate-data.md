# Candidate climate data documents

`ClimateData` reads, edits and writes USER_PREPARED, GHCND TEXT, TD3200 (DS-3200/3210), and Canadian DLY0204 files. It is independent of Model file references; reading an INP does not open external files.

```python
from dataclasses import replace
from easysewer.io.climate_data import ClimateData

weather = ClimateData.read("weather.dat")
weather.report.raise_for_errors()
edited = replace(weather, records=tuple(
    replace(record, observations=tuple(
        replace(value, value=value.value * 2)
        if value.parameter == "EVAP" and value.value is not None else value
        for value in record.observations
    )) for record in weather.records
))
edited.write("weather-edited.dat")
```

For integer monthly formats this example is valid only when the doubled
magnitude fits the five-digit field. A write fails before replacing the target
if a value cannot be represented exactly.

## Records, missing values and source fidelity

`ClimateData(format, records)` contains an immutable tuple of `ClimateRecord`
objects. A record contains `station`, `date`, `observations`, a monthly
`parameter` (also retained for zero-count TD3200 rows), an optional
TD3200 `units_code`, and GHCND `extra_fields` as `(column_name, text)` pairs.
Daily records use their observation date; monthly records use the first day of
the month and preserve their original physical row order.

Each `ClimateObservation` holds `parameter`, `value`, and optional monthly
`day`, `sign`, `time_code`, `measurement_flag`, and `quality_flag`. Daily values
are signed numbers in the source file's units. Monthly values are unsigned
integer magnitudes with a separate sign. `None` means missing; it is distinct
from a recorded zero or a nonmissing value rejected by a native quality flag.
TD3200 station metadata occupies eight characters (station plus division);
DLY0204 uses seven. These identifiers do not select a station in SWMM.

Unchanged documents return their original bytes, including CRLF/LF, spacing,
headers and ignored columns. `normalize=True` or `dataclasses.replace` writes
canonical native records. Monthly flags/time/sign/units metadata and GHCND
quality suffixes/extra columns survive canonical writing. USER trailing extra
columns and monthly trailing text are diagnosed and omitted in canonical output.
GHCND missing sentinels and DLY blank missing slots normalize to canonical
sentinels. Ordinary formatting and separator lines are not retained after edits.

The first physical line must identify the format. Month order must not go
backwards. Daily rows within a month can be unordered or repeated: the last
nonmissing value for each variable/day wins. Multiple stations are retained with
a warning because the engine merges their observations into those same slots.
Invalid calendar dates, malformed numbers, nonfinite values, native buffer
overflow, BOMs and unsafe encodings are rejected. Fixed-column files require
ASCII byte columns; USER also supports explicitly selected ASCII-compatible
legacy encodings. GHCND numeric output must fit its eight-character scan width
without rounding; a value requiring more precision is rejected.
A complete final row needs no newline. USER station identifiers may exceed
79 bytes within the 1022-byte physical-line limit. Native execution requires
the qualified [climate I/O capability](2.0-native-io.md); pure parsing and
round-trip writing do not load a native library.

## Native units and flags

| Format | Temperature | Evaporation | Wind and flags |
| --- | --- | --- | --- |
| USER_PREPARED | Project F/C | Project inches/day or mm/day | Native wind is **mph even in SI**; `*` means missing |
| GHCND C10 | Tenths C | Tenths mm/day | AWND tenths m/s; WDMV km/day |
| GHCND C | C | mm/day | AWND m/s; WDMV km/day |
| GHCND F | F | inches/day | AWND mph; WDMV miles/day |
| TD3200 | F | Hundredths inch/day | WDMV miles/day; only quality flag 0/1 is consumed, 99999 is missing; AWND is ignored |
| DLY0204 | Tenths C | Tenths mm/day | No wind channel; 99999/blank is missing; native ignores quality codes and the evaporation sign |

GHCND selects WDMV whenever that column exists, even if a particular day's WDMV
is missing and AWND is present. Its quality suffixes are preserved, but the
native climate reader does not apply them. Magnitudes of 9999 or greater are
missing. Unused monthly parameters remain explicit records and have a diagnostic.
DLY records for unused parameters can follow a recognized first row; an unknown
parameter alone does not establish the native format. Calendar padding slots
beyond the actual month length remain in monthly records but are not daily data.

The manual describes USER wind as km/h in SI projects. The bundled 5.2.4 engine
uses mph on this path; the inspector reports that discrepancy when wind is used.
GHCND wind conversion uses the engine's factor 0.62137, independently of Model
monthly-wind conversions. TD3200/DLY and USER ignore the GHCND C10/C/F label.

## Explicit interpretation and conversion

```python
from datetime import date

days = weather.daily(unit_system="SI", ghcnd_units="C10")
user_file = weather.as_user(unit_system="SI", ghcnd_units="C10")
user_file.write("weather-user-si.dat")
trajectory = tuple(weather.trajectory(
    start=date(2020, 1, 30), days=4,
    unit_system="SI", ghcnd_units="C10",
))
```

`daily` returns `ClimateDay(date, maximum, minimum, evaporation, wind)` values
with `None` still marking absent observations. Temperatures/evaporation use the
supplied project system; wind is always mph. GHCND requires an explicit C10/C/F
label. For USER input, `unit_system` declares its existing temperature and
evaporation units; changing this argument does not convert a USER file.

`as_user` explicitly materializes effective daily observations in USER format.
It merges stations and consumes monthly quality/sign rules; flags, station
identities and unused columns are consequently lost. It does not fill missing
days or mutate the source. Update the Model's `ClimateFile` reference explicitly
after writing. Model cross-system conversion with an external climate reference
remains guarded because external data transformation requires this extra step.

`trajectory` shows daily file values before monthly adjustments, temperature
interpolation or temperature-derived evaporation. The requested starting month
must actually occur in the file. Starting-day gaps use 70 F (or its C equivalent),
zero evaporation and zero wind, without looking backwards to earlier file days.
Later missing days/variables retain previous simulation-day values, including
across empty months. An explicit `ClimateFile.start_date` advances with elapsed
simulation days even when file and simulation calendars differ.

## Preflight and verification

`check_files(model)` now parses all four formats, checks the actual file start
month, and resolves units and consumers from `effective_climate`. It reports
missing/defaulted days and rejects consumed negative wind/evaporation or inverted
temperature ranges after carry-forward. It remains read-only and preserves the
existing byte budget and path checks. Warnings mean `complete=False`; file
validity is not a substitute for Model/backend/Runner validation.

Native tests compare canonical rewrites with original complete hydraulic,
temperature, evaporation, snow, runoff and mass-balance results. Independent
literal USER files verify US/SI conversions, all three GHCND labels, WDMV
precedence, monthly flags/signs, explicit starts, no-lookback initialization,
multi-station overwrites, year changes and leap days. Editing monthly evaporation
is checked against an independently changed file and changes actual results.

The qualified native reader closes climate handles on failed opens and repeated
close. Runner checks backend capabilities before execution and preserves prior
published results when climate reading or cleanup fails. Without backend
capabilities, file inspection reports execution qualification as pending.

The source basis is the SWMM 5.2 manual section 11.4 (printed page 193) and
the official tagged [climate.c](https://github.com/USEPA/Stormwater-Management-Model/blob/v5.2.4/src/solver/climate.c),
checked against the pinned 52004 sources and the identified EasySewer corrections.
The final platform release matrix remains open. Historical rainfall formats have a
[separate editable document](2.0-historical-rainfall.md), as does
[complete stored HOTSTART state](2.0-hotstart.md). The climate I/O guide separates
the completed stream behavior from remaining general time-series and checkpoint work.
