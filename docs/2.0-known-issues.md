# Known issues and follow-up work

## Intermittent Windows directory publication failures

Historical tests retain nine WinError 5 failures during directory publication or renaming. Independent retries passed. An open read handle can reproduce the blocking behavior, but the actual handle owner in those failures has not been identified. A complete fix has not been confirmed.

The native release qualification suite now includes packaged-backend directory
publication, checkpoint relocation and output-directory restore regressions.
The public CI workflow runs these checks on Windows and Linux; adding this
coverage, or passing it on Linux, does not confirm that the intermittent Windows
failure is fixed. See [testing and builds](2.0-testing.md) for qualification scope.

On failure, inspect RunResult status, retain the working directory and diagnostics, release conflicting handles, then explicitly retry. Do not use a failed result as a complete successful run. See [run recovery](2.0-run-recovery.md) for recovery and cleanup rules.

## Windows native working-directory encoding

The bundled solver resolves full paths through the process ANSI code page.
The Python worker launcher now tries an existing ASCII short-name alias for a
non-ASCII directory, after checking canonical location and filesystem identity.
This uses the same directory; it does not create an alias or move the workspace.
Windows checkpoint restore supplies relative names for its generated owned files.

If a usable alias is unavailable, an execution directory containing characters
that the code page cannot represent (for example, emoji on a non-UTF-8 setup)
still fails at native open with error 303. The native path buffer also limits full
paths to 4095 bytes. The original failure remains in the run result, with an
additional `run.native_path` hint for the qualified backend.

To publish results to an incompatible Unicode output directory, explicitly set
`Options.temp_directory` (`TEMPDIR`) to a shorter, representable writable path.
Runner captures and publishes Unicode paths through Python. The system temporary
directory may itself contain an incompatible username. Short-name aliases are
not guaranteed on NTFS and are unavailable on ReFS, so this is not universal
Unicode native-path support. An explicit `TEMPDIR` is never silently moved.
See [Runner](2.0-runner.md) for placement rules.

## Validation and accuracy limits

- The remaining 50 support-inventory sections and 317 variant groups need exhaustive per-item review. Historical gates also need revalidation when their bound source changes. See the [support inventory](2.0-support-matrix.md).
- KINWAVE flow fronts, short dry DYNWAVE conduits and spatial discretization accuracy need further study. Successful execution and a small continuity error do not automatically establish accurate local depth or arrival time.
- Standard 16/custom 14 include corrections for Modified Horton capacity, degenerate states and outfall gates. Historical experiments do not establish acceptance of every parameter combination.
- Follow-up work includes performance optimization, more browser/deployment environments, real projects and business-semantics review.
- Convenience APIs such as result durations remain future design work. Candidate proposals in the archive are not current public interfaces.

## Bad Image dialogs during tests

`broken.dll` is an intentionally invalid file used by native-load failure tests. Current native workers set the Windows error mode before loading, turning a bad library into an inspectable loading error without blocking automated tests on a system modal dialog. The regression is in `tests/test_native_windows_error_mode.py`.

Original failures, experiments and repair history remain in the [development archive](development-archive.md).
