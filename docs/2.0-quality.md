# Candidate pollutants and land uses

`Model` owns `pollutants`, `landuses`, `coverages`, `loadings`, `buildup` and `washoff`. Concentration and mass inflows use the separate inflow collections.

```python
from easysewer.model import Model, Ref
from easysewer.model.quality import (
    Pollutant, LandUse, Buildup, PowerBuildup, Washoff, EventMeanConcentration,
)

model = Model()
pollutant = Ref(collection="swmm:pollutants", key="TSS")
landuse = Ref(collection="swmm:landuses", key="Urban")
model.pollutants.add(Pollutant(
    id="TSS", units="MG/L", rainfall_concentration=0,
    groundwater_concentration=0, rdii_concentration=0, decay_rate=0,
))
model.landuses.add(LandUse(id="Urban"))
model.buildup.add(Buildup(
    landuse=landuse, pollutant=pollutant, normalizer="AREA",
    function=PowerBuildup(maximum=10, coefficient=2, exponent=1.2),
))
model.washoff.add(Washoff(
    landuse=landuse, pollutant=pollutant,
    function=EventMeanConcentration(concentration=30), bmp_removal=10,
))
model.convert_pollutant_units("TSS", "UG/L")
assert model.washoff[("Urban", "TSS")].function.concentration == 30000
```

This builds the quality graph; a runnable model also needs the drainage network,
hydrology, land-use coverages and analysis period.

## Records and native interpretation

Pollutant units are `MG/L`, `UG/L` or `#/L`, independent of the hydraulic unit
system. Rain, groundwater, RDII, optional DWF and initial concentrations are
nonnegative. Decay is per day and may be negative, which represents growth.
`snow_only` restricts ongoing surface accumulation when snow cover is absent;
it does not erase initial buildup calculated from `DRY_DAYS`.

Optional `co_pollutant` and `co_fraction` express additional runoff pollution.
The engine adds concentrations in native pollutant order and updates those
values in place. Chains and cycles therefore depend on order. Model/JSON/INP
preserve this order; explicitly moving pollutants can change results. Different
co-pollutant concentration units produce a warning because the engine performs
raw numeric addition, without an automatic units adjustment.

`LandUse` has optional `sweep_interval` (days), `sweep_availability` (0–1) and
`days_since_sweeping` (days). Zero interval disables sweeping. The candidate
requires nonnegative day values. If any sweeping field is supplied, INP needs
the complete triple; absent interior values are written as zero.

`Coverage(subcatchment, landuse, percent)` uses a `(subcatchment, landuse)` key.
Individual coverages and their total cannot exceed 100%. `InitialLoading`
uses `(subcatchment, pollutant)` and `mass_per_area`: lb/acre or kg/ha for mass
pollutants, counts/acre or counts/ha for count pollutants. Native initialization
uses positive loadings; a zero loading may fall back to antecedent `DRY_DAYS`
accumulation rather than forcing the initial mass to zero.

`Buildup` and `Washoff` use `(landuse, pollutant)` keys. Each owns a distinct
formula value, so adding a future formula does not add positional fields to
every existing formula.

| Buildup value | Parameters |
| --- | --- |
| `NoBuildup` | No parameters; the record uses default AREA |
| `PowerBuildup` | maximum, coefficient, exponent (zero or 0.01–10) |
| `ExponentialBuildup` | maximum, rate per day, unused third input parameter |
| `SaturationBuildup` | maximum, half-saturation days, unused second input parameter |
| `ExternalBuildup` | maximum, scale factor, time-series reference |

The normalizer is `AREA` or `CURBLENGTH`. Maximum and power coefficients use
project pollutant mass per normalizer; the coefficient also includes the
formula's time exponent. EXT series values are buildup mass per normalizer per
day. Count pollutants use counts instead of lb/kg. Curb length is a user-defined
quantity, not automatically metres or feet, and is unchanged by hydraulic
conversion. Nonnegative unused parameters are retained because native input
still parses them.

| Washoff value | Parameters and coefficient meaning |
| --- | --- |
| `NoWashoff` | No formula/removal parameters |
| `ExponentialWashoff` | coefficient, exponent; consumes surface mass using rain-intensity units |
| `RatingWashoff` | coefficient, exponent; constituent mass per second per project-flow raised to the exponent |
| `EventMeanConcentration` | concentration in the pollutant's units, unused exponent |

Washoff exponents, including the unused EMC input exponent, are between -10 and
10. Active formulas can specify `sweeping_removal` and `bmp_removal` (0–100%).
RC constituent mass is mg, µg or counts, not the lb/kg units of surface buildup.
With no buildup formula, RC/EMC output is not necessarily limited by an initial
loading; EXP consumes available surface mass.

## Units and resource sharing

`convert_units()` converts hydraulic dimensions, project surface mass/area,
EXT buildup data and formula coefficients. EXP washoff coefficients divide by
the rain-intensity conversion factor raised to their exponent; RC coefficients
divide by the flow conversion factor raised to their exponent. Concentrations,
EMC values and MASS inflow raw values/factors retain their units.

`convert_pollutant_units(id, units)` is a separate, atomic MG/L ↔ UG/L operation.
It converts the pollutant's concentrations, CONCEN inline series and baselines,
DWF quality baselines, EMC/RC coefficients and co-pollutant fractions. MASS
inflow factors convert, while their raw data remain unchanged. Surface buildup
and initial loadings retain their project mass units. A shared concentration
series converts once when all consumers explicitly agree to the same replacement.
External files, uncovered consumers, unknown variants and opaque records cause
rejection. Materialize or explicitly separate incompatible data first. There is
no inferred conversion between counts and mass.

Ordinary record updates cannot relabel pollutant units. Use
`reinterpret_pollutant_units()` only to explicitly change the label while keeping
all numeric values; it can create an invalid draft. Use a Model transaction when
coupled relabeling must be validated together. `ChangePollutantUnits` supports
conversion/reinterpretation in scenarios. The public [pollutant-unit extension
protocol](2.0-pollutant-units.md) lets each feature register its own rules and
shared-resource proposals without changes to the conversion coordinator.

Shared series declare consumer dimensions. Incompatible AREA/CURBLENGTH or
mass/count EXT consumers and incompatible concentration units are diagnosed.
Changing a file consumer's context does not silently rewrite its external file.
The default engine profile uses its fixed conversion constants; the explicit
physical policy uses physical conversion factors.

## Sources, references and persistence

Pollutants/landuses have named identities; relation keys derive from their Refs.
Renames update references and keys, removal checks consumers, and transactions
roll back conflicting or invalid patches. Eighteen explicit JSON type tags
cover the quality records/formulas and three pollutant inflow variants.

Multiple COVERAGES/LOADINGS pairs on a line and repeated assignments are
supported. The final pair value takes effect. Editing the quality feature
regenerates its owned rows atomically, keeping comments; malformed groups stay
in the source with errors. Named object redefinitions are errors. Untouched
source retains original optional tokens, spelling and layout. Normalization
uses one relation pair per line and canonical keywords.

Optional `None` values remain distinct in Model JSON. INP sometimes needs zero,
one or `*` placeholders to reach a later field; rereading these holes yields
explicit defaults with the same native meaning. A lone co-pollutant name
without its fraction is ignored by native; `*` also disables the fraction slot.
Ignored trailing columns and native keyword prefixes have diagnostics.

Run validation checks earlier overwritten source references too. In particular,
an EXT assignment can mark an active rainfall series as non-rainfall even when
a later assignment replaces it. Normalize obsolete assignments explicitly or
use separate data; lossless output does not silently remove this behavior.

## State files and validation scope

`HotstartLayout.from_model` now includes actual exported pollutant order/units
and land-use order. `RunoffLayout.from_model` includes the same pollutant
identity. Routing interface checks map named quality columns and require exact
concentration units for matched pollutants. Unmatched columns and absent target
pollutants have diagnostics. A quality-bearing header with zero target pollutants
is rejected for the bundled native parser's limitation. Identity manifests are
caller assertions, not authenticated production snapshots or a proof of physical
cache suitability.

Native tests compare 72 formula/normalizer/unit-system inputs against independent
literal INP files, including both pollutants' complete histories. Further checks
exercise edits to accumulation, loading, snow-only behavior, sweeping, BMP,
all three washoff formulas, MG/UG and count conversions, CONCEN/MASS/DWF,
co-pollutant order and state/routing file reuse.
