# Candidate transects, streets and inlets

The candidate `easysewer.model.Model` provides `transects`, `streets`, `inlets`
and `inlet_usage`. The first three are shared resources keyed by ID. Each inlet
usage is keyed by its conduit reference, so renaming that conduit changes the
relationship key and its references atomically.

```python
from easysewer.model import Model, Ref
from easysewer.model.surface import StreetSection, InletDesign, GrateInlet, StandardGrate

model = Model()
model.streets.add(StreetSection(
    id="Road", crown_width=10, curb_height=.5, cross_slope=2, road_roughness=.016,
))
model.inlets.add(InletDesign(id="G", design=GrateInlet(
    kind="GRATE", length=2, width=1, grate=StandardGrate(kind="P_BAR-50"),
)))
```

These values use the model's default CFS/US context. Street conduit geometry uses
`easysewer.model.geometry.Street(street=Ref(...))`; it is distinct from the shared
`StreetSection` definition. `InletUsage` links a conduit, design and receiving node
and carries optional count, clogging, flow cap, depression and placement values.

## Transect state and pinned engine behavior

`Transect` contains a tuple of `TransectPoint(elevation, station)`, left/right bank
positions, `TransectRoughness(left, right, channel)`, meander and width factors and
an elevation offset. Points may repeat a station to represent a vertical side,
but must not go backwards. The profile supports 2–1499 points and positive depth
and width; bank locations not represented by stations are diagnosed.

The codec resolves NC inheritance into each independent record. It preserves the
original text until projection is necessary. In the tagged 5.2.4 implementation,
native finalization multiplies the working channel roughness by the square root
of the meander factor. A later zero NC field can inherit that adjusted value.
Repeated section transitions also affect this state. Tests compare these cases
against the actual native library rather than treating zero as an unconditional
default or copying the last NC token.

For this profile, canonical X1 syntax has **two** ignored placeholder fields:

```text
X1 Name Count LeftBank RightBank 0 0 Meander WidthFactor ElevationOffset
```

The manual's additional placeholder shifts the values read by this engine. An
eleventh token is ignored by the solver; the reader diagnoses it and represents
the actual native positions. Count is derived from the point tuple on output;
an imported count that differs from GR data is diagnosed because native uses the
actual points.

The native reader finalizes a transect on an NC line or section transition, with
special behavior for the last declared transect. Merely starting the next X1 does
not finalize the preceding data. A terminal GR block at EOF also remains unfinished.
The writer emits explicit NC values before each X1 and adds a following REPORT
header when required. Empty old TRANSECTS headers are removed during regeneration
because they can themselves trigger native state changes.

When any model change is projected, existing structured transect blocks are
regenerated from their resolved values. This includes edits to other sections:
appending an OPTIONS section after a trailing NC could otherwise change the final
transect's roughness. Untouched source remains byte exact by default.

The engine divides the transect elevation-offset input by the length factor twice.
The fixed profile records this behavior for engine-preserving unit conversion;
`basis="physical"` retains ordinary linear length conversion. The offset is a
translation of the whole section, not a conduit invert elevation.

There is also a floating-point boundary issue: native bank positions use
`(bank / UCF) * width`, while stations use `(station * width) / UCF`, and roughness
regions depend on exact equality. With unequal overbank roughness, a non-unit
width factor can therefore change hydraulics across unit systems. Engine-basis
US-to-SI conversion first incorporates that factor into bank/station coordinates
and sets `width_factor=1`. This is an explicit representation change made by the
conversion operation; ordinary read/write retains the supplied factor.

For an existing SI transect with a non-unit width factor, the source engine may
already be using different roughness boundaries. Validation warns about this;
engine-basis conversion to US rejects the whole operation without changing the
model. An explicitly requested `basis="physical"` converts ordinary dimensions
and retains the width factor, but requires hydraulic revalidation. Converting
between flow units within the same length system leaves the transect unchanged.

## Street and inlet fields

Street definitions cover crown width, curb height, cross slope, road roughness,
gutter depression/width, one or two sides, and backing width/slope/roughness.
Positive backing width requires its slope and roughness. Omitted optional fields
remain distinct from explicit values; required interior defaults are materialized
only when later positional fields must be written.

Inlet designs include GRATE, CURB, SLOTTED, DROP_GRATE, DROP_CURB and CUSTOM.
`CombinationInlet` combines a street GRATE and CURB under one ID and emits two
records. Source records can present those components in either order. Grates use
one of seven `StandardGrate` patterns or `GenericGrate(open_fraction,
splash_velocity=None)`. Generic splash velocity defaults to native zero; standard
grates use their predefined parameters. Curb throat choices are HORIZONTAL,
INCLINED and VERTICAL, with native VERTICAL when omitted. DROP_CURB has no active
throat parameter; ignored source tokens are diagnosed.

For 5.2.4, **both street and inlet local depression heights use ft/m**, despite the
manual's in/mm descriptions. Their field dimension is length. Clogging is 0–99
percent, count is a positive integer, flow cap zero means unrestricted, and
placement is AUTOMATIC, ON_GRADE or ON_SAG. Native later INLET_USAGE assignments
replace earlier assignments for the same conduit; duplicate source rows collapse
on editing or normalization.

Validation checks supported design/shape combinations before native would silently
remove an incompatible inlet: curb/gutter designs require STREET; drop designs
require RECT_OPEN or TRAPEZOIDAL; CUSTOM requires a DIVERSION or RATING curve.
Curve purposes, graph references, renaming and dependent deletion participate in
the same shared-resource contracts as the rest of the model.

## Preservation and explicit normalization

```python
model = Model.from_inp("source.inp", strict=True)
model.validate(for_run=True, normalize=True).raise_for_errors()
model.to_inp("normalized.inp", normalize=True)
```

`normalize=True` regenerates supported owned rows and removes their obsolete
headers while retaining unknown records and comments. It handles the diagnosed
native finalization requirements and supported headers with whitespace after `[`.
`validate(for_run=True)` checks the preserved/projection output; setting
`normalize=True` checks the normalized output instead. A document can be structurally
readable yet require normalization before native execution.

This does not repair arbitrary malformed or unknown state. For example, GR data
continued after a native finalization boundary is retained with an error rather
than guessed into a different shape. Invalid source remains available through
`model.document`.

## Validation and limits

Native tests cover inherited/adjusted roughness, repeated sections, nonzero modifiers,
actual X1 positions, explicit repair of unfinished blocks and edits to unrelated
sections. The unit-conversion test includes asymmetric overbanks and a return
conversion to US; rejected SI conversions also verify whole-model rollback. Inlet tests cover
63 design/shape/side/placement combinations, including all grate patterns, throat
angles, reversed combination records and both custom curve kinds. They compare
complete receiving-node depths, surface/sewer flows, lateral flows and mass balance.
Implicit/explicit defaults and CFS-to-CMS capture conversion have separate comparisons.
