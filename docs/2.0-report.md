# Candidate RPT documents and tables

The candidate RPT reader preserves original bytes and supplies portable tables
without loading a native library. It is separate from OUT series: printed native
statistics and the maximum of saved OUT observations have different meanings.

Parsing status is separate from [result applicability](2.0-result-applicability.md).
A present table can contain unrecomputed numbers: typed queries expose missing
values with reasons while retaining its raw text and cell tokens.

```python
from easysewer.runtime import ReportReadOptions, RunConfig
from easysewer.model import FileReference

run = model.run(RunConfig(
    output_directory=FileReference(path="runs/report", direction="output"),
    report_read=ReportReadOptions(
        tables=("swmm:node_depth", "swmm:node_flooding"),
        on_table_error="raise",
    ),
)).raise_for_status()

depths = run.report_table("swmm:node_depth")
peak = depths.cell("J", "swmm:maximum_depth")
when = depths.cell("J", "swmm:peak_time")
print(peak.value, peak.unit, peak.precision)
print(when.value, depths.time_origin)
```

There are 43 built-in table keys; all names below have the `swmm:` prefix.

| Group | Keys |
| --- | --- |
| Nodes and links | node_depth, node_inflow, node_flooding, node_surcharge, storage_volume, link_flow, flow_classification, conduit_surcharge, pumping, outfall_loading, link_pollutant_load, street_flow |
| Catchments | subcatchment_runoff, subcatchment_washoff, groundwater, lid_performance |
| Continuity | runoff_quantity_continuity, groundwater_continuity, flow_routing_continuity, runoff_quality_continuity, quality_routing_continuity |
| Routing diagnostics | routing_time_step, highest_continuity_errors, time_step_critical_elements, highest_flow_instability, nonconverging_nodes |
| Status | analysis_options, element_count, rdii, rainfall_file, control_actions, analysis_timing |
| Resolved input | input_landuses, input_subcatchments, input_nodes, input_links, input_cross_sections, input_pollutants, input_raingages, input_lid_controls, input_shapes, input_transects, input_streets |

Selection is explicit; an unregistered key is rejected before native execution.
Request all registered keys with `easysewer.io.report.swmm_report_tables().keys`.
Input summaries require `model.update_report(input=True)`; control action logs
require `controls=True`. Unknown headings remain available as cataloged text.

## Status and resolved input

`analysis_options` contains the engine's effective printed settings. Each row
populates one of `text`, `number`, `calendar` or `duration`; the other cells have
an explicit missing reason. Starting/ending dates use the model calendar.
`analysis_timing` instead exposes the machine's local wall clock with unknown
timezone, plus processing seconds. Native `< 1 sec` is value 1 with the
`less_than` qualifier. It must not be interpreted as one measured second or as a
model timestamp. Even `REPORT DISABLED` can emit the wall-time block.

Input summary dimensional units come from the printed Flow Units or explicit
`ReportContext(flow_units=...)`. Runner supplies its captured unit context; a
conflict raises. Bare summaries without a unit context retain unit=None. Node
depths, conduit slope and full flow are engine-resolved quantities, so these
tables cannot reconstruct the original Model. Link endpoints retain the input
orientation even when SWMM internally reverses a conduit. Non-conduits have
explicitly inapplicable length/slope/roughness cells. Pollutant concentrations
use each row's printed MG/L, UG/L or #/L unit.

`input_shapes`, `input_transects` and `input_streets` expose normalized native
area, hydraulic-radius and width arrays. Each object has indices 1 through 50;
native index zero is not printed. Rows use `(id, index)` keys and the geometry
resource Ref. They are not the original curve points, stations or street
dimensions. Repeated LID deployment pairs retain ordinal row identities without
guessing Model deployment IDs, as in the performance summary.

Rainfall File Summary identifies external **stations**, not rain gages. Repeated
station labels remain separate rows. Asterisks in first/last dates mean unknown
dates, not a zero date. The native `w/Precip` counter may include accepted zero
rainfall records. RDII volume columns retain their US/SI units; the ratio row is
dimensionless and its second column is explicitly unprinted.

`input_raingages.source_text` always retains the printed source description.
File paths can resemble inline time-series descriptions. The reader therefore
requires `ReportContext(rain_gage_sources=(("R", "FILE"), ...))` to interpret a
file path, or `TIMESERIES` to split an ID, rain type and recording interval.
Runner obtains this context from the executed INP, not a subsequently edited
Model. Without proof, interpreted cells use `source_kind_not_proven`.

`control_actions` preserves actual event order, link targets, rule labels and
two-decimal settings. Multiple actions rounded to the same calendar second
remain separate rows; no fabricated fractional times or interval resampling
is applied.

## Original bytes and encoding

`ReportDocument.raw` is byte-for-byte identical to the native report. Standalone
`ReportDocument.read(path)` uses strict UTF-8/BOM decoding. A decoding failure
preserves raw bytes, leaves `text`/`encoding` unset and supplies a diagnostic;
`on_decode_error="raise"` raises instead. An explicitly known encoding such as
`cp1252` takes precedence and is recorded. It is not inferred from one byte.

SWMM's known storage/flooding volume headers contain literal ANSI `0xB3` for
superscript three, even when object names are UTF-8. For the bundled 5.2.4
backends, Runner applies `SWMM_UTF8_REPORT` from `easysewer.io.report_document`.
The strategy first tries strict decoding. Only after failure does it normalize
superscripts in the two recognized header grammars and retry strict UTF-8. It
records the strategy and original zero-based byte offsets, while retaining
`raw`. Unrelated invalid bytes are never repaired, dropped or replaced. Explicit
`encoding=` bypasses this strategy. A standalone caller must explicitly assert
this producer profile; a bare report does not establish its identifier encoding.

`max_bytes` defaults to 64 MiB in both ReportDocument and ReportReadOptions.
Reading consumes at most `max_bytes + 1` source bytes and closes the file before
parsing; exceeding the budget fails. Raw bytes, decoded text, catalog blocks and
materialized cells remain in memory. This is a source-byte budget, not an overall
Python memory limit or a streaming RPT implementation.

Report reading and queries accept an optional trusted `checkpoint` callable
with no arguments: `ReportDocument.read/from_bytes`, `ReportCapture.read`,
`read_report_tables`, `ReportReader` construction and its `table/detail/series`
methods, `read_lid_report`, `table_series`, and `ResultTable.to_json_document`.
Table serialization checks record construction, conversion, JSON encoding and
object parsing/validation while retaining the existing 1.1/1.2 wire format.
Built-in readers check file chunks,
line/row batches, source hashes and table validation. A callback exception leaves
the operation unchanged in type, identity and exception chaining; it is never
converted into an undecoded report or unsupported table layout. Nested calls
inherit the active work check, and it does not leak into later or other-thread
operations. Custom table codecs keep their existing three-argument signature;
checks surround their call but cannot forcibly stop arbitrary extension code.
Individual decoding, regular-expression, allocation and OS operations are not
preemptible, so this is cooperative cancellation, not a hard time bound.

`ReportDocument.message_contexts` supplements the existing `messages` diagnostics
with each printed error/warning's raw text. Known input errors retain the echoed
line, asserted INP line number and section; `input_report_span` locates that echo
in the RPT. These coordinates are not a verified link to an original Model.
Error 173 carries a model-calendar timestamp when printed. Error 318 preserves
its following rainfall-data line. Unknown message formats remain in raw text.

On a failed run, `RunResult.failure_report` may contain a `ReportCapture` even
when `keep_failed_artifacts=False` removes the workspace. Its `document` holds
captured bytes and diagnostic context. `truncated=True` means only the first
capture-budget bytes were captured; `sha256` always hashes that captured
prefix, never an unseen remainder. A split UTF-8 character remains undecoded.
Diagnostic capture uses preserve decoding even if the successful-read policy
was strict. Capture failures add warnings and never replace the primary
`RunFailure`. A missing report leaves this field None. Successful report fields,
table publication and previous destination files retain their existing rules;
this best-effort snapshot is not a success artifact or durable crash journal.

For cancellation and timeout, the failure capture budget is
`min(report_read.max_bytes, 64 KiB)`. This prevents a stopped report scan from
restarting a full large-report parse during failure handling. Other failures
continue to use `report_read.max_bytes`. The existing truncation diagnostic and
`ReportCapture.truncated` label the prefix; it is never presented as the complete
report. Full files still follow `keep_failed_artifacts`. Artifact hashing and
mandatory rollback/session/workspace cleanup also contribute to return latency.

## Values, identity and precision

`ResultTable`, `ResultRow`, `ResultColumn` and `ResultCell` are frozen values.
Rows retain their actual object IDs and Ref values. Columns use namespaced keys;
quality columns additionally use a separate pollutant Ref. Querying IDs follows
SWMM's ASCII case matching and preserves original spelling. Values do not depend
on a subsequently edited Model.

Rows can also have tuple keys. The aggregate System row in washoff/outfall tables
uses `("swmm:system",)` with no object target, so it cannot shadow a real object
named `System` or `swmm:system`. Ranked diagnostics use `(collection, id)`.
An object detail table also retains its own `target`, including an empty table;
the resulting empty series therefore still identifies the captured object.

Each cell retains its printed text, decoded source line/character columns,
effective unit, printed precision, inequality qualifier and missing reason.
Cell units are authoritative: continuity error rows use percent even in a mass
table. Node Inflow's low-outflow balance can use `gal`/`ltr` instead of percent.
COUNT loads printed as `LogN` remain logarithmic. `>50.00` velocities retain a
`greater_than` qualifier. Blank optional pump/weir/outlet fields are missing
values, not zero or another column's value. Native minimum field widths expand
for long IDs; optional link slots are located after the printed time.

Peak `days hr:min` values are `timedelta` values measured from **ReportStart**,
with nonpositive offsets clamped to zero. Native time conversion rounds to a
second and then omits seconds. The report therefore cannot recover an exact
second-level peak date. Runner captures the effective report start in
`table.time_origin`; standalone parsing leaves it unset unless a caller supplies
`ReportContext`. A zero time can also mean no positive peak was observed.

Native peak times are not guaranteed to be identical across platforms. Nearly
tied internal maxima can select different occurrences after tiny floating-point
differences, even when the printed maximum and the complete saved OUT agree.
Native statistics use a strict greater-than comparison; converting observations
to user units can also merge values that differ internally. Preserve the RPT's
reported time and sampling definition when comparing runs. Do not substitute
the first maximum from OUT or silently discard differing RPT times.

Depth and storage means use arithmetic routing-step endpoint means. Flooded and
surcharged positive durations are printed as at least 0.01 hours. The reported
maximum depth column uses native `maxRptDepth`; with REPORT AVERAGES it does not
mean the largest saved average. FlexiblePonding ABI 201 provenance marks adjusted
statistics and discrete external removal. Standalone files without producer
context retain unspecified numerical policy.

`time_origin` defines elapsed-time interpretation, not a universal aggregation
window. Native routing statistics are updated at steps ending at/after ReportStart;
continuity balances cover the simulation. Node Inflow's lateral volume comes from
those routing statistics, while its total inflow and balance use the native
whole-run node accumulators. A step crossing ReportStart can contribute its entire
interval. Do not subtract or compare totals as if all columns shared one window.

Subcatchment/groundwater and LID balances cover the whole run. Groundwater means
are weighted by runoff time. Flow Classification fractions use elapsed routing
time. Conduit Surcharge prints every emitted duration as at least 0.01 hours,
including zero-duration cells in an otherwise active row. Outfall System mean
flow sums per-outfall means, and its peak is the simultaneous total peak; neither
is computed by averaging or summing individual peaks. Street rows can omit all
inlet fields or only flow statistics; omitted cells carry a missing reason.
Routing time-step metrics and frequency bins use cell-specific units.

When a runoff interface supplies the runoff, native SWMM prints a file notice
instead of quantity balances. `runoff_quantity_continuity` then has one text
column `swmm:runoff_interface` and row `swmm:source`. No unprinted volume is zero.

## Missing tables, unfamiliar layouts and diagnostics

A table's status is `present`, `empty`, `absent`, `undecoded` or
`unsupported_layout`. Empty means the table explicitly reported no rows; absent
means the engine did not emit that table. Neither implies a numerical zero.
Rows outside the emitted table raise KeyError. Calling `run.report_table` for an
unrequested table also raises KeyError.

Known codecs validate complete normalized headers, row widths and finite values.
New or changed columns cannot silently shift values into existing meanings. The
default `on_table_error="preserve"` produces an unavailable table with its full
source block and diagnostic. `"raise"` fails before Runner publication, preserving
previous output files. Absent or explicitly empty tables are valid outcomes under
both policies. Quality-continuity blocks, each containing up to five pollutants,
join by identical row identities and distinct pollutant column identities. A
missing, duplicated or reordered metric row prevents that merge. Wide numeric
fields in known summaries and details can touch; known decimal precision allows
safe separation. Ambiguous ID/value boundaries still remain unsupported.

Long pollutant labels can also touch. Runner takes the exact ordered identities
from the executed input snapshot, including declared pollutants when
IGNORE_QUALITY is enabled. A standalone caller may supply
`ReportContext(pollutants=(...))`; the rendered headers must match those names.
Without that context, a header that cannot be separated safely stays unsupported.
The native integer name API does not expose pollutant names on every backend.

`ReportDocument.blocks` catalogs all detected sections, including unknown tables,
and `<<< Subcatchment/Node/Link >>>` details with object references and source line
ranges. Concatenating block text reproduces decoded text. `messages` exposes native
ERROR/WARNING lines with codes and spans; subsequent explanatory lines remain in
the document. Unknown blocks remain available even when no table is requested.
Detailed tables and LID outputs use the same value contract, as described below.

## Printed object observations

```python
from easysewer.model import Ref

reader = run.report_reader(on_error="raise")
node = Ref(collection="swmm:nodes", key="J")
detail = reader.detail(node)  # swmm:node_detail
depth = reader.series(node, "swmm:depth")
```

`ReportReader` queries a captured `ReportDocument` without a file/native handle.
Use `reader.targets` to discover printed object blocks and `reader.table(key)` to
read a registered summary that was not selected for publication. The RunResult
view uses the captured bytes and provenance; it does not reopen a changed RPT
path. Standalone use is `ReportReader(document, context=..., on_error=...)`.

Subcatchment, node and link details become `swmm:subcatchment_detail`,
`swmm:node_detail` and `swmm:link_detail` tables. They have `swmm:time` as a naive
calendar datetime, then the applicable OUT variable keys. Concentrations use a
pollutant Ref. Optional snow and groundwater columns follow the emitted header.
Subcatchment `swmm:losses` is OUT evaporation divided by 24 plus infiltration.
Capacity means conduit capacity or regulator/pump setting according to link type.

These are printed OUT observations, rounded to the source decimal precision;
they are not an additional native peak statistic. Dates have second precision,
runoff/groundwater flows four decimals, and other detail values three decimals.
Rows use observation ordinal keys, preserving duplicate rounded timestamps.
`series()` and `table_series(table, variable, ...)` return portable ResultSeries
only if timestamps strictly increase; otherwise use the table rows. Neither API
fills missing dates or invents fractional timestamps. Missing object blocks raise
NotRecordedError for a series and return `absent` for a table.

## LID performance and separate detail files

```python
from easysewer.io.report_details import table_series

performance = run.report_reader().table("swmm:lid_performance")
owner = Ref(collection="swmm:lid_usage", key="lid-usage-1")
detail = run.read_lid_report(owner, on_error="raise")
inflow = table_series(detail, "swmm:inflow")
```

The deployment must have requested a detail output before running. RunResult
verifies its archived file SHA-256 and size, and checks the header against the
captured deployment, before exposing data. Later Model renames cannot rebind it.
Extension models can supply `schema=` for snapshot restoration. Standalone
`read_lid_report(path, ...)` accepts a known encoding, source-byte budget and
optional expected identity/hash/size without requiring an engine or Model.

The detailed table has calendar time, elapsed hours and twelve LID flow/state
columns. Flow rates use in/hr or mm/hr; levels use inches or mm; soil moisture is
a fraction. Evaporation has four decimals, other numeric fields three. Values are
over a single unit footprint. These observations follow native runoff steps,
not REPORT_STEP. SWMM compresses dry sequences, and an entirely dry deployment
can produce an empty file with a valid header. Omitted intervals cannot be
treated as measured zero or integrated without additional native information.

LID Performance Summary prints one row per deployment but lacks easysewer's
deployment record ID. Repeated subcatchment/control pairs remain separate using
`("swmm:lid_occurrence", subcatchment, control, ordinal)` keys, with `target=None`.
Native report order is not a reliable mapping to INP order. The separate detail
file, whose resource ownership was captured before execution, has that binding.

## Persistence and extension

```python
from easysewer.results import ResultTable

document = depths.to_json_document()
restored = ResultTable.from_json_document(document)
assert restored == depths
```

The version 1.0 `easysewer:result-table` envelope preserves column definitions,
values, elapsed microseconds, tagged calendar datetimes, composite row keys,
optional table target, source SHA-256/run/input/backend identities,
diagnostics, raw block text, report start and decoding strategy. Runner publishes
each requested table as a `run:report-table` artifact, selected by
`field=(table_key,)`. The execution record includes decoding metadata, repair
offsets and table artifact names/statuses. A table JSON restores independently of
the engine and Model; original undecoded bytes live in the separate RPT artifact.
Earlier table envelopes without a table-level `target` still restore with None;
their existing row targets remain available.

`ReportTableCodec(key=..., title=..., parser=...)` registers a trusted Python
callback returning `(columns, rows)` from `(ReportBlock, ReportContext,
ResultSource)`. Extend `swmm_report_tables().with_codecs(codec)` and pass the
new immutable registry to `Runner(report_tables=registry)` or
`read_report_tables(..., registry=registry)`. Duplicate keys or kind/title pairs are rejected.
Extensions use the same query and persistence contract; callbacks are never
loaded from input text. `multiple="columns"` explicitly permits repeated column
blocks with matching row identities; the default rejects repeated titles.
`block_kind` defaults to `section`; `preamble`, `detail` and `timing` can be
selected explicitly. The tests include a preamble engine-banner extension codec
through Runner, persistence and restoration without changing existing queries.

The printed layouts and elapsed-time rules were checked against EPA's tagged
[statsrpt.c](https://github.com/USEPA/Stormwater-Management-Model/blob/v5.2.4/src/solver/statsrpt.c),
[report.c](https://github.com/USEPA/Stormwater-Management-Model/blob/v5.2.4/src/solver/report.c)
and [swmm5.c](https://github.com/USEPA/Stormwater-Management-Model/blob/v5.2.4/src/solver/swmm5.c),
the local SWMM 5.2 manual and actual standard/custom reports. Native LID layouts
also follow tagged `lid.c`/`lidproc.c`; input summaries follow
[inputrpt.c](https://github.com/USEPA/Stormwater-Management-Model/blob/v5.2.4/src/solver/inputrpt.c).
Report catalog and diagnostic scanning use bounded line lookahead, preserving
the distinct Python text/byte line boundaries and exact source offsets. Reports
still retain original bytes, decoded text and block text; this is not an
out-of-core report API. Parser-created reports keep an independent immutable
record snapshot for subsequent consistency checks. Each check compares all
fields; directly constructed or changed reports are verified against their raw
bytes. The snapshot is released when its report is collected, and does not
change archive formats or serialized evidence checks.

Full-scale performance, durable failure journals, old API migration and all
release gates remain in the development plan.
