# Candidate control programs

`easysewer.model.Model.controls` is an ordered collection of immutable
`ControlVariable`, `ControlExpression` and `ControlRule` records. Its composite
key is `(kind, id)`, such as `("RULE", "Drain")`. Variables, expressions and rules
have distinct namespaces. IDs and nested references use the same graph,
transaction, rename and deletion mechanisms as network objects.

```python
from datetime import timedelta
from easysewer.model import Model, Ref
from easysewer.model import controls as c

model = Model.from_inp("network.inp", strict=True)  # Contains conduit P.
model.controls.add(c.ControlVariable(
    id="PipeFlow", value=c.Attribute(
        object_type="CONDUIT", attribute="FLOW",
        target=Ref(collection="swmm:links", key="P"),
    ),
))
model.controls.add(c.ControlRule(
    id="Limit", conditions=(c.Condition(
        left=c.NamedOperand(reference=Ref(
            collection="swmm:controls", key=("VARIABLE", "PipeFlow"))),
        relation=">", right=c.Constant(value=1),  # Current model flow units.
    ),), then_actions=(c.Action(
        target=Ref(collection="swmm:links", key="P"), object_type="CONDUIT",
        setting=c.StatusSetting(value="CLOSED"),
    ),), else_actions=(c.Action(
        target=Ref(collection="swmm:links", key="P"), object_type="CONDUIT",
        setting=c.StatusSetting(value="OPEN"),
    ),),
))
model.update_options(rule_step=timedelta(seconds=20))
model.controls.rename(("VARIABLE", "PipeFlow"), "MeasuredFlow")
model.controls.rename(("RULE", "Limit"), "FlowLimit")
model.to_inp("controlled.inp")
```

`controls.move(key, before=other_key)` explicitly changes ordering; omitting
`before` moves the record to the end. Rule ordering affects equal-priority actions.
Moving a declaration that changes native name binding is rejected on validation
and export. Transactions roll back invalid changes.

## Syntax and source ownership

Conditions retain their ordered IF/AND/OR clauses and all six relational
operators. Operands represent object attributes, named variables/expressions or
typed constants. Durations use `timedelta`, dates use `date`, and calendar
month/day values use `MonthDay`. An expression may appear on the left of a
comparison; the right accepts a variable, object attribute or constant.

The attribute model covers NODE, LINK/CONDUIT, PUMP, ORIFICE, WEIR, OUTLET,
SIMULATION and GAGE, including intensity and 1–48-hour accumulated rain.
Attribute availability still depends on the actual target link family and fixed
engine behavior. For example, the native engine returns MISSING for OUTLET
SETTING premises; the run validator rejects that case.

Actions represent conduit/pump status, numeric settings, CONTROL curves,
setting time series and PID coefficients. PID integral/derivative times are
durations, serialized in minutes. Ordinary regulator numeric settings use [0, 1].
An omitted priority remains `None`; its native effective value is zero. Explicit
zero and negative priorities remain distinct source values.

Arithmetic has number, variable, unary, binary and function nodes. The codec
supports all 19 documented functions and SWMM's power association and signed
number syntax. Expressions are parsed as syntax and never evaluated with Python
`eval`. References inside arithmetic participate in renames and deletion checks.
The operand, expression and setting bases allow future variants, but each variant
also needs an explicit codec, validation and unit policy; inheritance alone does
not make an unsupported variant serializable.

CONTROLS is owned atomically. Unsupported syntax, repeated named definitions, or
declaration reordering that would change symbol binding preserves the entire
program as source-owned with a diagnostic. Malformed programs are retained with
errors. No partial editable prefix is exposed. Untouched supported source remains
byte exact, including comments and declarations between rule clauses. Rewriting
hoists variables and expressions before rules, preserving each namespace's order
and relative rule order. Removed clauses retain their comments as standalone text.

Native named lookup uses the first case-insensitive prefix match, with expressions
checked before variables on the left. It is not an exact-name lookup. Export checks
cross-namespace shadowing and shadowing of object keywords or constants. Named
variables/expressions have a native 32-byte capacity; arithmetic variable names
must be identifiers distinct from math function names.

Network declarations must precede their control actions. `for_run=True` checks
the projected document; explicit normalization repairs supported source order.
Feature `rewrite_after` dependencies also regenerate an unchanged program after
network declarations move. This is a generic writer dependency, not a special
case in Model for pumps or controls.

## Units and fixed-engine semantics

Direct numeric thresholds use the left operand's dimension. Named expressions
infer dimensions conservatively: averages of flow values, dimensionless scaling,
and compatible comparisons can convert. A dimensional offset such as `Depth + 2`
has no declared unit for the literal and conversion fails atomically. Wrapping it
in SGN, STEP or a zero power does not bypass this check. The AST is preserved;
the converter does not silently rewrite the user's formula.

CONTROL curve x dimensions come from the rule's possible controllers; y and
setting series are dimensionless. Shared resources convert once. Ambiguous
short-circuit controller dimensions, uncertain time comparisons and external
file values that need scaling cannot be guessed. Numeric PID gain and time
constants stay unchanged under an otherwise valid homogeneous unit conversion.

The fixed SWMM 5.2.4 implementation has several material details:

- OR has higher precedence than AND. Evaluation short-circuits. Equal-priority
  competing rules favor the first rule; multiple actions on the same link in one
  branch favor the last written action. Negative priority is below the omitted
  default of zero.
- CURVE/PID uses the last *evaluated* numeric comparison's controller/setpoint,
  which need not be the last written condition. TIME/CLOCKTIME equality and
  inequality can retain previous global controller state. Direct link-age control
  multiplies its value to hours while the setpoint stays in days. Diagnostics
  describe these native effects; this library does not reinterpret execution.
  Link-age operands can also return MISSING when the link has the other status,
  retaining previous global values. Modulated controller conversion conservatively
  rejects such operands, including RHS variables and named expression references.
- Numeric time constants in INP are hours; time attributes in expressions are
  days. Fractional clock components are truncated by native parsing; fractional
  numeric hours retain subsecond precision. RULE_STEP remains an independent
  analysis option, with omitted/zero meaning every routing step.
- Control time series extend their first/last values outside the record range.
  External flow series instead return zero there.
- The native link attribute is FULLDEPTH, although the manual lists MAXDEPTH.
  The alias imports with a diagnostic and needs explicit normalization to run.
- Gage history-window codes reuse attribute enum numbers. Some direct windows
  collide with status/time/date parsing and evaluation; direct `8-HR_DEPTH > .1`
  fails with ERROR 205. A named variable wrapped in a named arithmetic expression
  provides a numeric comparison path, tested for all 48 windows. A gage referenced
  only by controls can remain unused by runoff/RDII and then return zero.
- SGN(0) returns zero. Power with a nonpositive base returns zero, so `-2^2`
  evaluates to zero while the spaced unary form `- 2^2` evaluates to -4.
  These are native arithmetic rules, not Python or conventional math semantics.

## Validation and limits

The control increment adds 16 structured tests and 12 native tests. Native
comparisons rebuild a fresh Model and compare complete step-by-step link setting,
node depth, link flow and mass balance against independently written source.
Coverage includes all non-gage attributes, all functions, six relations,
priorities/order, all four regulated link families and four setting forms, pump
status, series endpoints, short-circuit/global controller state, 48 rain windows,
symbol renaming and declaration ordering. RULE_STEP tests compare actual first
action times for omitted, zero, 1-second and 20-second settings. Six-unit control
curve/expression cases compare hydraulic and setting histories within 1e-9.
