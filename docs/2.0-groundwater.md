# Candidate groundwater domain

`easysewer.model.Model` provides `aquifers`, `groundwater` and `gwf` collections
for all AQUIFERS, GROUNDWATER and GWF parameters. Aquifers have named identities;
groundwater bindings use the subcatchment ID; flow expressions use
`(subcatchment_id, "LATERAL" or "DEEP")`.

```python
from easysewer.model import Ref
from easysewer.model.groundwater import Aquifer, Groundwater, GroundwaterExpression
from easysewer.io.inp.groundwater import GroundwaterExpressionCodec

# model is an existing candidate Model with subcatchment S and receiving node J.
model.aquifers.add(Aquifer(
    id="Soil", porosity=.45, wilting_point=.1, field_capacity=.25,
    conductivity=.2, conductivity_slope=10, tension_slope=15,
    upper_evaporation_fraction=.5, lower_evaporation_depth=5,
    deep_seepage=.001, bottom_elevation=-10,
    water_table_elevation=2, upper_moisture=.3,
))
model.groundwater.add(Groundwater(
    subcatchment=Ref(collection="swmm:subcatchments", key="S"),
    aquifer=Ref(collection="swmm:aquifers", key="Soil"),
    node=Ref(collection="swmm:nodes", key="J"), surface_elevation=20,
    groundwater_coefficient=.001, groundwater_exponent=1.2,
    surface_water_coefficient=0, surface_water_exponent=1,
    interaction_coefficient=0, fixed_surface_depth=0,
))
model.gwf.add(GroundwaterExpression(
    subcatchment=Ref(collection="swmm:subcatchments", key="S"),
    kind="LATERAL",
    expression=GroundwaterExpressionCodec().parse("0.002 * (HGW - HCB)"),
))
```

The numbers above are in the default CFS/US input context, not calibrated site
parameters. `convert_units()` converts an existing graph; `reinterpret_units()`
explicitly changes the interpretation without changing its numbers.

## Aquifers and local overrides

Aquifer porosity, wilting point, field capacity and initial upper-zone moisture
are volumetric fractions. Validation requires `wilting < field_capacity <
porosity`, positive conductivity, and moisture between wilting point and
porosity. Conductivity and deep seepage are in in/hour or mm/hour. Conductivity
slope is dimensionless. Upper evaporation fraction is 0–1; lower evaporation
depth is ft/m. Optional `evaporation_pattern` must reference a MONTHLY pattern.

Bottom and initial water-table elevations are ft/m. Each groundwater binding
can override `bottom_elevation`, `water_table_elevation` and `upper_moisture`;
`None` uses the aquifer value. `threshold_elevation=None` uses the receiving
node's invert. Zero `fixed_surface_depth` uses routed node depth; positive values
fix the depth used in groundwater exchange. Local elevations require positive
total depth and a water table between bottom and ground surface. Fully saturated
initial conditions have a warning because native initialization subtracts its
small tolerance from the boundary.

The candidate applies physical bounds to fractions, depths and seepage even
where the native input reader accepts a broader range. Coefficients and
exponents remain finite signed numbers; reverse exchange is supported. Native
clips a negative base lateral flow to zero when the interaction coefficient is
nonzero. These formulas are passed to the engine, not reimplemented as a Python
hydrology solver.

Two manual/engine differences are explicit:

- The 5.2 manual labels aquifer tension slope in inches/mm. The fixed engine
  divides its input by the ft/m length factor. `tension_slope` therefore uses
  native length units and converts by 0.3048. Real CFS/CMS moisture histories
  agree after that conversion; using 25.4 measurably changes them.
- The manual describes the threshold column as optional. The fixed engine
  requires at least eleven GROUNDWATER tokens. The writer always supplies its
  numeric value or `*`, even when all four override fields are absent.

Native optional tokens beginning with `*` mean missing. Its numeric missing
sentinel is also recognized: -1e10 for US length fields or moisture, and
-3048000000 for SI length fields. These import as `None` with a diagnostic and
normalize to `*`; original source stays unchanged. A programmatic numeric value
that collides with this sentinel is rejected in favor of explicit `None`.

## Expressions and units

GWF uses the common syntax in `easysewer.model.expressions`: numbers, unary and
binary arithmetic and the 19 native math functions. `GroundwaterVariable` adds
the eleven domain leaves below. Control expressions retain their existing
imports and JSON tags but use the same common arithmetic classes. Domain
validation rejects a control variable in GWF or a groundwater variable in a
control expression. No formula is evaluated as Python code.

| Variables | Input units |
| --- | --- |
| HGW, HSW, HCB, HGS | ft/m, relative to aquifer bottom |
| KS, K, FI, FU | in/hour or mm/hour |
| THETA, PHI | dimensionless moisture/porosity |
| A | acres/hectares |

The LATERAL expression **adds to** the standard coefficient formula. Its result
is cfs/acre or cms/hectare, even if project flow units are GPM, MGD, LPS or MLD.
The DEEP expression **replaces** default deep seepage and returns in/hour or
mm/hour. An expression without a groundwater binding is retained and diagnosed
as inactive. Native full-keyword variable prefixes are recognized in native
lookup order and diagnosed: `KSuffix` resolves to KS, not K.

Hydraulic conversion scales the first two base coefficients by the
groundwater-flux factor divided by the length factor to their exponent, and
the interaction coefficient by flux divided by squared length. For arbitrary
GWF arithmetic, conversion substitutes each new variable divided by its unit
factor into the old formula, then multiplies the result by its output factor.
This preserves empirical constants and nonlinear functions without guessing
their dimensions. Same-system flow-unit changes leave these expressions alone.
Repeated cross-system conversions can enlarge the syntax tree; compact rendering
and large-expression performance remain release work.

Preflight checks GWF physical line length against the fixed input buffer and
individual arithmetic tokens against its 254-character payload. Unsafe source
is never exercised by the tests. A long native prefix or numeric spelling can
be repaired by explicit normalization when its canonical expression fits.

## Persistence, state and evidence

Named aquifer redefinitions are errors. Repeated groundwater/GWF assignments
retain the final value, with original source preserved until editing or explicit
normalization. All rows in a relation group must parse successfully; native
references in earlier overwritten bindings are checked before running.

Aquifer, node, subcatchment and pattern renames propagate through the graph;
relation keys update automatically. Scenario patches return changed copies and
validate atomically. Four additional JSON tags cover the new records/leaf;
source-free JSON restores the complete groundwater model.

`HotstartLayout.from_model()` now records each subcatchment's aquifer binding
and therefore its optional groundwater state block. A USE HOTSTART binding
protects groundwater structural changes until explicitly detached. RUNOFF's
existing fixed groundwater columns now work with a fully owned groundwater
model. Native tests produce, read, rewrite and reuse both caches alongside two
pollutants, with complete hydraulic/quality histories and matching identity
manifests. Manifest assertions still do not prove physical suitability or
authenticated production provenance.

Independent literal native tests cover all 16 local-override combinations in
both unit systems, every variable/function, monthly evaporation across January
and February, signed exchange, concentration edits, numeric missing sentinels,
coefficient/expression edits and all six flow units. Common control arithmetic
also retains its native regression coverage.
